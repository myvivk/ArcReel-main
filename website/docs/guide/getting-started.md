# 完整入门教程 {#getting-started}

本教程带你从零开始部署 ArcReel，并完成第一条可预览、可回滚、可导出的 AI 视频。

## 你将完成什么 {#what-you-will-build}

完成教程后，你将能够：

1. 使用 Docker 启动 ArcReel；
2. 登录工作台并配置模型供应商；
3. 创建短剧工厂项目并完成工件交稿；
4. 生成角色、场景、道具、分镜和视频片段；
5. 查看任务状态和费用；
6. 剪辑一集，再渲染成片或导出剪映草稿继续后期。

## 预计时间与费用 {#time-and-cost}

- 首次部署和配置通常需要约 10～20 分钟。
- 视频生成耗时取决于分镜数量、供应商排队和所选模型。
- 文本、图片、视频和 TTS 调用可能产生第三方 API 费用。
- ArcReel 可以在生成前提供费用预估，并在生成后记录实际调用量。

建议第一次只使用少量内容和 2～4 个分镜验证流程，不要直接提交完整长篇项目。

## 1. 准备环境 {#prepare-environment}

### 1.1 系统要求 {#system-requirements}

推荐环境：

- Linux
- macOS
- Windows + WSL2
- Docker Desktop

建议准备：

- Docker
- Docker Compose
- 建议从 2 GB 可用内存起步
- 可访问所选模型供应商的网络环境
- 足够的磁盘空间保存图片、视频、项目归档和日志

默认工作流使用远程模型 API，通常不要求本机 GPU。接入本地模型服务时，CPU、GPU 和内存要求由该服务决定。

### 1.2 准备模型凭据 {#prepare-credentials}

ArcReel 中有两类凭据，职责不同。

#### Agent 凭据 {#assistant-credentials}

Agent（智能体）用于项目对话、工厂创作、资产准备和制作编排。工厂正文由强文本模型生成，并经过医生精修、机检和合规检查。

可使用 Anthropic 官方服务或 ArcReel 支持的兼容服务，并按需配置 Base URL 和模型名称。

#### 媒体与文本生成凭据 {#media-and-text-credentials}

用于实际调用文本、图像、视频和 TTS 模型。

ArcReel 当前支持的预置供应商包括：

- Gemini
- 火山方舟
- Grok
- OpenAI
- Vidu
- 阿里百炼
- MiniMax
- 可灵 Kling
- Agnes
- 自定义 OpenAI 兼容或 Google 兼容供应商

不同供应商支持的媒体类型不同。完整流程通常至少需要：

- 一个可用的文本生成能力；
- 一个可用的图像生成能力；
- 一个可用的视频生成能力；
- 可选的 TTS 能力。

详细选择建议见 [供应商与模型配置](./providers.md)。

> API Key 属于敏感信息。不要把真实密钥提交到 Git、Issue、日志截图或公开聊天记录中。

## 2. 部署 ArcReel {#deploy-arcreel}

### 2.1 克隆项目 {#clone-repository}

```bash
git clone https://github.com/ArcReel/ArcReel.git
cd ArcReel
```

### 2.2 使用 SQLite 默认部署 {#deploy-with-sqlite}

默认部署适合首次体验、个人创作和轻量使用。

```bash
cd deploy
cp .env.example .env
```

编辑 `.env`：

```dotenv
AUTH_USERNAME=admin
AUTH_PASSWORD=请设置一个强密码
AUTH_TOKEN_SECRET=请设置一个长期固定的随机密钥
```

`AUTH_TOKEN_SECRET` 可以使用以下命令生成：

```bash
openssl rand -hex 32
```

启动：

```bash
docker compose up -d
```

检查状态：

```bash
docker compose ps
docker compose logs --tail=100 arcreel
curl http://localhost:1241/health
```

健康检查返回成功后，在浏览器打开：

```text
http://localhost:1241
```

> `AUTH_PASSWORD` 留空时，首次启动会自动生成密码并回写到 `.env`。正式使用时仍建议主动设置强密码并妥善保存。

### 2.3 使用 PostgreSQL 生产部署 {#deploy-with-postgresql}

长期运行、并发访问或正式服务建议使用 PostgreSQL。PostgreSQL 改善并发、备份与运维能力，但不提供用户隔离；请勿让互不信任的用户共享同一 ArcReel 实例：

以下命令从 ArcReel 仓库根目录执行：

```bash
cd deploy/production
cp .env.example .env
```

编辑 `.env`：

```dotenv
AUTH_USERNAME=admin
AUTH_PASSWORD=请设置一个强密码
AUTH_TOKEN_SECRET=请设置一个长期固定的随机密钥
POSTGRES_PASSWORD=仅使用字母数字的数据库密码
```

启动：

```bash
docker compose up -d
docker compose ps
curl http://localhost:1241/health
```

完整的生产部署、升级、备份和反向代理说明见 [部署与运维](../ops/deployment.md)。

## 3. 完成首次配置 {#first-time-setup}

登录后，建议先完成首次使用引导并打开只读演示项目。它可以帮助你认识项目大厅、工作台、Agent 和设置入口，而不需要先消耗模型额度。

随后进入 **设置** 页面。

### 3.1 配置 Agent {#configure-assistant}

填写：

- API Key 或凭证；
- Base URL；
- 主模型；
- 按需要配置不同任务所使用的模型。

保存后先发送一条简单消息验证连接，不要直接开始大批量任务。

### 3.2 配置媒体供应商 {#configure-media-providers}

至少配置一个图像和一个视频供应商。

建议第一次使用以下策略：

- 角色设计选择质量更稳定的图像模型；
- 批量分镜选择速度和成本更均衡的图像模型；
- 视频先选快速或低成本档位验证画面；
- 确认角色、构图和运动方向后，再切换高质量模型。

### 3.3 配置并发和费用 {#configure-concurrency-and-cost}

根据供应商配额调整：

- RPM 限制；
- 图像并发；
- 视频并发；
- 音频并发。

设置过高可能导致供应商限流，设置过低则会延长批量任务时间。初次使用建议保守设置，确认稳定后逐步提高。

## 4. 创建第一个项目 {#create-first-project}

在项目列表页点击 **新建项目**。

### 4.1 设置项目 {#choose-project-source}

填写项目名称、画面比例、视觉风格、全剧总集数、单集目标和模型配置。创作链路固定为短剧工厂，可选择真人或动画视觉风格。

至少准备可用的强文本模型、图像模型和视频模型。首次制作使用少量分镜，先验证风格、参考图和视频输入能力。流程说明见 [短剧工厂制作流程](./workflows.md)。

### 4.2 提交工厂内容 {#choose-content-mode}

在欢迎页或概览中选择「AI 原创剧本」，填写创意简报、题材和篇幅目标，然后交给 Agent。工厂支持新建、续写和连写。每个批次须完成医生精修、机检、返修和合规检查，合格后原样保存七类 Markdown 工件。

已有合格工厂工件时，把工件目录放进项目工作目录，交给 ArcReel Agent 原样入库。每个交付集必须包含分集规划、正文、机检报告和合规报告；系列工件可复用已保存版本。单篇正文或普通小说文件不能代替完整工件目录。

在「故事规划」查看人物圣经、全剧大纲、台账和分集规划，在集页「剧本」查看本集源稿。这些内容只读，正文修改需要回到工厂质量流程。

## 5. 完成一集制作 {#run-workflow-with-assistant}

打开右侧 Agent 面板，按阶段推进，也可使用集页对应按钮。

### 5.1 准备本集资产 {#character-scene-prop-assets}

进入「资产」，登记本集角色、场景和道具，补齐描述并生成资产图。先核对主要角色的年龄、发型、服装和体型，再扩大资产生成范围。缺少登记或描述时，先补齐资产再做 AI 分镜。

### 5.2 生成 AI 分镜 {#episodes-and-script}

进入「分镜」，点击「AI 分镜」，选择内容优化强度。系统根据工厂源稿、项目分镜时长和已登记资产生成分镜段与分镜提示词。检查剧情覆盖、台词、分镜用途和相邻镜头的空间关系。校验失败会返修，重试用尽后报错。

### 5.3 确认参考素材 {#storyboard-images}

在分镜详情中检查引用和分镜提示词，再生成「参考素材」。默认 2×2，也可选 2×3 或 3×3。检查同一分镜内 K 帧的动作、构图和角色一致性，确认后完成切分和绑定。取消编辑不会保存。

修改规格后须重新生成并确认。模型必须支持对应参考图数量，系统不会为适配模型而自动丢弃 K 帧。

### 5.4 独立编写视频提示词 {#video-prompts}

参考素材确认后，单独生成视频提示词。它读取工厂源稿、已保存分镜提示词和 K 帧；两类提示词分开生成。修改参考素材后，核对提示词中的动作和 K 帧引用，按需重写。

### 5.5 生成视频片段 {#video-clips}

确认提示词和预计费用，再生成视频。输入包含当前 K 帧、前镜接续点和完整参考图关系。先检查少量视频的人物形态、动作、运动方向与结尾接续，再补齐整集。

### 5.6 配置声音 {#narration-and-tts}

项目可配置视频原声、角色声音和 TTS 旁白。需要 TTS 时，在项目设置中选择 TTS 模型、音色与语速；先试听少量旁白，检查人物名和停顿。无旁白的分镜不需要生成旁白音轨。

需要角色音色复刻时，选择「参考音频」绑定方式，为发言角色上传参考音频，并确认视频模型支持该能力及音频数量、时长限制。声音能力不依赖旧参考生视频项目路线。

## 6. 查看任务和费用 {#tasks-and-cost}

生成任务会进入异步队列。

在任务监控中关注：

- 排队中；
- 运行中；
- 成功；
- 失败；
- 取消。

遇到失败时，先查看失败原因，不要立刻连续重试。常见原因包括：

- API Key 无效；
- 额度不足；
- 供应商限流；
- 参数不被当前模型支持；
- 网络超时；
- 参考图数量或格式不符合要求。

在费用页面查看：

- 预估费用；
- 实际费用；
- 文本、图像、视频和音频调用量；
- 不同供应商和币种的统计。

## 7. 剪辑和出片 {#compose-and-export}

### 7.1 剪辑并渲染成片 {#compose-final-video}

视频生成后，在集页顶部切换到 **剪辑** 视图。一集的成片形态由剪辑时间线决定：可以交给 Agent 剪一版，也可以按脚本新建一条剪辑时间线，再在对话中让 Agent 调整。使用这条时间线核对分镜顺序、截取、字幕和音轨。

点击剪辑视图顶部的 **出片**，在「出片 · <剪辑时间线名称>」对话框中选择 **成片**。已是最新的成片可以直接下载；还没有成片或成片已落后于剪辑时间线时，点击渲染，对话框内会显示进度，完成后即可下载。

对话框中可以选择成片的版本，每种组合是一份独立的成片：

- **旁白版本**：只有 TTS 配音项目可以选择，默认 **带旁白**。旁白比所在片段长时按原长度混入成片，不截短，也不顺延后面的旁白，问题列表会提示重叠；超出成片末尾的部分被截掉。
- **烧入字幕**：默认勾选。字幕直接画进视频画面，播放时无法关闭；字体是随包的思源黑体。字幕里有这款字体没有的字符时，问题列表会列出这些字符。

需要背景音乐时，点击剪辑视图 BGM 轨名称旁的上传按钮，上传 MP3、WAV 或 M4A 音频（不超过 100 MB）。上传时 ArcReel 测量一次响度，把每首 BGM 统一到相同的响度水平；几乎无声的音频无法上传。BGM 属于整个项目，各集的剪辑时间线都能使用。上传后，在对话中让 Agent 把 BGM 摆进剪辑时间线；BGM 比时间线短时，Agent 会接着摆下一段。同一时刻只有一首 BGM，超出剪辑时间线末尾的部分会被截掉，并在截断处淡出 1 秒。成片与剪映草稿都会混入 BGM。目前不支持在页面上删除已上传的 BGM。

建议在出片前检查：

- 片段顺序；
- 画面比例；
- 每个片段的实际时长；
- 旁白和画面的对齐；
- 是否需要背景音乐；
- 相邻片段是否需要转场。

### 7.2 导出剪映草稿 {#export-jianying-draft}

需要在剪映中继续精修字幕、音轨、转场和节奏时，在同一个出片对话框中选择 **剪映草稿**。详细步骤见 [剪映草稿导出指南](./jianying-export.md)。

顶栏的 **导出项目** 只用于打包下载整个项目，不导出成片或剪映草稿。

## 8. 第一次项目的完成标准 {#first-project-checklist}

不要以“所有素材都生成过”为完成标准。建议至少达到：

- 角色设计已审核；
- 关键道具和场景参考已审核；
- 分镜结构合理；
- 相邻分镜主体和运动方向可衔接；
- 视频片段没有明显崩坏；
- 费用在预期范围内；
- 至少一集可以成功出片；
- 项目完成一次备份或归档。
