# 完整方案

## 一、背景

### 1.1 工厂产出什么
工厂（`short-drama-factory` Skill）是工业化短剧编剧系统，逐集产出 **7 类工件**：人物圣经、全剧大纲（四幕/单元链/回合表/付费墙）、连续性台账、分集规划、整集剧本、机检报告、合规检查。

### 1.2 目前实现存在的问题
- **丢 6 类**：`import_short_drama_script`（`script_authoring.py:103`）只搬"整集剧本"，其余 6 类根本没导入，故事规划面板全空。
- **重写 1 类**：`short_drama_import.py` 导入时做重投影（微幕切分、动作/台词压平、时长拟合、meta 降级），把工厂产物改写后再存。
- **静默丢人**：`extract_script_events`（`story_planning.py:178`）把不在 `project.characters` 里的 `[人物]` 直接过滤掉。
- **生产侧 ArcReel 插手**：`CLAUDE.drama.md:6` 的"改编"身份压低体量；`SKILL.md:85` 第 7 步让 Agent 交稿时调 `generate_episode_script`（ArcReel 文本模型）把剧本再重写一遍，违反"不让 ArcReel 处理"。
- **入口断裂**：导入 10 集后"AI 原创剧本"入口消失，无法续写。

### 1.3 生成质量为何受损（本方案最核心的问题）
工厂剧本的质量来自三件事：**强文本模型写足额体量** + **跨集连续设定（人物圣经/大纲/台账/分集规划）喂给每一集** + **产出不被任何环节改写**。当前集成在每一环都削弱它：

| 质量支柱 | 当前如何被削弱 |
|---|---|
| 强模型足额写 | 被"改编/补充"身份压制 → 体量缩水、冲突弱化 |
| 跨集设定连续 | 6 类设定根本没存 → 续写/生产时模型拿不到圣经、大纲、台账，**盲写** → 连续性崩、质量塌 |
| 产出不被改写 | 生产侧 `generate_episode_script` 重写 + 导入重投影 → 二次失真 |

**本质**：集成版质量 ≠ 工厂原版质量，是因为集成过程在"写、存、续"三处都稀释了工厂产物。本方案要解决的正是"让集成版质量≈工厂原版质量"。

## 二、目的
1. **保住生成质量**：集成过程任何一环都不稀释工厂产物——模型足额写、设定全留、产出原样。
2. 工厂 7 类产物**全量、原样**进系统，不丢一类、不改一字。
3. 进来的内容在「故事规划」「分集」**可读、可查**，且生产侧两处 ArcReel 插手的口子堵死。

## 三、预期效果
- **存储**：7 类工件字节级落在 `source/short_drama/`，与工厂原文逐字节一致。
- **可读**：故事规划页展示系列级 4 类（圣经/大纲/台账/分集规划）；分集页每集展示集原文。
- **产出不被改写**：短剧模式按工厂原意写足额剧本；交稿不走 ArcReel 文本模型重写。
- **质量保真**：存进系统的 ≡ 强文本模型产出的工厂原版；6 类设定全留，后续续写/生产时有完整上下文可读，**不再盲写**。
- **边界**：本阶段只做"进系统 + 可看 + 保原样"；派生 ArcReel 原生剧本/资产（编译步）不在本阶段。

## 四、核心原则
① 写作交文本模型 ② 工厂 7 类产物全量进系统 ③ 导入零处理 ④ 不阉割工厂 ⑤ `CLAUDE.drama.md:218` 对工厂导入无管辖权

## 十四、方案优化项（实现缺口，须在本阶段补）

本方案初版落地后出现两处与「核心原则① / 第十一节」不符的实现缺口，须补齐才能真正达成「质量 ≈ 工厂原版」：

### 14.1 写作必须交文本模型（落实核心原则① + 第十一节）

- **现状缺口**：第十节只删掉了 SKILL 第 7 步的 `generate_episode_script` 调用，却没有补「用文本模型写」的出口，工厂写作真空落到**助手模型**上——用户配置的强文本模型（`TextGenerator` 后端）在工厂链路里完全没被使用，违反核心原则①「写作交文本模型」与第十一节「配强模型是质量天花板，弱模型写不出原版体量」。
- **补法**：
  - 新增工厂文本生成工具（建议 `server/agent_toolset/short_drama_factory_gen.py`），经 `lib/backends/text_generator.py` 的 `TextGenerator` 调用**用户配置的强文本模型**逐件产出 7 类 Markdown 工件；该工具只返回原文，不做 JSON 投影、不触发 `generate_episode_script`。
  - `TextGenerator` 新增工厂任务类型（如 `TextTaskType.FACTORY_EPISODE` / `FACTORY_SERIES`），确保走「文本模型」路由而非助手模型。
  - `SKILL.md` 改写：工厂正文由该工具产出，Agent 仅做读取 references、编排、机检与 `ingest` 落盘，**不得自己写正文**。
  - 如此第十一节「配强模型」才有代码落点：工厂写作模型即用户所选文本模型，弱模型写不出原版体量的问题在代码层被强制保证，而非依赖部署自觉。

### 14.2 旧链路在 drama 模式须失效但不能删（保留兼容） —— 已实现

- **现状缺口**：`import_short_drama_script` / `import_short_drama_series` 仍作为工具存在且可被 Agent 提供/调用；旧 factory 流程里 `generate_episode_script` 的「ArcReel 文本模型重写」路径仅在提示词层禁止，**服务端没有硬门禁**，drama 项目里 Agent 仍可能绕回旧入口（如用户说「导入第 1~10 集」时被当成旧批量导入，并向用户抛出入口选择）。
- **补法（不删除、加门禁）—— 已实现**：
  - `server/agent_runtime/agent_access_policy.py` 新增 `LEGACY_DRAMA_IMPORT_TOOLS` 常量与 `deny_legacy_drama_import(content_mode, tool_name, *, legacy_compat)` 规则方法：`content_mode=drama` 项目下，两个旧入口**默认拒绝**（新交稿一律走 `ingest_short_drama_artifacts`）。
  - 两个 handler（`import_short_drama_script` / `import_short_drama_series`）在入口处 load 项目、取 `content_mode`，非 drama 返回 `invalid_request`；drama 下调用上述规则，未显式 opt-in 时返回 `legacy_import_blocked` 问题（文案引导改用 `ingest_short_drama_artifacts`）。
  - **显式 opt-in**：两请求模型新增 `legacy_compat: bool = False` 字段；仅当用户在请求中**明确置 true**（对应「旧工作区 / 转原生剧本 JSON」场景）时放行，且调用即代表已知其「改写 JSON、丢 6 类、重投影」后果。
  - Web 端「导入」按钮（`/short-drama/import`、`/short-drama/import-batch`）即用户显式选择旧转 JSON 路径，路由层直接传 `legacy_compat=true` 放行，旧工作区交稿仍可走。
  - 配合第十节提示词加固（禁止就入库入口提问、禁止把旧入口当选项），提示词 + 服务端门禁双保险：旧链路在 drama 新建项目里彻底失效，但旧工作区仍可走兼容入口，不破坏存量数据。
- **补法（断点闭环：工厂正文必须成为「本集正文」）—— 已实现**：
  - `lib/short_drama_ingest.py` 新增 `register_factory_episode_sources`：`ingest_short_drama_artifacts` 落盘七类工件后，把每集 `episodes/episode_NN.md` 登记为该集 **OWN 源文本**（类型记为剧本）。这一步曾被漏掉，导致集 `source_origin` 仍为 `none`、分集页「本集正文」空白、下游只能空起稿（`start_blank_script`）。
  - 调用方：`server/routers/short_drama.py` 的 `import-artifacts` 与 `server/tool_runtime.py` 的 `ingest_short_drama_artifacts_tool` 在导入后都调用它；集不在账本时跳过、工件仍原样保留。
  - 前端 `EpisodePage.tsx` 的 `hasShortDramaSource` 在 `source_origin === "own"` 时也为真：即便集被误建了空白正式脚本（`script_file` 被设），工厂集仍优先走 `FactoryEpisodeSourceView` 显示 `source/short_drama/episodes/episode_NN.md`，不再呈现空「本集正文」。
