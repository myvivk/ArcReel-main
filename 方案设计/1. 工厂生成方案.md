# 1. 短剧工厂独立生成方案

> 唯一链路约束（2026-10-23）：以《短剧工厂唯一链路删除清单》为准。生产只保留「工厂质量闭环与七类工件入库 → 资产 → AI 分镜 → 逐镜 ShotGrid / K 帧确认 → 独立视频提示词 → 视频与声音 → 剪辑导出」。旧单集／批量正文导入、源稿直接保存、普通源文规划、旁白／广告模式、参考单元和跨分镜联合图的页面、HTTP、Agent 与任务入口全部删除。文中基线问题和旧源码定位只用于说明设计依据，不构成保留旧生产入口的要求。
>
> 历史项目保留源文、媒体、版本、读取、归档、已有剪辑和已提交付费任务恢复；不改写旧模式字段，不从旧 JSON 拼造七类工件。工厂剧情与台词以 `source/short_drama/` 为真相源，`scripts/episode_N.json` 只保存视觉派生状态；生产要求工厂源稿修订与派生来源一致。

## 一、背景

### 1.1 工厂产出什么
`short-drama-factory` 是工业化短剧编剧系统。它不是 ArcReel 原有脚本规划链路的补丁，而是一条独立编剧链路，负责从创意简报、题材、档位和连续设定出发，产出完整短剧正文与质量报告。

工厂按系列和单集产出 7 类 Markdown 工件：

| 类型 | 工件 | 作用 |
|---|---|---|
| 系列级 | `character-bible.md` | 人物圣经，包含人物动机、秘密、弧光、语言指纹和外形 |
| 系列级 | `series-outline.md` | 全剧大纲、四幕结构、单元链、回合表、付费墙规划 |
| 系列级 | `ledger.md` | 连续性台账，记录伏笔、人物状态、道具状态、世界观规则 |
| 集级 | `episode-plan/episode_NN.plan.md` | 分集规划，约束本集冲突、场景、节奏和钩子 |
| 集级 | `episodes/episode_NN.md` | 整集剧本原文，保留 `[人物]`、`[场景]`、`[道具]` 和动作/台词结构 |
| 集级 | `reports/episode_NN.machine.md` | 规则机检报告 |
| 集级 | `compliance/episode_NN.compliance.md` | 合规检查报告 |

### 1.2 目前集成存在的问题
当前问题不是单个导入函数不完善，而是短剧工厂被接进了 ArcReel 原有编剧链路，导致工厂能力被削弱。

- **链路混入**：工厂正文生产、项目脚本规划、旧导入、视觉提示词生成之间边界不清，Agent 容易把短剧工厂当成普通剧本补写工具。
- **丢失工件**：旧入口只处理单集正文，其余 6 类工件没有稳定进入系统，故事规划页无法读取人物圣经、全剧大纲、台账和分集规划。
- **质量上下文断裂**：续写时缺少系列级设定和台账，模型拿不到跨集连续信息，容易盲写、断人物、断伏笔。
- **规则闭环缺失**：工厂原本包含医生精修、机检、合规和返修流程，接入后如果只保存一版正文，就等于绕过了工厂的质量控制能力。
- **写作模型不明确**：如果正文由助手模型直接写，而不是经用户配置的强文本模型写，体量、冲突密度、节奏和台词质量都会下降。
- **前端入口误导**：「AI 原创剧本」入口必须交给短剧工厂独立链路，不应把用户带回旧脚本生产路径。

### 1.3 质量为什么必须由工厂链路保证
短剧工厂的质量来自完整流程，而不是一次性生成剧本文本。

| 质量支柱 | 必须保留的能力 | 不能发生的削弱 |
|---|---|---|
| 强文本模型写作 | 所有工厂正文经 `TextGenerator` 的强文本模型生成 | Agent 自己写正文，或弱模型承担主写作 |
| 系列设定连续 | 人物圣经、全剧大纲、台账、分集规划进入每集上下文 | 只保存单集正文，续写时看不到系列设定 |
| AI 剧本优化 | 用工厂医生规则对台词、节奏、断章、回合升级做优化 | 一稿裸交，没有返修 |
| 规则机检 | `validate_episode.py` / `validate_series.py` 一票否决失败项 | 机检只生成报告但不参与通过标准 |
| 合规检查 | 合规报告随集保存，红线问题修到通过 | 合规只作为人工备注，不参与交付 |
| 原文保真 | 通过后的 7 类 Markdown 工件原样保存 | 入库时改字、压平、降级或抽取替代原文 |

**本质要求**：短剧工厂生产剧本是一条独立链路。ArcReel 在本阶段只提供模型路由、工具调用、文件存储、项目锁、权限和只读展示，不参与工厂正文的创作、优化和改写。

## 二、目标

1. 建立短剧工厂独立生产链路：从创意简报到 7 类 Markdown 工件，全程按 `short-drama-factory` 规则执行。
2. 写作和优化交给用户配置的强文本模型：Agent 只负责编排、读取 reference、组装 prompt、调用工具、执行机检和落盘。
3. 保留完整工厂能力：立项、人物圣经、全剧大纲、分集规划、单集撰写、医生精修、机检、合规、台账更新都必须在链路内闭环。
4. 7 类工件全量、原样进入 `source/short_drama/`，作为短剧工厂产物的真相源。
5. 故事规划页和分集页读取工厂 Markdown 展示，让用户能查、能看、能发现质量问题。
6. 原有 ArcReel 编剧逻辑不参与本阶段工厂正文生产；后续视觉制作另按独立步骤处理。

## 三、文档分工与步骤顺序

`方案设计/` 下的文档共同描述剧本工厂从源稿到视频生成的完整步骤。每份文档只定义本步骤的职责、输入、处理流程、产出和页面交互；后续步骤只能读取上一步明确产出的数据，不能反向改写上游源稿。

| 顺序 | 文档 | 步骤职责 | 主要输入 | 主要输出 |
| --- | --- | --- | --- | --- |
| 1 | `1. 工厂生成方案.md` | 工厂正文生成、质量检查和 Markdown 入库 | 用户创意简报、已有系列工件、工厂 references / templates | `source/short_drama/` 下 7 类 Markdown 工件 |
| 2 | `2. 资产步骤方案.md` | 从工厂源稿与故事规划抽取、登记并生成角色 / 场景 / 道具资产 | `source/short_drama/episodes/episode_NN.md`、人物圣经、全剧大纲、台账、分集规划 | 项目资产条目、资产描述、资产图任务 |
| 3 | `3. AI 分镜方案.md` | 从本集 Markdown 源稿生成分镜段和分镜提示词 | 本集工厂源稿、已登记且有描述的资产 | 视觉制作状态中的分镜段、`image_prompt.scene` |
| 4 | `4. 参考素材（镜头宫格）生成方案.md` | 基于 `image_prompt.scene` 生成并确认参考素材 K 帧 | 分镜段、分镜提示词、资产图、项目画布比例 | `ShotGrid`、宫格图、`cell_paths`、逐格文本留证 |
| 5 | `5. 视频提示词独立步骤生成设计.md` | 基于分镜提示词和已确认 K 帧生成 `video_prompt` | `image_prompt.scene`、已确认 `ShotGrid.cells`、分镜上下文 | 视觉制作状态中的 `video_prompt` 与 `video_prompt_basis` |
| 6 | `6. 视频输入组织方案.md` | 把提示词、K 帧、尾帧、音频和参数组织成视频生成请求 | `video_prompt`、`cell_paths`、尾帧、角色音频、模型能力 | `VideoGenerationRequest` 与视频生成任务 |

本方案只覆盖第 1 步。后续步骤可以读取工厂源稿，但不得修改 `source/short_drama/episodes/episode_NN.md`，也不得把视觉制作派生状态重新定义为工厂剧本真相源。

## 四、核心原则

### 4.1 工厂链路独立
短剧工厂链路不依赖 ArcReel 原有 `story_plan`、脚本规划、旧导入、资产登记和视觉提示词生成逻辑。项目基础设施可以提供读写、锁、权限、模型路由和 UI 展示，但不能接管工厂正文。

### 4.2 写作交文本模型
所有工厂正文必须通过 `generate_short_drama_factory` 调用 `TextGenerator` 生成。`TextTaskType.FACTORY` 归档到 `COMPLEX` 档，使用用户配置的强文本模型。Agent 不直接写正文。

### 4.3 质量闭环必须完整
工厂不是「生成一份 Markdown」即可交付。每集必须经过：

```text
草稿生成 → AI 医生精修 → 规则机检 → 问题返修 → 合规检查 → 通过后落盘
```

机检失败时，Agent 把失败项作为约束回喂给文本模型修稿，再重新机检。合规失败同理返修。只有通过后的工件进入正式工厂源目录。

### 4.4 7 类工件全量保存
人物圣经、全剧大纲、连续性台账、分集规划、整集剧本、机检报告、合规报告都要保存。不能只保存单集剧本，也不能把机检和合规当成临时对话结果。

### 4.5 入库零改写
`ingest_short_drama_artifacts` 只负责安全校验、质量拒绝和原样写入。它可以拒绝不合格包，但不能修改通过后的工件内容。

### 4.6 不阉割工厂能力
不得为了适配 ArcReel 原有工作流而删除或弱化以下能力：

- 档位判定：标准档、长档、漫剧档。
- 情绪契约和单元链。
- 人物圣经和外形原样引用。
- 连续性台账读写。
- 分集规划和中段小钩。
- 台词医生和反 AI 腔优化。
- `validate_episode.py` 与 `validate_series.py` 机检。
- 合规审核。
- 分批交付和续写。

## 五、端到端流程

```text
[AI 原创/连写入口]
        │
        ▼
[Agent 编排工厂流程]
读取 short-drama-factory references / templates / 已有工件 / 用户简报
        │
        ▼
[generate_short_drama_factory]
强文本模型逐件生成人物圣经、全剧大纲、台账、分集规划、集正文、机检报告、合规报告
        │
        ▼
[AI 医生精修 + 规则机检 + 合规返修]
失败项回喂文本模型，直到达到交付标准
        │
        ▼
[ingest_short_drama_artifacts]
通过后的 Markdown 工件原样写入 source/short_drama/
        │
        ├──▶ [故事规划页] 读取系列级工件和分集规划
        └──▶ [分集页] 读取 episodes/episode_NN.md
```

本阶段的交付重点是「工厂产物进入系统并可读」，不是把工厂产物混入 ArcReel 原有编剧链路。

## 五 A. 首写与续写：入口契约与运转方式

「AI 原创剧本」弹窗（`episode === 0` 的创建模式）承担两种批次，判定以**当前账本最大集号**为准，不另设独立入口：

| 批次 | 判定 | 用户可改项 | 锁定项（首写已定） |
| --- | --- | --- | --- |
| **首写** | 最大集号 = 0 | 题材、连写集数、总集数、篇幅档位、创意简报、风格基调 | 无 |
| **续写** | 最大集号 ≥ 1 | **仅连写集数** | 题材、总集数、篇幅档位、创意简报、风格基调 |

集页入口（`episode > 0`）仍是「指定已有集单集重写」，不属于本表的批量续写；单集重写不改全剧总集数，也不开放连写集数。

### 5A.1 首写怎么运转

```text
用户填简报与规划
  →（可选）PATCH total_episodes 落库
  → 透明建空白集 / 复用末尾空集
  → GET story-planning/context（首集前为空）
  → 组装「立项 + 本批目标集」Agent 指令
  → Agent：立项系列工件 → 逐集质量闭环 → ingest 分批落盘
```

- 总集数写入项目 `total_episodes`，供后续续写与四幕 / 付费墙规划。
- 题材、档位、简报写入本批 prompt；系列级真相源落盘后以 `source/short_drama/` 为准。

### 5A.2 续写怎么运转

```text
弹窗只收「连写集数」
  → 展示已有集数、起始集号、续写后累计、规划总集数（只读）
  → 校验：已有集数 + 新建集数 ≤ 规划总集数
    （末尾空白集优先复用，不计入「新建」增量）
  → 不修改 total_episodes、不重填题材 / 档位 / 简报
  → GET story-planning/context（读到续写起点之前的工厂上下文）
  → 组装「续写」Agent 指令：沿用人物圣经 / 大纲 / 台账 / 已有档位与题材
  → Agent：读台账与前集 → 本批质量闭环 → 更新 ledger → ingest
```

- **可写边界**：只扩展尚未写满的集号区间；不得借弹窗改全剧规划。
- **容量公式**：`projected = maxEpisode + max(0, count - trailingBlankCount)`；`projected > total_episodes` 时禁止提交；提示只要求减少连写集数，不引导提高总集数。
- **收尾**：本批最大目标集号 ≥ `total_episodes` 时，指令要求收尾闭环；否则保持断章、留续写空间。
- **设定来源**：续写 prompt 不重新立项；Agent 必须先读 `source/short_drama/` 已有工件，冲突以台账与已交付系列工件为准。

### 5A.3 与工厂工具的对应关系

首写与续写共用同一套工具与质量闭环，差异只在入口约束与 prompt 语义：

| 环节 | 首写 | 续写 |
| --- | --- | --- |
| 系列工件 | 本批生成并入库 | 复用已有；台账随本批更新 |
| `generate_short_drama_factory` | 全量七类按需生成 | 本批集级工件为主，系列件仅在缺失或台账变更时重交 |
| `ingest_short_drama_artifacts` | 首批须带齐系列件 | 系列件可复用；每集仍须同批规划 + 正文 + 两报告 |
| 前端可编辑字段 | 简报全套 | 仅连写集数 |

## 六、存储布局

`source/short_drama/` 是短剧工厂产物的真相源。目录即真相，不新增 manifest。

```text
source/short_drama/
├── character-bible.md                    # 人物圣经（系列级）
├── series-outline.md                     # 全剧大纲/回合表/付费墙（系列级）
├── ledger.md                             # 连续性台账（系列级，逐集更新）
├── episode-plan/episode_NN.plan.md       # 分集规划（集级）
├── episodes/episode_NN.md                # 整集剧本（集级，含 [人物]/[场景]/[道具]）
├── reports/episode_NN.machine.md         # 机检报告（保存，暂不展示）
└── compliance/episode_NN.compliance.md   # 合规检查（保存，暂不展示）
```

文件命名必须稳定，前端和后续链路只从这些路径读取工厂原文。

## 七、生成与优化契约

### 7.1 生成工具
新增或保留工厂专用文本生成工具：

- 工具名：`generate_short_drama_factory`
- 请求模型：`ShortDramaFactoryGenRequest`
- 文本任务类型：`TextTaskType.FACTORY`
- 档位：`COMPLEX`
- 调用后端：`TextGenerator`
- 输出：工厂 Markdown 原文

该工具只返回文本模型产出的 Markdown，不解析、不投影、不触发 ArcReel 原有脚本生成流程。

### 7.2 Agent 职责
Agent 只能做编排工作：

- 读取 `short-drama-factory` 的 references、templates、examples 和已有工件。
- 根据用户简报、总集数、档位、续写范围组装 prompt。
- 调用 `generate_short_drama_factory` 生成各类工件。
- 把机检和合规失败项整理为返修 prompt，再次调用文本模型。
- 通过后调用 `ingest_short_drama_artifacts` 原样落盘。

Agent 不得自己撰写正文，也不得把一稿直接当成最终交付。

### 7.3 AI 优化闭环
每集正文至少经过以下质量步骤：

1. **初稿生成**：按人物圣经、全剧大纲、台账和分集规划生成集正文。
2. **医生精修**：按 `dialogue-doctor-anti-ai.md` 优化台词、节奏、人物语言指纹、回合升级和断章。
3. **机检**：运行 `validate_episode.py`，长档、漫剧按对应档位检查。
4. **返修**：机检失败项必须回喂文本模型重写相关工件。
5. **台账更新**：本集新增伏笔、人物状态、道具状态和世界观规则写入 `ledger.md`。
6. **系列机检**：阶段性运行 `validate_series.py`，检查伏笔超期、死人开口、断章缺失、付费墙空缺等问题。
7. **合规检查**：生成合规报告，红线问题必须返修。

机检报告和合规报告是交付工件的一部分，不只是对话记录。

## 八、导入契约

新交稿入口固定为 `ingest_short_drama_artifacts`。

### 8.1 入口职责
`ingest_short_drama_artifacts` 负责：

- 校验路径只落在 `source/short_drama/` 允许范围内。
- 校验内容是 UTF-8 文本。
- 校验同一导入包没有重复路径。
- 对 episode 工件执行质量闸，失败则拒绝整包。
- 原样写入通过后的 7 类 Markdown 工件。
- 将 `episodes/episode_NN.md` 登记为该集的 `OWN` 源文本，便于分集页和后续步骤读取。

### 8.2 明确禁止
导入阶段不得做以下事情：

- 不改写 Markdown 原文。
- 不抽取到 `story_plan`。
- 不自动登记角色、场景、道具资产。
- 不调用原有脚本规划或视觉提示词生成逻辑。
- 不根据视频模型能力调整剧本文本。

### 8.3 完整性要求
导入包应支持分批落库，但每个批次必须自洽：

- 系列级工件可以复用已有版本，但缺失时必须随首批提交。
- 每个提交的 episode 至少应包含分集规划、集正文、机检报告和合规报告。
- 同一批次中，机检失败的任一集会导致整包拒绝，避免部分落盘造成连续性错位。

### 9.2 分集页
分集页的「剧本 / 原文」视图读取：

页面必须保留 `[人物]`、`[场景]`、`[道具]`、动作行和台词原貌，不做结构化改写展示。

### 9.3 入口保留
「AI 原创剧本」入口必须持续存在，用于新建、续写和连写。首写与续写的字段可编辑边界、容量校验与 prompt 语义见 **五 A**。该入口生成给 Agent 的指令必须要求：

- 使用 `short-drama-factory` 完整流程。
- 通过 `generate_short_drama_factory` 让文本模型写作和优化。
- 通过 `ingest_short_drama_artifacts` 原样保存工件。
- 不把旧脚本生产入口作为选项。
- 续写时仅提交连写集数与目标集范围，明确沿用已有系列设定，不得借入口改总集数或重新立项。

## 十、生产侧必须修改

### 10.1 `CLAUDE.drama.md`
短剧模式下的身份指令改为：

- 工厂 Markdown 是剧情、对白、体量和连续设定的真相源。
- 进入 `short-drama-factory` 模式时，ArcReel Agent 只做编排，不写正文。
- 用户说「AI 原创剧本」「连写」「续写」「交稿」「导入」时，默认走工厂独立链路。

### 10.2 `short-drama-factory/SKILL.md`
第 7 步改为「生成 + 优化 + 分批落库」：

- 所有正文由 `generate_short_drama_factory` 生成。
- 医生精修、机检、合规和返修必须执行。
- 一个单元或一个批次通过后立即调用 `ingest_short_drama_artifacts` 落盘。
- Agent 不得裸交失败工件，也不得等全剧写完再一次性交付。

### 10.3 「AI 原创剧本」前端提示词
`ShortDramaGenerateDialog.tsx` 生成的 Agent 指令必须改成工厂独立链路说明，不能再指向旧导入工具，也不能提示后续由原有脚本生成补视觉层。

## 十一、前置条件

- **强文本模型配置**：`TextTaskType.FACTORY` 必须走 `COMPLEX` 档文本模型。弱模型会直接限制体量、台词和节奏质量。
- **Skill 完整安装**：`agent_runtime_profile/.claude/skills/short-drama-factory/` 下的 references、templates、examples、scripts 必须完整可读。
- **机检脚本可运行**：`validate_episode.py` 和 `validate_series.py` 必须能在 Agent 工作目录下运行。
- **项目集账本存在**：导入集正文时，如果目标集不存在，工件仍可保存，但源文本登记会跳过；需要前端或 Agent 先完成建集。

## 十二、本方案不做，由后续步骤负责

本方案只保证工厂正文生产、质量检查、原样入库和只读展示，不做以下内容。这些内容由后续步骤文档定义，不能混回工厂生成步骤。

- 角色、场景、道具资产登记与资产图生成：见 `2. 资产步骤方案.md`。
- AI 分镜、分镜段和 `image_prompt.scene` 生成：见 `3. AI 分镜方案.md`。
- 参考素材宫格生成与确认：见 `4. 参考素材（镜头宫格）生成方案.md`。
- `video_prompt` 生成：见 `5. 视频提示词独立步骤生成设计.md`。
- 视频请求输入组织与生成准入：见 `6. 视频输入组织方案.md`。
- 质检报告 UI 展示。
- 对账 manifest。
- 生成上下文回填到 ArcReel 原有 `story_plan`。

## 十四、验收标准

### 14.1 生成链路
- 「AI 原创剧本」触发后，Agent 调用 `generate_short_drama_factory` 生成工厂工件。
- Agent 不直接输出最终正文作为交付。
- Agent 对机检和合规失败项执行返修。
- 通过后调用 `ingest_short_drama_artifacts`。

### 14.2 存储
- `source/short_drama/` 下出现 7 类工件。
- 通过后的工件内容与文本模型最终产出一致。
- 未通过机检的 episode 不落盘。
- 同一批次中任一集失败时整包拒绝。

### 14.3 可读
- 故事规划页能读取人物圣经、全剧大纲、连续性台账和分集规划。
- 分集页能读取对应 `episodes/episode_NN.md`。
- 工厂原文中的 `[人物]`、`[场景]`、`[道具]` 和台词动作格式不被改写展示。

### 14.4 质量
- 单集正文满足对应档位体量、拍数、断章、中段小钩、人物外观、道具外观等机检要求。
- `ledger.md` 随集更新，续写时能读取历史伏笔、人物状态和道具状态。
- 合规报告随集保存，红线问题已在交付前返修。

### 14.5 隔离
- 工厂正文生产不读取或写入原生 `story_plan` 编辑区。
- 工厂正文生产不调用原有脚本规划和视觉提示词生成逻辑。
- ArcReel 项目基础设施只承担模型路由、工具权限、文件写入、锁、读取和 UI 展示。
