# 10. 机械分镜与分镜提示词分步方案（实施文档）

> 状态：已实施（P1–P4），P5 为静态检查与手工走查；实施记录见 §19。本文是实施文档与落地口径。
> 关联：`方案设计/3. AI 分镜方案.md`（本文取代其"分镜与提示词同一步"的结论）、`docs/agents/short-drama-markdown-reimport.md`、`docs/adr/0098-storyboard-shot-beat-grid.md`、`docs/adr/0101-storyboard-semantic-continuity-gate.md`。

## 一、结论

生产链路从「分镜与提示词由模型一次写完」改为：

```text
资产 → 机械分镜（纯代码） → 分镜提示词编写（独立下一步） → 参考素材 K 帧 → 视频
```

三个决定：

1. **分镜结构由代码机械生成，不调用任何文本模型。** 边界、时长、分镜 ID、出场资产、逐字口播、`source_text`、`scene_description` 全部从工厂 Markdown 与项目资产表确定性推导，同一输入永远得到同一输出。
2. **`image_prompt` 不再由分镜步骤产出。** 机械分镜落盘的条目 `image_prompt = null`、`pending_authoring = true`（`PendingPrompt` 与待编写标记已存在，见 `lib/script/script_models.py:602`、`:627`）。
3. **分镜提示词是独立一步，输入就是分镜产物。** 复用现有 `generate_episode_script` / 提示词编写服务，只读 `scripts/episode_N.json` 的结构层来渲染输入、写回 `image_prompt`；工作流新增「分镜提示词」步骤与 `AUTHOR_PROMPTS` 动作的显式顺序。

现状与目标的差距（避免重复建设）：

| 现状 | 位置 | 本文改动 |
| --- | --- | --- |
| beats 已被机械切成 12–15 秒的幕 | `server/services/short_drama_workflow.py:1737` `_mechanical_groups` | 规则移入 `lib/`，去掉模型参与 |
| 机械切幕后逐幕调用模型写 `scene_description` + `image_prompt` | 同文件 `:1778` `_request_mechanical_plan`、`:2144` 调用 | 删除模型调用；描述由 beats 机械合成 |
| 分镜与提示词同一步、同一次落盘 | `import_short_drama_episode` | 拆成「建结构」与「写提示词」两次落盘 |
| 提示词编写服务已支持只写 `image_prompt`、按待编写标记选条目 | `server/text_generation.py`、`lib/script/prompt_authoring_scope.py:108` | 保留，作为下一步的实现主体 |
| 工作流只有 `final_script`（结构 + 提示词） | `lib/workflow/workflow_rules.py:26` | 新增 `storyboard_prompt` 步骤并调整动作顺序 |

## 二、目标与非目标

### 目标

- 机械分镜：确定性、可重放、无模型调用、无缓存轮次、失败即带原因拒绝。
- 分镜产物：一份可审阅、可手改的镜头结构（`scripts/episode_N.json`），不含视觉提示词。
- 分镜提示词：独立入口、独立工具、独立工作流步骤；输入分镜产物，输出 `image_prompt`，既有质量闸不变。
- 兼容已有项目：历史 AI 分镜数据可读、可继续生成；不静默改写源稿。

### 非目标

- 不改工厂 Markdown 格式、不改 beat 解析口径、不新增源稿真相源。
- 不把景别、机位、运镜写进机械分镜（它们是创作判断，仍由提示词步骤决定）；机械分镜只定「这一幕装哪些 beat、多久、谁在场、说了什么、原文锚是什么」。
- 不改参考素材、视频、成片的生成与费用路径。
- 不引入第二份分镜 JSON；分镜产物就是 `scripts/episode_N.json` 的结构层。
- 不新增测试、不运行测试（遵循 `AGENTS.md` 的最高优先级约束）。

## 三、参照 huobao-drama 的分镜模型

huobao-drama（`myvivk/huobao-drama`，fork 自 `chatfire-AI/huobao-drama`）把分镜做成独立制作单元：`storyboards` 表按 `storyboard_number` 一行一镜，含 `scene_id`、`title`、`location`、`time`、`shot_type`、`angle`、`movement`、`result`、`atmosphere`、`image_prompt`、`video_prompt`、`bgm_prompt`、`sound_effect`、`description`、`duration`，由 Agent 工具 `save_storyboards` 写入（`backend/src/db/schema.ts`、`backend/src/agents/tools/storyboard-tools.ts`）。它的拆分仍由模型完成，但"分镜是一等产物、提示词是分镜上的字段"这一点值得对齐。

映射到本项目：

| huobao 分镜字段 | 本项目落点 | 归属步骤 |
| --- | --- | --- |
| `storyboard_number` / `scene_id` | `scene_id`（`E{集}S{序号}`） | 机械分镜 |
| `duration` | `duration_seconds` | 机械分镜 |
| `location` / 出场人物 / 道具 | `scenes`、`characters_in_scene`、`props` | 机械分镜 |
| 台词 | `utterances`（逐字） | 机械分镜 |
| 原文段落 | `source_text`（逐字锚） | 机械分镜 |
| `description` / `result` / `atmosphere` | `scene_description`（视觉改编摘要） | 机械分镜 |
| `shot_type` / `angle` / `movement` / `image_prompt` | `image_prompt` 镜头块：时间码 + 机位运镜 + 动作 + 画面/声音（fea_1026 视频提示词写法；历史四层兼容） | **提示词步骤** |
| `video_prompt` / `bgm_prompt` / `sound_effect` | 不新增独立字段；声音写进每镜的「声音：」标记 | 提示词步骤 |

不照搬的部分：huobao 的拆分数目、景别与运镜由模型自由决定；本项目要求切点可复现，因此景别/机位/运镜留给提示词步骤，避免把创作判断塞回代码。

## 四、术语与产物

- **机械分镜**：只依赖源稿、资产表、项目配置的确定性函数，把 beats 切成 12–15 秒的分镜段。
- **分镜产物**：`scripts/episode_N.json` 的 `scenes[]`，每项只含结构层字段；`image_prompt` 为空、`pending_authoring` 为真。它同时是人工审阅、参考素材准入、提示词编写三处的唯一输入。
- **分镜提示词**：`image_prompt`，唯一动态提示词，参考素材与视频共同消费。由独立步骤、独立工具写入。
- **待编写**：`pending_authoring = true` 的条目。下游（参考素材、视频）不得消费待编写条目。

## 五、机械分镜算法（无模型）

实现落点：新增 `lib/script/mechanical_storyboard.py`（纯函数，不 import 任何文本后端/`TextGenerator`），服务层只做 IO 与事务。

### 5.1 输入

| 输入 | 来源 | 用途 |
| --- | --- | --- |
| 解析后的 `ParsedEpisode` | `parse_short_drama_episode(markdown)` | blocks / beats / 场景与人物声明 / 头部时长 |
| 已登记资产 | `project.json` 的 `characters` / `scenes` / `props` | token 合法性、资产归属 |
| `【本集时长】` | `parsed.total_duration` | 时长分配目标；缺失时按档位回退（现有 `derive_tier` 口径） |
| 碎片空间 | `fragment_scene_names(...)` | 首镜必须出现的冷光/叠影/画外声 |
| 切分器版本 | 常量 `MECHANICAL_STORYBOARD_VERSION` | 幂等复用与失效 |

### 5.2 切幕：动态规划选切点

目标：分镜数 `n = clamp(round(total / 13.5), 1, beat 数)`，并把每段时长约束在 `STORY_SCENE_WINDOW_SECONDS = (12, 15)` 内。

候选切点 = 相邻两个 beat 之间；对切点 `p`（新一段从第 `p` 个 beat 开始）定义代价：

| 项 | 代价 | 理由 |
| --- | --- | --- |
| 段时长偏离 13.5 秒 | `abs(duration_i - 13.5)` | 均匀但不强求 |
| 切在 `[场景]` 块内部 | `+8` | 优先块边界，一眼换场 |
| 新段以台词 beat 开头 | `+20` | 台词必须跟它前面的动作同段（沿用 `_mechanical_groups` 的规则） |
| 段时长出窗口 | `+1000` | 窗口是硬约束（单段 beat 极少时豁免） |

在 `(beat_index, groups_made)` 上做 DP，取总代价最小的 `n-1` 个切点；同代价按更早切点决胜，保证可复现。块边界优先用 DP 的代价表达，不再写两套启发式。

边界情形：

- 无 beat：拒绝，`short_drama_parse_failed`「源稿没有可分镜的动作或台词」。
- `total / n < 12` 或 `> 15`：先增减 `n`，仍越界则允许单段越界并在回执 `duration_shortfall` 里报告（与现有导入回执同口径）。
- beat 数少于目标段数：一段至少一个 beat，`n = beat 数`。

### 5.3 时长分配

1. 每 beat 权重：台词 `estimate_spoken_seconds(text)`；动作固定 2 秒（沿用 `_MECH_ACTION_SECONDS`）。
2. 段时长 `w_i` 按权重占比分摊 `total`，四舍五入后钳进 `[12, 15]`。
3. 用 `_fit_within_window` 同口径的 ±1 微调把合计拉回 `total`；窗口是硬约束，宁可总时长有缺口也不把某段挪出窗口。
4. 台词预算：段内台词估算秒数之和必须 ≤ 段时长的 80%（沿用 `_dialogue_overflow` 的判定口径）。不满足时先在窗口内加时长；仍不满足则整批拒绝并给出「第 N 段台词 X 秒 > 段长 Y 秒」的可操作原因，不产次品。

### 5.4 资产与场景归属（无提示词 token 可依）

现有 `resolve_scene_assets` 依赖 `image_prompt` 里的场景 token（`lib/script/short_drama_import.py:543`），机械分镜阶段没有提示词，因此增加确定性归属规则：

- **角色**：本段 action beat 文本里出现的登记角色 + 台词 speaker（比较键匹配，大小写/空白归一）。块声明的 `[人物]` 不整块带入——没在 beat 出场的角色不给参考图。
- **道具**：本段全部 beat 文本里出现的登记道具。
- **场景**，按优先级：
  1. 本段 beat 所属块只有一个 `[场景]` → 取该场景；
  2. 块内多个场景时，取 beat 文本里按名字点到的场景（按出现序去重）；
  3. 全集合计只有一个登记场景 → 取它；
  4. 仍无法判定 → 取本段首块的第一个场景，并在回执 `warnings` 里记 `scene_attribution_ambiguous`（含分镜号与候选），提示用户手改。**不阻断**：场景歧义是可肉眼修正的结构信息，不该让机械步骤停摆。
- **碎片空间**：登记场景出现在本集源稿、却不在任何 `[场景]` 声明里，沿用 `_fragment_scenes`；只允许以光/声/叠影出现，提示词步骤负责写进首镜（现有 `_fragment_gap` 校验保留）。

### 5.5 `scene_description`

由 `_build_scene_description(beats)`（`lib/script/short_drama_import.py:431`）确定性合成：动作 beat 正文 + 台词的神态提示。它只承载画面可见信息，不内嵌台词原句，作为提示词步骤的"视觉改编"基底。

### 5.6 确定性与版本

- 输入相同 → `scene_id`、beat 分组、时长、资产清单、`scene_description`、`source_text` 逐字节相同（除 `updated_at` 等时间戳）。
- `MECHANICAL_STORYBOARD_VERSION` 进 meta 与提示词输入；版本变化使既有结构按新规则重建，并使已完成的分镜提示词过期（复用判定见第十二节）。
- 模块内不出现 `TextGenerator` / `generate_text` / 供应商配置读取；服务层的机械分镜函数签名里不接收任何 generator 参数，用类型与依赖注入把「无模型」变成结构约束。

## 六、分镜产物契约

`scripts/episode_N.json` 的条目（示例）：

```json
{
  "scene_id": "E1S01",
  "duration_seconds": 13,
  "segment_break": false,
  "characters_in_scene": ["林清", "陈峰"],
  "scenes": ["书房"],
  "props": ["信纸"],
  "image_prompt": null,
  "utterances": [
    {"kind": "dialogue", "speaker": "林清", "text": "这封信，你什么时候收到的？"}
  ],
  "source_text": "△林清攥紧信纸。\n林清（压着声音）：这封信，你什么时候收到的？",
  "scene_description": "林清攥紧信纸，指节发白。",
  "generated_assets": {},
  "pending_authoring": true,
  "note": null
}
```

- `image_prompt: null` 是模型层的 `PendingPrompt`，已有读时兼容；`pending_authoring: true` 是提示词编写的选择依据（`prompt_authoring_scope.py:108`）。
- 落盘 meta 新增：

```json
{
  "mechanical_storyboard_options": {
    "splitter_version": 1,
    "mode": "mechanical",
    "force_regenerate": false,
    "regenerated_scene_ids": [],
    "scene_attribution_warnings": []
  }
}
```

- 历史 `ai_storyboard_options` 保留读取，不迁移、不清空；新分镜不再写它。
- `segment_break` 恒为 `false`（沿用 `_build_scene` 的尾幕哨兵说明）；换场由场景变化表达，硬切由创作者后续显式标记。

## 七、下一步：分镜提示词编写

### 7.1 入口

- Web：分镜页「编写分镜提示词」按钮（现有 `PromptAuthoringButton` / `PromptAuthoringDialog` 复用）。
- HTTP：`POST /projects/{project_name}/episodes/{episode}/text-generation`（现有 `generate_episode_script` 路由，`fields=["image_prompt"]`）。
- Agent：`generate_episode_script` 工具，语义从"给 AI 分镜补写"改为"消费机械分镜产物"。

### 7.2 输入：分镜产物 + 承接上下文

新增渲染函数（放在 `lib/prompts/prompt_builders_script.py`，复用 `render_drama_content_for_prompt_authoring`）：

```text
### E1S01（时长 13 秒）
出场资产：角色 [林清, 陈峰]、场景 [书房]、道具 [信纸]
视觉改编：林清攥紧信纸，指节发白。
口播：
  - [台词] 林清：这封信，你什么时候收到的？
原文锚：△林清攥紧信纸。/ 林清（压着声音）：……
上一分镜末镜（只读承接，不得照抄）：E0?…
```

规则：

- 只读分镜产物与项目资产表，不重新解析 Markdown 来"再分一次镜"；源稿只用于 revision 冲突校验与碎片空间识别。
- "上一分镜末镜"仅在该分镜已有 `image_prompt` 时渲染（部分编写场景）；整批编写时上一段来自同一次输出，由现有 `handoff_problem` 校验兜住。
- 碎片空间仍置顶渲染（现有 `_build_drama_prompt_authoring_prompt` 已做）。
- 资产事实（外观/来路）仍只作依据、不给模型抄写（现有 `_prop_scene_facts` 保留）。

### 7.3 生成与校验

- 输出 schema 不变：`[{scene_id, image_prompt}]`，`scene_id` 对齐锚。
- 校验沿用现有全套：`lint_shot_prompt`、`storyboard_motion_prompt_problem`、`handoff_problem`、`seam_prop_problem`、`_fragment_gap`、语义连续性审查（`review_storyboard_semantics`）。
- 失败返修沿用 `_PROMPT_AUTHORING_ATTEMPTS`（5 轮）与单条局部修复；耗尽整批拒绝、不写半成品。
- 不允许把"没写出来的提示词"写成骨架冒充：分镜步骤已经给了结构，提示词步骤要么通过闸门，要么报错。

### 7.4 范围与顺序

- 默认范围：全部 `pending_authoring = true` 的条目，按分镜顺序。
- 点名条目：只写点名条目；`rewrite=true` 才覆盖已有 `image_prompt`（现有覆盖确认与丢失清单不变）。
- 顺序约束：点名编写某条时，若它前一条仍无 `image_prompt`，按现有规则拒绝并提示"先编写前一条"（`script_generator.py:697`）。UI 的"编写提示词"只在存在连续待编写前缀时可用，或自动从首条待编写开始。

### 7.5 写回与失效

- 写回只改 `image_prompt` 与 `pending_authoring`，清除待编写标记；`updated_at` / `generator` 刷新（现有 `_authored_script`）。
- `image_prompt` 变化使该分镜的参考素材与视频按 Artifact Manifest 过期；有媒体时仍须 `confirm_artifacts` 才允许覆盖（沿用现有入口）。
- 写回使用同一把项目锁与 `expected_fingerprint`；并发编辑按现有冲突拒绝。

## 八、工作流、准入与 UI

### 8.1 动作与顺序

`WorkflowActionType` 不变（`PLAN_SHORT_DRAMA_STORYBOARDS` / `AUTHOR_PROMPTS` 已存在），改判定顺序（`lib/workflow/workflow_state.py:1499`、`:1530`）：

1. 工厂源稿缺失 → `COLLECT_PROJECT_INPUT`。
2. 资产未登记/缺描述/缺资产图 → `PREPARE_EPISODE_ASSETS`。
3. 无正式脚本、源稿 revision 变化、结构非法、结构版本过期 → `PLAN_SHORT_DRAMA_STORYBOARDS`（机械分镜）。
4. 有结构且存在 `pending_authoring` 条目 → `AUTHOR_PROMPTS`（分镜提示词）。
5. 参考素材缺失 → `GENERATE_SHOT_GRIDS`。
6. 视频缺失 → `GENERATE_VIDEOS`。
7. 无剪辑时间线 → `CREATE_EDIT_TIMELINE`。

现状 `:1530` 的 `pending_ids` 被并入第 3 条；必须挪到第 4 条，否则机械分镜后计划会反复要求"重新分镜"。

### 8.2 步骤

`lib/workflow/workflow_rules.py` 的 `_STEP_IDS` 增加一步：

```text
project_input → asset_sheets → final_script → storyboard_prompt → script_structure → shot_grid → video → edit
```

- `final_script` 的完成条件改为「有条目」（不再要求无待编写）。
- `storyboard_prompt` 的完成条件为「没有待编写条目」。
- `AUTHOR_PROMPTS` 映射到 `storyboard_prompt`；`PLAN_SHORT_DRAMA_STORYBOARDS` 仍映射 `final_script`。
- `text_episode_script` 任务映射从 `final_script` 改到 `storyboard_prompt`（`lib/workflow/workflow_plan.py:162`）。
- 前端 i18n 增加步骤名「分镜提示词」与动作文案；`WorkflowPanel` 按新 step id 渲染。

### 8.3 准入

- `admit_author_prompts` 不变（要求正式脚本存在且有 pending）。
- `admit_shot_grids` 增加一条：存在待编写条目时拒绝并给原因码 `storyboard_prompt_pending`，避免用户在提示词未写时点参考素材。

### 9.3 部分重分镜

`regenerate_scene_ids` 语义改为确定性重切。因为切分是源稿的函数，同一份源稿重切会得到同一份结构，所以实现是「整体重算 + 定点清空」而不是子树重切：

- 整体按同一 DP 重算结构；点名分镜的 `image_prompt` 置 `null`、`pending_authoring = true`；
- 未点名分镜在「原文锚 + 时长」不变时整体沿用旧条目（提示词、媒体绑定与手改都不动）；
- 点名的分镜在重算后不存在（源稿已改）即拒绝，要求 `force_regenerate=true`，不静默拼；
- 源稿变化导致结构变化时，未点名但结构已变的分钟同样回到待编写，绝不保留对不上结构的提示词。

## 十一、兼容与迁移

- **历史项目**：已有 `image_prompt` 的分镜不动；`ai_storyboard_options` 只读兼容；不要求迁移或补写。
- **待编写条目**：历史项目里 `pending_authoring` 为真但无提示词的条目，直接进入新步骤处理，无需重分镜。
- **API 去字段顺序**：① 后端先接受并忽略 `planning_strength`（响应不再返回）；② 前端与 Agent 工具去掉该字段；③ 下一版删字段。避免旧客户端因 `extra="forbid"` 直接 422。
- **meta 版本**：结构读取以 `mechanical_storyboard_options.splitter_version` 为准；缺失但 `scenes` 合法且无 pending 的历史脚本，按"已完成"对待，不强制重建。
- **缓存**：删除 `drafts/short_drama_plan_*.json` 计划缓存的使用；存量文件不主动删除，由下一次保存覆盖或忽略。

## 十二、幂等、并发与失效

- 同一 `source_revision` + `splitter_version` + 无 `force_regenerate`：直接复用现有结构，返回 `reused=true`，不写盘。
- 源稿 revision 变化：重建结构。按 `source_text` 指纹保留 beat 分组未变的分镜的 `image_prompt`；分组变化的分镜置 `null` + `pending_authoring`，并在回执列出受影响分镜。
- 手改结构（用户通过分镜编辑改时长/台词？当前结构字段不对用户开放编辑，保持现状）：若结构字段与机械产物不一致，`force_regenerate` 前先按现有 `_require_preservable_script` 口径判定，避免静默覆盖。
- 并发：沿用项目锁 + `expected_fingerprint` + 源稿 revision 复核；机械分镜是同步写盘，不占任务队列；提示词步骤仍按长任务执行。
- 失败：机械分镜整批不落盘（构建失败即拒绝）；提示词步骤整批不落盘（现有行为）。

## 十四、验收标准

1. 机械分镜全程不调用文本模型：同源码路径下无 `TextGenerator` 依赖，服务层不读供应商配置；回执 `mode = "mechanical"`。
2. 同一源稿重复执行，`scene_id`、beat 分组、时长、资产、`source_text`、`scene_description` 完全一致；`force_regenerate` 只影响写盘与否，不影响结果。
3. 每个分镜的 beat 连续、不重不漏；时长落在 12–15 秒（或回执明确报告越界原因）；台词估算不超段长。
4. 落盘条目 `image_prompt = null`、`pending_authoring = true`；参考素材/视频入口对待编写条目明确拒绝。
5. 分镜提示词步骤只读分镜产物（`scene_id`、时长、资产、口播、`source_text`、`scene_description`）与上一镜承接上下文，不重新读 Markdown 分镜；输出 `image_prompt` 通过现有全套闸门；写回后 `pending_authoring` 清除。
6. 工作流计划按「机械分镜 → 分镜提示词 → 参考素材 → 视频」推进；`final_script` 完成后不再因待编写而回到分镜动作。
7. 历史 AI 分镜项目可读、可继续生成；`image_prompt` 修改仍使参考素材与视频过期，已有媒体仍要求确认。
8. 前端不再出现"内容优化强度"，Agent 工具描述不再承诺"AI 分镜多轮返修"。

## 十五、验证方式（本项目禁止运行测试）

- 静态闸门：`uv run python scripts/gate.py backend frontend`（项目闸门不含测试）。
- 代码走读：机械模块的 import 面（不得出现 `lib.backends` / `TextGenerator`）；工作流动作顺序；提示词输入渲染字段与分镜产物一一对应。
- 手工走查（单集样例）：
  1. 入库一集源稿 → 点「机械分镜」→ 检查 `scripts/episode_1.json`：N 个分镜、提示词全空、待编写全真、时长合计与 `【本集时长】` 差异。
  2. 重复点一次 → 回执 `reused=true`，文件不变。
  3. 点「编写分镜提示词」→ `dry_run` 检查输入块含分镜号/时长/资产/口播/原文锚/视觉改编；实跑后检查每条 `image_prompt` 覆盖时长、时间码 + 机位运镜 + 动作 + 画面/声音齐全、承接通过。
  4. 工作流面板：确认步骤依次点亮，不再出现"重新分镜"回流。
  5. 历史项目打开：分镜与提示词原样，可继续参考素材/视频。
