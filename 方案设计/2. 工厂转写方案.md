# 短剧工厂转写方案

> 读工厂单集原文 → 切分镜 → 写 `scripts/episode_N.json`。
> 分镜 = 一段视频的描述。本文只管转写这一步；参考图、出图、出视频都是后面的步骤，不在本文。

## 一、概念定义

| 概念 | 定义 |
|---|---|
| **分镜** | 脚本里可独立生成的一段视频（12~15 秒）。 |
| **分镜正文** | 这段视频的描述：谁、在哪、连续发生什么、镜头怎么走、什么声音、台词归属。是该段视频唯一的内容真相。 |
| **台词** | 分镜正文的一个字段（`utterances`）：谁说的、说了什么。供配音、字幕、口型使用。 |
| **资产** | 角色 / 场景 / 道具的名字 + 外观描述。转写负责登记；登记后的用途不在本文范围。 |
| **切分镜** | 把工厂单集原文按拍（动作行 / 台词行）切成 N 段。 |

## 二、正文密度：12~15 秒不是四行字能撑住的

一段 12~15 秒的视频，要拍得紧凑丰满，正文必须给到**每秒至少一个可拍的细节**。细节没法机检，机检折算成行：一行动作或台词大约承载 2 个细节，所以 12~15 秒段至少要 6~8 行，即 6~8 拍（口径见 §5.1）。写作时按细节构思，落笔一行一拍：

- 环境**参与动作**：雨水渗进门缝、货箱挡路、塑料筐被踢开——不是一句"夜，仓库"的背景板；
- 人物**连续动作链**：进门 → 顿住 → 扫视 → 踢开筐 → 走近，一步接一步，不能只有一个"推门而入"就跳到台词；
- **对手戏反应**：A 说狠话时 B 在干什么（摁灭烟头、别过脸）——沉默的反应也是内容；
- 台词**前后有承接**：说话前的姿态、说完后的动作，避免"站定→念台词→切镜头"的空档。

**密度从哪来**：从工厂单集原文来。转写是忠实映射，不注水——原文只有一句"推门而入"，转写不会替它编出踢筐、扫视。所以密度要求落在**工厂写原文的环节**（`1. 工厂生成方案.md` 的单集正文要求）：动作行要写足连续的拍，一拍一个可执行的动作，而不是一句概括。

## 三、转写做什么

1. 读 `source/short_drama/episodes/episode_NN.md`；
2. 按 `[场景]` 块 / `△` 动作行 / `角色（神态）：台词` 行切分镜，每段落在 12~15 秒窗口（`STORY_SCENE_WINDOW_SECONDS`），切点只落在拍与拍之间，不劈断台词；
3. 每段分镜产出：
   - `text`：这段视频的描述——环境 + 连续动作 + 神态 + 镜头走法 + 台词归属（`@[角色]{台词}`）；
   - `utterances`：从原文台词派生，逐字保留；
   - 引用：该段涉及的角色名、场景名（有道具行则含道具名）；
4. 登记资产：名字 + 外观描述写进 `project.json`，已存在的不覆盖；
5. 回执：分镜数、总时长与 `【本集时长】` 的差额、缺描述的资产清单。

转写不写提示词、不生成任何图片或视频。

## 四、正文映射规则

工厂原文（节选，按密度要求写足后）：

```
【本集时长】：120 秒
[场景]：城郊仓库｜水泥地、铁门、单侧顶光
[人物]：林辰（隐忍龙王｜三十岁上下，寸头，旧夹克）、陈峰（嚣张富二代）
△ 顶光从铁门缝隙切进来，照在湿漉漉的水泥地上，雨水顺着门缝往里渗。
△ 林辰侧身挤开半掩的铁门，夹克肩膀浸出深色，在门口顿了一秒，抬眼扫过墙角的货箱。
△ 陈峰靠在货箱上没动，把烟头在铁栏杆上摁灭。
△ 林辰抬脚踢开挡路的空塑料筐，径直走向陈峰。
林辰（冷笑）：三年了，你们欠我的，该还了。
陈峰（别过脸）：你疯了？
```

切出的分镜正文：

```
顶光从铁门缝隙切进来，照在湿漉漉的水泥地上，雨水顺着门缝往里渗。
@[林辰] 侧身挤开半掩的铁门，夹克肩膀浸出深色，在门口顿了一秒，抬眼扫过墙角的货箱。
@[陈峰] 靠在货箱上没动，把烟头在铁栏杆上摁灭。
@[林辰] 抬脚踢开挡路的空塑料筐，径直走向陈峰，冷笑。
@[林辰]{三年了，你们欠我的，该还了。}
@[陈峰] 别过脸。
@[陈峰]{你疯了？}
```

| 工厂原文 | 正文处理 |
|---|---|
| `[场景]` 行 | 环境细节进动作拍；场景名用于登记资产 |
| `[人物]` 行 | 只登记资产；正文首次出现写 `@[名字]` |
| `[道具]：名称｜外观` 行 | 登记资产（名称 + 外观描述）；道具在动作拍里出现时保留原样 |
| `△` 动作行 | 逐拍保留，一句一行，不合并、不概括 |
| `角色（神态）：台词` | 神态单独成一个动作拍；台词 `@[角色]{台词}` |
| 旁白 / 画外音 | 裸 `{台词}` |
| 镜头走法 | 原文写了（推、拉、摇、移）就保留，没写就空着，不编 |

## 五、工厂侧配套：怎么实现

三项都是硬闸门，落在两处：工厂本地脚本（Agent 写稿时立刻能看到）与服务端落库（跳过脚本也拦得住）。

### 5.0 为什么是两道闸

`scripts/validate_episode.py` 是 Agent 自己跑的。它跳过去直接调 `ingest_short_drama_artifacts`，就没有任何东西会拦——SKILL 里写"机检 FAIL 不得交稿"只是纪律，不是机制。

所以判定抽成纯函数放 `lib/short_drama_quality.py`（无 I/O，输入 Markdown，输出问题列表），`ingest_short_drama_artifacts` 落盘前调用一次；skill 里的脚本保留同等判定（它要能独立 `python3` 跑，不能 import 服务端代码）。两边一致性由 `tests/unit/lib/test_short_drama_quality_parity.py` 守：同一批 fixture 跑 CLI 与 lib，断言 fail/warn 集合逐条相同。

### 5.1 密度机检（E12）

**计数单位**：一拍 = 一个 `△` 动作行或一条台词行。不按标点切子句——切法随写作习惯晃动，同一份稿子换个标点就换个结果，机检就不可复现。

**阈值**：`required = ceil(声明秒数 ÷ 2)`。12~15 秒段 6~8 拍；105 秒集 ≥53 拍；180 秒集 ≥90 拍。秒数取 `【本集时长】`，没写时按档位中位兜底（standard 105 / long 180 / manju 75）。

**为什么不是「每秒一拍」**：按这个口径先量了工厂自带的两份示例：

| 示例 | 声明时长 | △ 行 | 台词行 | 行级拍 | 每秒一拍要求 | 差 |
|---|---|---|---|---|---|---|
| `examples/ep01-longwang-demo.md` | 105 秒 | 7 | 7 | 14 | 105 | −91 |
| `examples/long-format-3min-demo.md` | 180 秒 | 20 | 23 | 43 | 180 | −137 |

再把 E1 的体量约束叠上：标准档正文 350~500 字 / 90~120 秒，即每秒只有 3~5.6 个字。要凑到每秒一拍，每拍只能分到 3~5 字，也就是"△ 推门。"这种碎片；而一句 15 字台词也只算一拍，越写越亏。**「每秒一拍」在现有档位下只能靠碎片凑数，不是密度。**

落成可执行的等价口径：**创作上仍是每秒一个可拍细节，机检按「一行≈2 个细节」折算，即每 2 秒至少一行**。12 秒段 6 行 = 12 个细节，105 秒 53 行 = 106 个细节，与要求对得上，也不和 E1 打架。

阈值抽成常量 `BEAT_SECONDS = 2.0`；改成 1.0 只动这一个数，但得同步抬 E1 上限，否则没有一集能过（见 §十一）。

**实现**：

```python
# scripts/validate_episode.py（顶部补 import math）
BEAT_SECONDS = 2.0  # 一行（动作/台词）折算的秒数
PROFILE_SECONDS = {"standard": 105, "long": 180, "manju": 75}


def declared_seconds(text, profile):
    m = re.search(r"【本集时长】[：:]\s*(\d+)\s*秒", text)
    return int(m.group(1)) if m else PROFILE_SECONDS[profile]


def beat_count(text):
    """一行一拍：△ 动作行 + 台词行（旁白写作「旁白：…」也走 _is_dialogue）。"""
    n = 0
    for line in text.splitlines():
        s = line.strip()
        if s.startswith("△") or _is_dialogue(s) is not None:
            n += 1
    return n
```

判定：

```python
secs = declared_seconds(text, profile)
need = math.ceil(secs / BEAT_SECONDS)
have = beat_count(text)
if have < need:
    fails.append(
        f"E12 拍数 {have} < {need}（{secs} 秒 ÷ {BEAT_SECONDS:g} 秒/拍），缺 {need - have} 拍；一句概括不算拍，拆成连续动作"
    )
```

- docstring 的检查项表加 E12 一行，退出码不变；
- 错误信息给"缺几拍"，不给"请补充细节"这种没用的提示。

**服务端第二道闸**：

```python
# lib/short_drama_quality.py
@dataclass(frozen=True)
class QualityIssue:
    code: str  # E12 / E13 / E14
    level: str  # "fail" | "warn"
    message: str
    line: int | None


def check_episode(markdown: str, *, bible: str | None = None, profile: str = "auto") -> list[QualityIssue]: ...
```

挂进 `lib/short_drama_ingest.py::ingest_short_drama_artifacts`，在 `atomic_write_bytes` 之前：

```python
for item in prepared:
    if _EPISODE_PATH_RE.match(item.path):  # episodes/episode_07.md
        issues = check_episode(item.content.decode("utf-8"), bible=_read_bible(source_dir))
        fails = [i for i in issues if i.level == "fail"]

            raise ShortDramaArtifactError(
                f"{item.path} 机检未过："
                + "；".join(f"{i.code} 第{i.line}行 {i.message}" if i.line else f"{i.code} {i.message}" for i in fails)
            )
```

落盘前拦，失败一个字节都不写，不会留下半套工件。

### 5.2 道具行（E13）

**模板**（`templates/episode-format.md` 标准档与长档两处，放在 `[人物]` 下面）：

```text
[道具]：铁门｜锈迹斑斑、半掩、门轴下垂       ← 有戏的道具才登记；「｜」后接外观（必填）
```

一个道具一行，要几个写几行（外观里带顿号，一行多道具切不干净）。

**机检 E13**：

| 情况 | 级别 |
|---|---|
| 条目缺 `｜`，或 `｜` 后为空 | FAIL（报条目名） |
| 同一集出现两个同名道具 | FAIL |
| 道具名在该集动作行/台词里一次都没出现 | WARN「登记了但没进戏」 |
| 道具名与角色或场景重名 | WARN（转写会记进 `asset_conflicts`） |

**解析**（`lib/script/short_drama_import.py`）：

```python
_PROP_RE = re.compile(r"^\[道具\][：:]\s*(.+)$")
# ParsedEpisode 增加
props: dict[str, str] = field(default_factory=dict)  # 名称 → 外观
```

切条目不能按「、」切：外观本身就爱用顿号（"锈迹、半掩、门轴下垂"），一切就碎。所以**一个道具一行**，与 `[场景]` 同一种写法，一行只认第一个 `｜`：

```text
[道具]：铁门｜锈迹斑斑、半掩、门轴下垂
[道具]：断椅｜木刺外翻，缺一条腿
```

```python
def _split_prop_line(line: str) -> tuple[str, str] | None:
    """``铁门｜锈迹、半掩`` → ``("铁门", "锈迹、半掩")``；缺 ``｜`` 返回 None。"""
    name, sep, look = line.partition("｜")
    return (name.strip(), look.strip()) if sep and name.strip() else None
```

**归属到幕**：`_build_scene` 里 `props` 不再恒 `[]`。`[道具]` 是集级声明，但一幕只该登记这一幕真的用到的道具，所以按"该幕原文里出现过这个名字"判：

```python
def _build_scene(..., props: list[str] | None = None) -> dict[str, Any]:
    text = "\n".join(beat.raw for beat in sub_beats)
    ...
    "props": sorted(name for name in (props or []) if name in text),
```

调用方把 `list(parsed.props)` 传进来；跨块合并的幕取并集（与 `characters` 同法）。整集道具不能串到每一幕，否则后面的资产参考会带着无关道具走。

**登记**：`referenced_asset_descriptions(parsed)` 增加 `"prop": parsed.props`；`register_missing_assets` 本来就支持 prop 桶，不改。

**回归**：现有断言 `props == []` 的用例要改；新增「有 `[道具]` 行 → 命中幕有值、未命中幕为空」「同一道具跨两幕 → 两幕都有」。

### 5.3 外观必写（E14）

**机检**：

```python
entries = _split_character_entries(line)  # [(名字, 外观)]，与 importer 同一套括号深度切法
missing = [name for name, look in entries if len(look.strip()) < 8]
if missing:
    fails.append(f"E14 [人物] 行外观缺失或过短：{'、'.join(missing)}；每位出场角色须从人物圣经抄入完整外形（30~60 字）")
```

下限 8 字挡的是「嚣张富二代」这类标签；推荐 30~60 字写进模板注释。一行多角色逐个判，报名字不报行号——一行里第几个说不清。

**与圣经的一致性**（防改写、防漏抄）：可选参数 `--bible character-bible.md`：

```python
norm = lambda s: re.sub(r"\s", "", s)
para = bible_paragraph(name)  # 圣经里该角色的段落
if para is None:
    fails.append(f"E14 人物圣经里没有 {name}，外观抄无可抄")
elif norm(look) not in norm(para):
    fails.append(f"E14 {name} 的外观不是从人物圣经原样抄入（被改写或漏抄）")
```

第二条同时在拦 §八 的第 3 类成因：圣经里没写的角色，在交稿这一步就过不去，不会拖到转写后才发现。

**调用点**：`SKILL.md` Step 5 命令改为 `python3 scripts/validate_episode.py <单集.md> --bible character-bible.md`；Step 3 加一句「写 `[人物]` 行前先取该角色在圣经里的外形段，原样抄入括号」。

## 八、缺失描述：修复场景怎么实现

正常流程里不该缺（§五 三道闸都过了，角色、场景、道具都有外观）。会缺的只有三种：

1. 绕过工厂手写单集原文直接转写；
2. 机检被跳过（调试、紧急交稿）；
3. 人物圣经本身没写这个角色（§5.3 的 `--bible` 会在交稿时拦下，这是它的上游）。

这条不做成流程步骤，但必须能闭环：**服务端算出缺谁 → 页面上看见 → 就地补 → 状态自动消失**。

### 8.1 服务端算出"缺谁"

`ShortDramaImportResult`（`server/services/short_drama_workflow.py:36`）增加一个字段：

```python
assets_without_description: list[dict[str, str]]
# [{"type": "character", "name": "林辰", "reason": "source_missing"}]
```

计算点就在同一个函数的 `_update_project` 里，`register_missing_assets` 之后——那里已经拿着 `current_project` 的最新快照：

```python
for atype, bucket in (("character", "characters"), ("scene", "scenes"), ("prop", "props")):
    for name in names.get(atype, []):  # 本集引用到的名字
        entry = (current_project.get(bucket) or {}).get(name) or {}
        if not str(entry.get("description") or "").strip():
            missing.append(
                {
                    "type": atype,
                    "name": name,
                    "reason": "source_missing" if name in registered.get(atype, []) else "existing_blank",
                }
            )
```

- 只报**本集引用到的**资产，不扫项目全量；
- `reason` 区分两种情况：这次源稿没给外观（`source_missing`）、项目里本来就有这个资产但一直是空描述（`existing_blank`）；
- `as_dict()` 里为空就不输出，正常交稿的回执长度不变。

### 8.2 页面上怎么看见

`AI 分镜` / `AI 重新分镜` 成功后，结果区多一行黄条（复用现有批量结果面板的样式）：

```
⚠ 2 个资产缺描述：林辰（角色）、铁门（道具）           [去补描述]
```

「去补描述」按第一个缺失资产的类型跳到对应资产页（`StudioCanvasRouter.tsx:449` 起的 `CHARACTERS` / `SCENES` / `PROPS` 路由），带 `?focus=<名称>` 让详情抽屉直接打开那一条。不弹新页面，不建批量补全流程——修复是例外路径，一个入口就够。

### 8.3 补描述这个动作已经有了，缺的是上下文

资产详情编辑器里已有「AI 补全」按钮（`AssetDetailEditor.tsx:184` → `POST /projects/{p}/{type}s/{name}/ai-fill`），只填空字段、不覆盖已有内容（`_asset_router_factory.py:550-552`）。

现状不好用的原因很具体：`_collect_asset_context`（`_asset_router_factory.py:220`）只从 `scripts/*.json` 里扒场景摘录，**工厂工件一个字都没读**。角色圣经里那几百字外形，模型根本看不见。

改两处：

**① 上下文补 `canon` 块**

```python
canon: list[str] = []
if asset_type == "character":
    canon.append(_bible_section(project_dir / "source/short_drama/character-bible.md", name))
elif asset_type == "scene":
    canon.append(_marker_section(project_dir / "source/short_drama/series-outline.md", name))
    canon += _episode_marker_lines(project_dir, "场景", name)  # 各集 [场景] 行
elif asset_type == "prop":
    canon += _episode_marker_lines(project_dir, "道具", name)  # 各集 [道具] 行
context["canon"] = [c for c in canon if c]
```

**② 提示词里定优先级**

`_build_ai_fill_prompt`（同文件 `:262`）在"剧本摘录"之前插入：

```
【项目设定｜优先依据】
（来源：人物圣经 / 全剧大纲 / 单集标记行；与剧本摘录冲突时以此为准）
...
```

优先级写死为 **canon > 剧本摘录 > 题材补全**。现在的规范（`asset_description_rule.md`）已经允许按题材补全，缺的就是让模型先看到 canon。

### 8.4 补完之后

- 缺描述名单是**回执快照**，不落库、不建状态机；资产页的"缺描述"由 `hasUsableDescription`（`AssetSheetStatusBadge.tsx:2`）实时判定，补完自然消失；
- 漏补的代价是明确的，不是静默失败：资产生成侧本来就拿这个判定挡着，画廊上写「另有 N 个因缺描述不会生成」（`AssetSheetBatchControls.tsx:34`），不会拿名字瞎猜。

### 8.5 回归

1. 单集只给名字不给外观 → 回执 `assets_without_description` 含该角色，`reason=source_missing`；
2. 项目里既有资产原本空描述 → `reason=existing_blank`；
3. 点「AI 补全」→ 描述非空，且人物圣经里的外形词出现在结果里（证明确实读到了 canon）；
4. 已有描述的资产点「AI 补全」→ 描述一个字不变；
5. 道具行上线后，道具走同一份名单、同一条修复路径。


## 九、页面交互：在哪触发

### 9.1 入口只有一个：分镜页

按钮放在**分镜页**，不放在剧本页。理由：转写的产物就是分镜，动作出现在产物所在的位置；剧本页的职责是读源稿、改源稿，不承担生产动作。

### 9.2 为什么不能只加在剧本页

剧本页的「剧本」是 `EPISODE_VIEW_SOURCE` 改了标签（`EpisodePage.tsx:306`），它渲染的是 `FactoryEpisodeSourceView`——一行路径 + 一个只读 `<pre>`，源稿存在时连按钮都没有（第 44、52 行只有源稿缺失时才给按钮）。把生产入口挂在这种只读阅读页上，用户在分镜页永远找不到「怎么把我的剧本变成分镜」。

分镜页则天然是生产现场：有脚本时那一排动作（编写提示词、批量补齐）已经在那儿了，产物在哪、动作就在哪。

### 9.3 现状（按当前代码）

| 场景 | 现状代码 | 结论 |
|---|---|---|
| 分镜页·已有正式脚本 | `TimelineCanvas.tsx:218` 的 `EpisodeHeaderActions`，工厂集因 `importedShortDrama` 为真把三个创建入口隐藏（第 221-226 行），只剩「编写提示词」和批量按钮 | 「AI 重新分镜」直接加进这一排，位置就在现有动作旁 |
| 分镜页·还没转写 | `TimelineCanvas.tsx:181-187`：`!episodeScript && !hasDraft` 时直接 `return` 一句 `select_episode_hint`，**头部动作区根本不存在** | 必须先补一个工厂集专用空态，才有地方放按钮 |
| 分镜页·开着宫格 | 分镜页改由 `GridImageToVideoCanvas` 渲染；`view === "board" && hasScript` 时同样有 `EpisodeHeaderActions`（第 230 行），没脚本时同样是 `select_episode_hint`（第 178 行） | 这一处也得同步加，不能只改 TimelineCanvas |

顺带修一个现有缺陷：未转写的工厂集点「分镜」，页面显示的是 `请在左侧选择剧集`（`select_episode_hint`）。集明明已经选中了，这句文案是错的，本方案的空态把它换掉。

### 9.4 按钮名称与状态（已定）

| 本集分镜数 | 按钮文案 | i18n key |
|---|---|---|
| 0 | **AI 分镜** | `short_drama_ai_storyboard` |
| ≥1 | **AI 重新分镜** | `short_drama_ai_restoryboard` |

- 界面上不出现「转写」二字，统一叫「分镜 / 重新分镜」；「转写」只是本文与代码里的内部说法。
- 两个文案共用一个组件，只按分镜数切标签，不给用户两个按钮。
- 有分镜时按钮不降级为次要样式，仍是主按钮，但点击先出覆盖确认。

### 9.5 点击后发生什么

两种情况打开同一个弹窗，差别只在标题与覆盖区：

| | 分镜数为 0 | 分镜数 ≥1 |
|---|---|---|
| 标题 | `AI 分镜 · 第 3 集` | `AI 重新分镜 · 第 3 集` |
| 覆盖区 | 无 | 红字「本集已有 9 个分镜，重新分镜会整体替换」+ 勾选框，未勾选不能提交 |
| 主按钮 | 「开始分镜」 | 「重新分镜」 |

### 9.6 剧本页的「重新导入」怎么处理

`DramaScriptContentView` 标题行现有「保存源稿」「重新导入」（`short_drama_source_reimport`）。按 9.1 的口径，转写入口只在分镜页，同一条动作留两个入口会出现两套确认提示和两套措辞。

**默认处理：剧本页移除「重新导入」，保留「保存源稿」**，重新分镜统一走分镜页的「AI 重新分镜」——两者读的都是已保存的那份源稿，能力不丢。要恢复源稿页就地重解析，加回按钮并把文案改成「AI 重新分镜」即可，成本一道 JSX。

### 9.7 改动清单（文件级）

| 文件 | 改什么 |
|---|---|
| `shared/ShortDramaStoryboardButton.tsx` | 新增。按钮 + 弹窗 + 提交 + 成功后刷新，两处复用 |

### 9.8 弹窗内容

弹窗只保留单集形态，字段全部从当前集带出，不让用户再选集：

| 区域 | 内容 | 来源 |
|---|---|---|
| 源稿 | 只读摘要（路径、行数、字符数） | `getShortDramaSource` |
| 预览 | 分镜数、总时长 / `【本集时长】`、引用资产、缺描述资产 | 与转写同一套解析逻辑，避免预览和结果不一致 |
| 覆盖 | 见 9.5 | `meta.storyboards.available` |
| 按钮 | 「取消」+ 主按钮 | 提交后转 loading，禁用关闭 |

批量不新建弹窗：沿用现有「批量导入」的粘贴入口，只把提交动作从导入换成转写。

## 十、预期结果：页面上能看到什么

本文不画界面示意、不新增界面稿，一切以项目当前真实页面为准。**除下面列出的两处入口外，不改动页面上的任何其它内容与布局**：分区、顺序、已有按钮、提示词输入框、媒体卡、右栏一律保持现状。与现状的差异只有两处：

1. 页头动作区最左多一颗按钮：分镜数 0 时叫「AI 分镜」，≥1 时叫「AI 重新分镜」，与「编写提示词」「补齐分镜图 · N」同一排；
2. 未分镜的工厂集进分镜页时，现状的「请在左侧选择剧集」换成一个带「AI 分镜」主按钮与「先看剧本」次链接的空态。

弹窗内容见 §9.8。

### 10.1 看不到的东西

- 剧本页没有任何发起分镜的按钮；
- 页面上不出现「转写」二字，只有「AI 分镜 / AI 重新分镜」；
- 转写本身不写提示词：分镜提示词 / 视频提示词两个输入框保持空态，等「编写提示词」这一步来填；
- 分镜页不出现「AI 原创剧本」「导入短剧工厂剧本」「AI 生成剧本」三个入口（现状已隐藏，保持）。

### 10.2 可度量的验收

1. 未分镜的工厂集，进分镜页两次点击内能发起「AI 分镜」（现状是零入口、且文案错为「请在左侧选择剧集」）；
2. 分镜数 0 时按钮叫「AI 分镜」，≥1 时叫「AI 重新分镜」，同一位置只出现一个；
3. 剧本页不存在任何发起分镜的按钮；
4. 弹窗预览的分镜数、时长与实际结果一致；
5. 已有分镜时，不勾选覆盖不能提交；
6. 同一份源稿重复「AI 重新分镜」，结果逐字不变；
7. 宫格项目与普通项目两种画布下，按钮与空态表现一致；
8. 异常文案都带集号，不出现只有「分镜失败」四个字。
9. 交稿时拍数不足的集落不了库：调用 `ingest_short_drama_artifacts` 返回的错误里带集号、E12、缺几拍，且 `source/short_drama/` 下一个字节都没变；
10. `[人物]` 行外观为空的集同样落不了库（E14），道具行缺 `｜` 的集落不了库（E13）；
11. 缺描述的集分镜成功后出现黄条与「去补描述」，点进去是那条资产的详情抽屉；补完再回来看，黄条不再出现（回执是快照，资产页状态实时）。

## 十一、待确认

**`BEAT_SECONDS` 取 1.0 还是 2.0。**

- 2.0（默认，每 2 秒一拍）：与现有 E1 体量区间自洽，105 秒 ≥53 拍；工厂现有两份示例（14 拍、43 拍）会被拦下，需按新密度重写样例。
- 1.0（每秒一拍，你最初的措辞）：105 秒要 105 拍，每拍只能分到 3~5 字（350~500 字 ÷ 105 秒），只能靠"△ 推门。"这类碎片凑数；要真按这个密度写，E1 上限得从 500 抬到 800 左右，属于改档位规格，影响的不止机检。

我按 2.0 写的实现。你要 1.0 就说一声，我连同 E1 档位一起改，不留两套互相打架的数。
