# 3. AI 分镜方案

> **修订记录（2026-10-21，用户拍板后生效，实现已落地）**
>
> 1. **流程独立**：AI 分镜是独立步骤，输入只有剧本工厂源稿（已保存 Markdown）与项目已登记资产，不读其它模式产物、不读视频/图像供应商能力。
> 2. **AI 是唯一路径**：删除「快速切分」入口与机械回落；AI 校验失败不再回落机械切分，而是**带原因持续返修**（`_PLAN_ATTEMPTS` 轮），穷尽后报错——报错即「模型/流程无法运作」，绝不交付骨架提示词冒充 AI 结果。动作动词白名单（`_ACTION_WORDS`）扩充为宽词表，避免误杀合法提示词；新增提示词标准化（`_normalize_plan`：统一镜头标记写法与行尾空白后再校验）。
> 3. **缺描述置灰**：本集源稿引用的资产缺外观描述时（GET 源稿回带 `assets_missing_description`），分镜入口置灰并提示先去补齐；「同时用 AI 补齐缺描述资产」勾选删除。
> 4. **按分镜重生成**：重新分镜弹窗改为分镜复选框（默认全选）——全选 = 整体 AI 分镜；只勾选部分 = 按分镜重写（`regenerate_scene_ids`，beat 分组用 `scene_beat_groups` 从 `source_text` 锚定），未勾选分镜原样保留，已生成的媒体与手动编辑不会丢。
> 5. 契约文档 `docs/agents/short-drama-markdown-reimport.md` 已同步修订（mode 两态、无回落、reimport 请求、缺描述清单、多语言 key）。

## 目标

输入源固定为本集工厂 Markdown 源稿 `source/short_drama/episodes/episode_NN.md` 和项目已登记资产。AI 分镜只生成视觉制作派生状态，不修改工厂源稿。

1. **智能切分**：在结构保真前提下，用 AI 语义断点替代机械按时长装桶。
2. **内容优化**：用 AI 把逐字转写提升为镜头可读的描述，保证内容质量，而非单纯继承上游。
3. **标准分镜提示词**：每幕产出一段 12–15 秒的标准分镜提示词，补齐"摄影分镜四要素"（景别 / 机位 / 运镜 / 视觉参考），作为 `image_prompt` 输出。

附带：校正 `docs/agents/short-drama-markdown-reimport.md` 中"8 秒 `default_duration` 切幕"与代码实际用 12–15 秒窗口的漂移。

## 决策（D）

**D-1 切分由机械装桶改为 AI 语义切分 + 结构保真护栏。**  
保留 `parse_short_drama_episode` 的确定性解析（提取块、拍、人物、道具、元信息），作为 AI 的输入与护栏基准。AI 在「优先 `[场景]` 块边界、其次拍边界、绝不劈断一句台词/一个动作行」的硬约束下，按叙事语义（说话人更替、地点切换、情绪/节奏转折）决定切点，而非按时长比例。

**D-2 内容由逐字转写改为 AI 优化为镜头可读描述，保留 `source_text` 原稿锚。**  
AI 把动作行改写为视觉化、可拍的 `scene_description`（show-don't-tell），理顺神态与动作的镜头归属；`source_text` 仍逐字保留原文，用于审计与回溯，不被 AI 改写覆盖。

**D-3 每幕输出标准分镜提示词（`image_prompt`），补齐摄影四要素；`video_prompt` 仍留待宫格确认后生成。**  
`image_prompt` 在 AI 分镜步骤产出，含场景、人物神态动作、景别、机位、运镜、视觉参考；`video_prompt`（K 帧之间的"怎么动"）仍 `None` 并 `pending_authoring=True`，因为需要宫格图确认后的 K 帧作参考。`image_prompt` 为**单段模板文本**，直接写入 `image_prompt.scene`，下游 `generate_grid` 读 `image_prompt.scene` 消费，图像生成链路与前端输入框均无需改动（见 R-3）。

**D-4 单次文本模型调用产出全部分镜。**  
一次结构化输出调用，喂入 `ParsedEpisode` 序列化体 + `referenced_asset_descriptions` 的资产外观，返回完整 scenes 数组（含每幕的 beat 归属、时长、地点、人物、道具、`scene_description`、`utterances`、`image_prompt`、`source_text`）。避免逐幕多次调用，控制成本与延迟。

**D-5 保真护栏：AI 输出须 100% 覆盖解析出的 beat；校验失败不回落机械切分。**  
校验 AI 返回的 scenes 对 `ParsedEpisode.beats` 是一一覆盖（不丢、不重、不劈断行）。校验失败则**带原因返修**（把拒绝原因回喂给模型，重试 `_PLAN_ATTEMPTS` 轮），穷尽仍不合格就报错终止——机械切分不再是 AI 失败的备用选项，AI 分镜是唯一路径；只有模型/基础设施异常导致流程无法运作时才允许失败。（修订：原文「校验失败则回落机械切分」已废弃，见修订记录。）

**D-6 引入文本模型即打破"reimport 不调文本供应商"契约，须同步修订契约（见 P/R）。**  
第一环从"零模型"变为"至少一次文本模型调用"，需更新 `docs/agents/short-drama-markdown-reimport.md` 的"重新导入不执行"清单与工具说明。仍**不调用图像/视频生成供应商、不读取视频供应商能力、不生成分镜图/视频**。

**D-7 时长窗口与 shortfall 语义不变。**  
AI 给出的 `duration_seconds` 仍须落在 12–15 秒；窗口钳制后总时长对不上时，回执 `duration_shortfall` 照常报警，不偷偷凑数。

**D-8 第一环对资产只「引用」，不「登记」。**  
资产的登记归资产步骤（方案 2 的「抽取 → 登记 → 描述 → 出图」）。AI 分镜只把已登记且有描述的资产喂给模型当上下文，让提示词按 `角色@[角色/锚点]` / `场景@[场景/锚点]` 语法引用它们。源稿里出现但资产库没有的名字，或资产已登记但缺描述时，本步骤阻断并提示先完成资产步骤；不静默建新条目，也不在分镜弹窗里补资产描述。

**D-9 弹窗文案按 D-3/D-6/D-8 重写，废弃「不写提示词」。**  
旧文案「AI 按剧情节奏规划分镜并登记资产；不写提示词，不生成图片或视频」来自早期转写方案（两个提示词输入框留空）的契约原文，与 D-3（第一环即产出 `image_prompt`）直接冲突：**现在写的是分镜提示词（`image_prompt`），留空的是视频提示词（`video_prompt`）**。文案只保留真实边界：写分镜提示词、引用资产、不新增资产、不生成图片/视频。

## 标准分镜提示词格式（D-3 落地形态）

**不改输入框布局**：`image_prompt` 就是单段模板文本（字符串），前端仍是现有的一个输入框；四要素不拆字段、不加分栏，而是**内嵌在文本里的固定语序**中。格式对齐现有宫格提示词的写法（`【镜头N】角色@[角色/锚点]…`）：

```
【镜头N】<景别+机位>，<运镜>。<画面主体：角色@[角色/神态·动作锚点]，…>。
<环境与道具：场景@[场景/锚点]，道具@[道具/锚点]，光影/氛围>。
<视觉参考：风格锚@[资产/参考]>
```

示例（对应 12–15 秒一幕，含三个镜头，镜头之间**换行分隔**、镜头内部三段**各占一行**，满足"下限 3"）：

```
【镜头1】中景，平视机位，缓推。
画面主体：沈昭@[沈昭/大礼仪式微张左手手掌心的极端特写：一枝断头金簪斜斜扎入掌肉]，沈婉@[沈婉/伪装娇怯态]跪坐一侧。
环境道具：暗殿@[暗殿/残并蒂莲屏风]，朱红漆案、铜醮香炉、喜烛火焰在鎏金雕面掩映出暖橙光斑。
视觉参考：风格锚@[短剧/暗殿对峙质感]

【镜头2】近景，俯拍，固定。
画面主体：沈昭@[沈昭/垂眸将金簪缓缓抽出，血珠滚落]。
环境道具：砖地@[砖地/酒液漫成细线流光]。
视觉参考：风格锚@[短剧/暗殿对峙质感]

【镜头3】特写，仰拍，缓拉。
画面主体：沈婉@[沈婉/指尖攥紧袖中银剪，眼底伪怯褪去转冷]。
环境道具：残并蒂莲屏风@[残并蒂莲屏风/半毁映出两人畸影]。
视觉参考：风格锚@[短剧/暗殿对峙质感]
```

换行规则：

- **镜头间**：每个 `【镜头N】` 起新行，多镜头竖向堆叠；
- **镜头内**：「景别+机位+运镜」「画面主体」「环境道具」「视觉参考」各起一行，便于阅读与整体替换；
- 保留 `角色@[角色/锚点]`、`场景@[场景/锚点]` 资产引用语法，与引用资产体系一致。

要点：

- **景别 / 机位 / 运镜**放在段首固定位置（`中景，平视机位，缓推。`），一眼可读、可整体替换；
- **人物神态动作**沿用现有 `角色@[角色/锚点]` 资产引用语法，与引用资产体系一致；
- **场景 / 道具 / 光影氛围**沿用 `场景@[场景/锚点]` 语法；
- **视觉参考**在 AI 分镜步骤只能是风格锚与已登记资产参考的文本引用（无生成帧）；像素级参考图仍由下游宫格 / 参考素材环节绑定。

存储上仍是 `image_prompt.scene` 一个字符串字段，`generate_grid` 与前端输入框零改动。

## 镜头数策略与丰满度要求（D-3 配套约束）

**核心原则：镜头数由内容语义决定，绝不为凑数制造无效切片；质量由丰满度校验保证，不由数字保证。**

**1. 镜头数服务于叙事分镜描述，与宫格格数解耦。**

- AI 按本幕戏剧内容自决**叙事镜头数**（image_prompt 里的 `【镜头N】` 块）：平静对视幕 2 个、常规 3、动作/对峙密集幕 4–6。指令明确给出典型区间（12–15 秒单幕常见 3–5），但**禁止为达成某个数字而编造填充镜头**——每个镜头必须承载独立的戏剧节拍（不同说话人、地点切换、情绪/动作转折）。
- **宫格的目的不是"一个镜头一格"，而是提取分镜内容的连续帧、保证视频一致性与连续性**：宫格是把分镜提示词渲染成一张多格联合图、再 `split_grids` 切分为连续 K 帧的工具，各格绑成视频首尾帧参考图。因此**宫格的格数 / 布局由视频对关键帧连续性与一致性的需求决定**（按该幕时长、视频后端 K 帧上限等选 2×2 / 1×N 等），**既不反向逼迫 image_prompt 凑镜头数，也不必与叙事镜头数硬性相等**。
- 若 image_prompt 的叙事镜头数与所选宫格格数不一致，由生成阶段按"逐格映射 / 语义重排 / 同镜多帧"处理，第一环无需为此改镜头数。
- 因此**取消"≥3 硬保底校验"**：那道校验会倒逼 AI 往平静幕里塞无效切片，与 D-1 语义切分精神相悖。

**2. 内容检查机制（已有 + 新增，两层护栏）。**

- **D-5 结构护栏（已有）**：保证 AI 输出 100% 覆盖解析出的 beat、不丢内容——它管"有没有漏"，不管"好不好"。
- **丰满度校验（本方案新增，质量闸）**：管"好不好"。这是保证最终产出"内容丰满、高质量"分镜的**唯一硬性手段**，必须强制通过，不达标即重生成。

**3. 丰满度 / 高质量要求（须在 authoring 指令里硬约束，仅靠四要素格式无法保证）：**

每个 `【镜头N】` 块必须同时满足：

1. **具体动作 + 具体神态/情绪**，且为该幕独有、非套话（show-don't-tell，禁止"沈昭站着""气氛紧张"这类空描述）；
2. **环境 / 光影 / 氛围**一句，须是可拍的细节（如"喜烛暖橙光斑落在鎏金雕面"），不泛泛形容词；
3. **至少引用一个已登记资产锚点**（`角色@` 或 `场景@` 或 `道具@`），否则无法落地成像；
4. **禁止模板化填充 / 禁止凑数切片**：不得用"一位人物""一处场景"等占位泛写，不得为凑镜头数而把一个完整动作硬拆成多个雷同镜头。

**4. 丰满度校验（硬性质量闸，必过）：**  
任一镜头块字符数低于阈值、或缺少动作动词、或零资产锚点、或与其他镜头语义高度重复（疑似凑数）→ 判不合格，触发**整体重生成**（非局部修补，避免越修越碎）。校验与 D-5 beat 覆盖护栏同级，均为「不合格即重跑直至通过；重试用尽后报错」。

> 说明：四要素固定语序只保证"结构齐全"，丰满度四条 + 硬性校验才保证"内容丰满高质量"。**最终目的是产出丰满、高质量的分镜内容，因此丰满度校验是本环节不可绕过的质量终点，不是可选项。** 叙事镜头数只服务于分镜内容描述、不替内容质量背书，也不决定宫格布局（宫格格数服务于视频连续帧提取）。

## 入口与弹窗文案

**入口**：分镜页右上角「AI 分镜」（本集尚无分镜）/「AI 重新分镜」（本集已有分镜）。不在剧本页，也不用资产步骤的按钮。

弹窗标题：`AI 分镜 · 第 N 集` / `AI 重新分镜 · 第 N 集`。

描述文案（`short_drama_ai_storyboard_desc`）按 D-3/D-6/D-8 固定为：

```
读取本集已保存的 Markdown 源稿，AI 按剧情节奏规划分镜，产出标准分镜提示词并引用已登记资产；不新增资产，不生成图片或视频。
```

三个短句对应三条边界，一个不多、一个不少：

| 断言 | 依据 |
|---|---|
| 产出标准分镜提示词 | D-3：`image_prompt` 在本环产出；`video_prompt` 仍空 |
| 引用已登记资产 | D-8：只引用，不建条目 |
| 不新增资产、不生成图片/视频 | D-8 / D-6 |

**不再出现的说法**：

- ~~「登记资产」~~ → 登记归资产步骤（D-8）；
- ~~「不写提示词」~~ → 与 D-3 冲突，且语义含糊（写的是分镜提示词，空的是视频提示词）。要表达"视频提示词仍留空"，就说「视频提示词留待宫格确认后编写」，不要用"不写提示词"这种把两个框一起否掉的写法。

弹窗内不再提供「同时用 AI 补齐缺描述资产」选项。缺描述资产由资产步骤处理；本步骤只读取已就绪资产。

## 问题 / 风险（P）

**P-1 非确定性。** AI 切分与提示词每次可能不同；reimport 本意是"从源稿重建"，若每次重切会变分镜。需在 R-1/R-2 决策缓存策略。

**P-2 成本与延迟。** 每次 reimport 至少一次模型调用；批量导入 N 集应并发调用，但每集仍是独立事务。

**P-3 与工厂 E12/E13/E14 机检的关系。** 机检在 ingest 落盘时跑，AI 优化在其后，不破坏已检源稿的事实质量；但 AI 改写 `scene_description` 后，源稿的"动作行密度"约束不再等同输出密度，需在护栏里仅校验覆盖，不反向约束。

**P-4 第二环「编写提示词」语义变化。** AI 分镜步骤已产出 `image_prompt`，原 `PromptAuthoringButton`（编写提示词）需重定义为"微调/覆盖分镜提示词 + 编写视频提示词"，避免与本步骤产出重复或冲突。

**P-5 视觉参考的早期性。** AI 分镜步骤没有生成帧，"视觉参考"只能是文本 / 资产引用，不能越俎代庖生成分镜图。

## 待拍板（R）

- **R-1（已更新）** 不再提供「快速切分」入口。AI 分镜是本步骤唯一路径；AI 校验失败时带原因返修，重试用尽后报错，不回落机械装桶。
- **R-2（已拍板）** 按 `source_revision` 缓存 AI 切分结果。缓存键 = `source_revision` + 优化强度选项（保守/标准/增强）；同源稿且同选项 reimport 时直接复用已存 scenes、跳过模型调用，保证分镜稳定不反复重切。源稿变更（revision 变）或选项变更时重算。提供「重新智能分镜」强制忽略缓存重跑。用户在分镜页手动改过 `scene_description`/提示词后，reimport 视为存在手动编辑，默认保留手动结果并提示，除非显式勾选覆盖。
- **R-3（已拍板）** `image_prompt` 为**单段模板文本**（即 `scene` 字符串本身）：不拆结构化字段、不改输入框布局，前端保持现有的一个输入框。四要素以固定语序内嵌在文本里（见"标准分镜提示词格式"），`generate_grid` 读 `image_prompt.scene` 不变，链路零改动。
- **R-4（已拍板）** 内容优化强度做成用户可选：弹窗提供「保守（仅视觉化/格式，不碰台词）/ 标准 / 增强（可微调台词节奏与动作分配）」三档，默认"标准"。

## 校验与不变量

- **保真**：AI 输出对 `ParsedEpisode.beats` 一一覆盖；`source_text` 逐字保留；覆盖失败时带原因返修，重试用尽后报错（D-5）。
- **时长**：每幕 12–15 秒；`duration_shortfall` 照常回执。
- **资产引用**：第一环只引用已登记且有描述的资产，不新增条目，不补资产描述。`referenced_asset_names` / `referenced_asset_descriptions` 只用于给模型喂名字与外观。
- **契约**：不读视频供应商能力、不生成分镜图/视频（D-6/D-7）。
- **测试**：新增 AI 结构化输出 schema 校验、beat 覆盖护栏、返修失败报错测试、分镜提示词固定语序格式校验（段首景别 / 机位 / 运镜、`@[资产/锚点]` 引用合法、含视觉参考段）、**镜头数语义合理性校验（禁止明显凑数切片：同幕镜头语义高度重复判不合格）**与**丰满度校验（每镜头块含动作动词 + 至少一资产锚点 + 字符数阈值 + 非模板泛写）**；旧 `_split_by_story_window` 单测可作为历史工具函数覆盖保留。

## 验收
