# 3. AI 分镜方案

> **已被 `10. 机械分镜与分镜提示词分步方案.md` 取代。** 分镜结构改为代码确定性生成（不调用模型），`image_prompt` 拆成独立的下一步；本文保留作历史背景与存量数据口径。历史 AI 分镜项目仍可读，但新分镜不再按本文生成。

> 唯一链路：工厂源稿 → 资产 → AI 分镜（唯一动态提示词）→ 参考素材 / K 帧确认 → reference/r2v 视频。

## 一、目标

AI 分镜把工厂 Markdown 源稿转换为派生视觉制作状态。每个分镜段同时确定剧情边界、时长、出场资产、逐字口播、原稿锚点和唯一动态提示词 `image_prompt`。

`image_prompt` 同时服务两个下游：

1. 参考素材阶段从中抽取可见转折，生成 K0…Kn。
2. 视频阶段把全文与实际 `reference_images` 一起发送给 reference/r2v 模型。

系统不再生成第二份 `video_prompt`，也不允许在 K 帧确认后用 AI 改写提示词。

## 二、输入与真相源

| 输入 | 来源 | 用途 |
| --- | --- | --- |
| 本集正文 | `source/short_drama/episodes/episode_NN.md` | 剧情、动作、台词与原稿锚点 |
| 分集规划 | `source/short_drama/episode-plan/episode_NN.plan.md` | 钩子、情绪流变、时长与场景约束 |
| 系列工件 | 人物圣经、全剧大纲、连续性台账 | 身份、关系和跨集连续性 |
| 资产登记 | 项目角色、场景、道具表 | 合法 token、外形、来路与资产图 |
| 项目设置 | 画面比例、视觉风格、语言 | 视觉表达边界 |

工厂 Markdown 是剧情与对白的唯一真相源。`scripts/episode_N.json` 只保存派生视觉制作状态，不反向覆盖源稿。

## 三、分镜输出

每个 `scenes[]` 条目至少包含：

- `scene_id`：稳定分镜 ID。
- `duration_seconds`：该分镜段时长。
- `scene_description`：视觉改编摘要。
- `characters_in_scene`、`scenes`、`props`：本镜实际出场资产。
- `utterances`：逐字台词与画外音，顺序即发声顺序。
- `source_text`：源稿逐字锚点。
- `image_prompt`：唯一动态分镜提示词。

历史 `video_prompt` 与 `generated_assets.video_prompt_basis` 只为读取旧项目保留。新分镜不生成、不更新、不依赖这两个字段。

## 四、动态提示词格式

`image_prompt.scene` 是连续多镜头文本。每块以 `【镜头N｜景别】` 开头，随后写连续时间段和四层制作信息：

```text
【镜头1｜中景】0-4秒：主体动态：林清@[林清]抬眼、攥紧信纸，呼吸顿住；空间调度：平视机位缓推，她从窗边转向门口，右手始终压住桌沿；画面与光线：窗外雨痕逆光发蓝，桌面暖灯压住半边脸；声音：雨点击窗、纸张收紧的脆响。
```

硬约束：

1. 第一镜从 0 秒开始，后一镜起点等于前一镜终点，末镜终点等于 `duration_seconds`。
2. 每块都包含「主体动态」「空间调度」「画面与光线」「声音」。
3. 主体动态写触发、过程、可见结果和表演细节；每次切镜都要改变信息、关系或压力。
4. 空间调度写机位、运镜、人物走位、视线、屏幕方向和持物关系。
5. 画面与光线写可观察的构图、光源、色温、材质和环境变化。
6. 声音只写环境声、动作声和已知声源；台词原句只保存在 `utterances`。
7. 资产 token 只能引用本镜出场清单中的登记名，首次出现使用实名与 `@[登记名]`。
8. 提示词先于 K 帧生成，正文不得出现 `K0`、`K1`、首帧图或尾帧图等前向引用。
9. 不写 `Reference_Images`、模型参数、画面比例、资产编号和请求包装字段。

## 五、质量闸

AI 分镜与显式提示词重写共用同一套确定性校验：

- beat 连续覆盖且不重不漏。
- 各幕时长之和符合源稿目标时长。
- 分镜 ID、时长、口播与原稿锚点保持稳定。
- 资产 token 已登记且属于本镜出场清单。
- 镜头编号连续，景别、机位、运镜和正文丰满度合格。
- 时间轴连续完整，四层制作信息齐全。
- 台词原句不进入 `image_prompt`，K 帧编号不进入上游提示词。
- 相邻镜头与相邻分镜的人物位置、视线、持物、轴线和主光连续；换场或跳时必须写明确切点。
- 碎片空间单独成镜，不把其他时空的动作和道具搬入当前主空间。

校验失败把具体原因回喂模型。全局结构失败时重做整批；单个 scene 失败时只返修该 scene。返修耗尽则整批拒绝，不写半成品。

## 六、重新分镜与时效

- 整体重新分镜替换本集全部派生分镜。
- 部分重新分镜只替换点名 scene，未选 scene 的文本和媒体状态保持原样。
- `image_prompt` 变化后，该分镜的参考素材与视频按 Artifact Manifest 判为 stale。
- 参考素材确认、取消确认或替换只影响视频时效，不反向改写 `image_prompt`。
- 已有媒体时必须先确认影响；系统不静默删除付费产物。

## 七、提示词编写入口

`generate_episode_script` 只接受 `fields=["image_prompt"]`。省略 `fields` 时同样只处理 `image_prompt`。

该入口用于补齐或显式重写动态提示词，不重切分镜、不改时长、不改 `utterances`、`source_text` 或资产清单。显式重写必须通过覆盖确认，并明确告知参考素材与视频会过期。

## 八、验收标准

1. 新生成分镜不需要独立视频提示词即可继续到参考素材和视频。
2. 每条 `image_prompt` 连续覆盖完整时长并具备四层制作信息。
3. 任何 `K{n}` 前向引用、台词原句、未登记 token 或跨镜连续性硬错误都在落盘前被拒绝。
4. 修改 `image_prompt` 会使参考素材与视频过期；修改 confirmed 参考素材只使视频过期。
5. 历史 `video_prompt` 可读取，但不会出现在编写入口、工作流、准入、请求组装或时效判断中。
