## 术语

| 术语      | 指什么                                        | 落点                                    |
| ------- | ------------------------------------------ | ------------------------------------- |
| 分镜提示词   | 第一步产物，整分镜的画面意图（导语 + 镜头序列），**唯一真相源**        | `image_prompt.scene`                  |
| 逐格镜头文本  | 第二步出图时按规格从分镜提示词解析出的 N 段文本，为本次出图留证，**不可编辑** | `ShotGrid.cells[].prompt`             |
| 宫格图     | 一张 N×M 的关键帧联合图                             | `ShotGrid.composite_path`             |
| 系统指令    | 网格排版 / 风格 / 参考图声明 / 纯净性约束，不由作者写            | 渲染时拼装                                 |
| 视频提示词   | **本步收尾产物**（补充），喂给视频模型的文本；结构化或文本形态，可编辑      | 正式脚本 `video_prompt`                   |
| 视频提示词依据 | 写这条视频提示词时所用宫格的指纹，用于「宫格变了要重写」               | `generated_assets.video_prompt_basis` |

## 背景

「生成参考素材」目前是分镜详情里的一个**内联小按钮**（`ReferenceMaterialsSection.tsx:128`），点了  
直接 `enqueueShotGrid`，规格硬编码 3×3、提示词由后端现场拼一段 contact-sheet 指令  
（`generation_tasks.py:1617-1626`）。`saveShotGrid`（`api.ts:3861`）与 i18n key `shot_grid_layout`  
已存在但**零调用方**——本方案只把它们用来存规格（2×2 / 2×3 / 3×3），不存任何文本。

新需求分两处：

1. **制作进度新增「参考素材」一行**，排在「分镜图 / 宫格」与「视频」之间。这一步有两条路：  
   **整集并行制作**（批量，自动生成）与**单个分镜制作**（点「配置参考素材 / 生成参考素材」按钮开确认弹窗）。
2. **两条路口径不同**：单分镜走**确认弹窗**（宫格规格选择 + 提示词输入框 + AI 生成），作者可手填  
   宫格提示词、可改规格，确定后落库入队（**D-1 / D-3**）；整集批量**不弹窗、不手填**，规格统一 2×2、  
   逐格文本从 `image_prompt.scene` 现解析（**D-1 批量分支**）。排版指令由系统按规格拼装（**D-2**）。

同时给了一份「宫格生成规范」：【基础设置】+【风格与角色锚点】+【逐格镜头描述】+【纯净性约束】。

> **补充（第十一节）**：这一步不只要出宫格图，还要把**视频提示词**一起产出来。视频提示词已有产线
>   
> （`prompt_authoring` 的 `fields=["video_prompt"]`），但今天它是分镜详情下方一个孤立按钮，输入里
>   
> 既没有分镜提示词也没有宫格，工作流与批量也不认它的存在——后半段见 **十一**。

## 一、宫格提示词规范可行性分析

### 判定表

| 规范条目                      | 判定               | 说明                                                                    |
| ------------------------- | ---------------- | --------------------------------------------------------------------- |
| 提示词必须是四段式结构               | ✅ **采纳**         | 与仓库已有的 `storyboard/grid.md`（布局要求 / 帧链节奏 / 各格内容 / avoid）几乎同构，不是新发明     |
| 必须有显式网格排版指令（行列、阅读顺序）      | ✅ **采纳**         | 现状已有（`contact sheet with exactly R rows and C columns`），但**内容要重写**，见下 |
| 每格 = 一个时间节拍 / 一个动作        | ✅ **采纳**         | 与 0098 D-A「一格一镜」一致；现状"每格是同一镜头的时间推进"正是被推翻的部分                           |
| 明确的景别变化（全景→中景→特写）         | ✅ **采纳**         | 现状 `cells[].prompt` 没有景别槽位，需在解析与拼装里带上                                 |
| 风格与角色锚点                   | ⚠️ **采纳但改写**     | 见 **P4**：不能复述资产外观，否则与参考图冲突                                            |
| 纯净性约束（无文字 / 序号 / 气泡 / 箭头） | ✅ **采纳**         | 复用 `storyboard/image/avoid` 与 `storyboard/grid/avoid`                 |
| "画面比例 16:9 / 9:16（双朝向）" | ✅ **采纳** | 比例由项目画布设置（canvas_ratio）驱动，可横（16:9）可竖（9:16）；提示词里不写死任何比例，始终由系统按规格拼装（见 **P1 / D-6**） |
| "各格之间用黑色细边框分隔"            | ❌ **否决**         | 见 **P2**：下游按等分裁剪，边框会污染每一格与整张分镜图                                       |
| 网格排版指令写进提示词正文             | ❌ **否决（改为系统拼装）** | 见 **P3**：正文里出现行列数，规格一改就自相矛盾                                           |

### P1（关键）比例由项目画布设置驱动，支持 16:9 与 9:16 双朝向

- 分镜宫格的画布比例跟随项目视频比例：横屏项目为 **16:9**，竖屏（短剧）为 **9:16**  
  （`lib/artifacts/video_visual_provenance.py:20` 的 `resolve_video_aspect_ratio` 直接返回  
  `project.aspect_ratio`；`lib/script/grid/layout.py` 的 `video_aspect_ratio_of` /  
  `grid_aspect_ratio_for` 按该值取朝向）。**两种朝向都受支持，比例绝不在提示词文本里写死。**
- 整图比例由 `(rows, cols, canvas_ratio)` 算出（D-6）：方形档（2×2、3×3）整图即视频比例本身，  
  单格比例因此也等于视频比例；非方形档（2×3）整图取几何自洽的比例，单格仍通过切分时的  
  center-crop 对齐到视频比例，不变形（见 **D-6 / R4**）。
- **结论**：比例是系统字段，由项目画布设置 + 规格共同决定；提示词模板只接收算好的  
  `grid_aspect_ratio` / `panel_aspect_ratio` 槽位（D-6）。**「写死 16:9 并忽略项目朝向」才是被否决的——  
  16:9 与 9:16 都要实现（D-6 / R4）。**

### P2（致命）黑细边框会污染下游

`POST /shot-grids/{grid_id}/confirm`（`shot_grids.py:178-197`）按 `width/cols`、`height/rows` **等分  
裁剪**，并把**整张宫格图**绑成 `storyboard_image`、各格绑成视频首尾帧与参考图。有边框 → 每格都带  
黑边、正式分镜图带网格线、视频首帧带黑边。与 0098 D3「无边框无间隙」一致：**必须无边框**。  
规范里这一条要删掉。

### P3（结构性）网格排版指令不能落在人能写的地方

一旦排版指令（「2 列 x 2 行共 4 格」）出现在任何**可编辑文本**里，规格一改就必然与正文打架：改规格的人  
不会记得回去改那句话。所以**排版指令、整图 / 单格比例、纯净性约束始终由系统按 `rows/cols` 拼装**，不进  
弹窗的「宫格提示词」输入框——这是避 P3 的根本做法。

弹窗的「宫格提示词」只承载**逐格画面意图**（四段式里的【逐格镜头描述】），不承载排版 / 比例 / 约束；  
作者可手填（**D-3**），也可留空退回系统从 `image_prompt.scene` 现解析（**D-1 批量分支**）。scene 里  
同样不允许写排版指令——那是分镜意图，不是出图参数。

### P4 角色锚点不要复述资产外观

角色 / 场景 / 道具资产**图**已随请求发出，并有 `Reference_Images` 声明行与 `@[名称] → 图N` 编号  
（`lib/prompts/reference_image_numbering.py`）。再让 AI 抄一遍"素色窄袖短褐、深色长裤"，一旦与资产图  
不一致，模型会在"图"与"文"之间摇摆，反而破坏一致性。**锚点段只承载跨格恒定约束**（同一套服装、  
同一光线方向、同一时段、不换装），资产外观交给参考图；作者侧的跨镜头环境基线写在 scene 导语段，  
由系统拼进锚点位置。

## 二、决定

**D-1 单分镜走确认弹窗、整集批量不弹窗，但生成时同一套「prompt 优先、scene 兜底」逻辑。**

| 路径  | 入口                                                            | 规格                                       | 逐格镜头文本从哪来                                                          |
| --- | ------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------ |
| 单分镜 | 分镜详情「参考素材」区「配置参考素材」→ 打开 `ShotGridDialog` 确认        | 弹窗内 ToggleGroup（2×2 / 2×3 / 3×3，默认 2×2） | **弹窗里手填的 `ShotGrid.prompt` 优先**；留空则生成时回退解析 `image_prompt.scene` |
| 整集  | 制作进度「参考素材」行 → 批量                                        | 统一 2×2，不由人定                              | **无 prompt，生成时一律解析 `image_prompt.scene`**                          |

单分镜的弹窗（`ShotGridDialog.tsx` + `shot-grid-dialog-store.ts`，从 `63daec9` 还原）让作者  
选规格、写宫格提示词（可点「AI 生成」由 `POST /author-prompt` 现写），确定后 `saveShotGrid`  
落库（`prompt` / `rows` / `cols` / `scene_revision`）再 `enqueueShotGrid` 入队。整集批量没有  
任何提示词界面，规格与文本都由系统定，两条路在「生成时读 prompt、空则解析 scene」这一层汇合  
（**D-3 / D-7**）。

`ReferenceMaterialsSection` 保留「配置参考素材」按钮（开弹窗）、结果展示、轮询与「确认参考素材」。

**D-2 四段式落地为「系统拼装 +（可选）作者手填的逐格段」，排版 / 比例 / 纯净性约束永远系统拼。**

| 规范段落      | 来源                                                                                | 谁写                  |
| --------- | --------------------------------------------------------------------------------- | ------------------- |
| 【基础设置】    | `rows/cols` + 项目画布比例 → 整图比例 / 单格比例 / 行列数 / 阅读序                                  | 系统                  |
| 【风格与角色锚点】 | 项目风格块（`shared/media_style`）+ 参考图声明（图N）+ scene 导语段                               | 系统 + 作者（导语写在 scene） |
| 【逐格镜头描述】  | **单分镜弹窗手填 `prompt` 时以 `prompt` 为准**；无 `prompt`（批量或留空）则从 `image_prompt.scene` 现解析（含景别） | 作者（可选）/ 系统        |
| 【纯净性约束】   | `storyboard/grid/avoid` 类模板                                                         | 系统                  |

排版指令、整图 / 单格比例、纯净性约束**始终由系统按规格拼装**，不进任何可编辑文本——这是避 **P3**（规格  
一改，可编辑文本里的行列数就自相矛盾）的关键。作者只在弹窗的「宫格提示词」里写逐格画面意图，且可留空  
退回纯系统解析；要改系统解析结果，要么在弹窗里写 `prompt`，要么改 scene 重出（**D-3**）。

**D-3 单分镜弹窗手填的 `ShotGrid.prompt` 优先，空则回退 `image_prompt.scene`。** 这是还原 `63daec9`  
后采用的**混合口径**：单分镜弹窗把作者写的宫格提示词存进 `ShotGrid.prompt`（连同 `scene_revision`  
指纹，用于视频提示词时效比对，见 **D-15 / D-18**）；出图时 `generate_shot_grid` 先读 `grid.prompt`，  
为空才解析 `image_prompt.scene`（批量路径从不设 `prompt`，自然走 scene 兜底，不崩）。解析出的 N 段  
文本回填进 `cells[].prompt`（景别进 `continuity_notes`），只作**本次出图留证**与 `<keyframes>` 素材，  
不参与再编辑。与 0098 D-E「scene 唯一真相源」的关系变为：**scene 仍是批量与兜底真相源，单分镜作者可在  
弹窗里用 `prompt` 覆盖一次**。

**D-4 `saveShotGrid`（PUT ""）存规格 + prompt，且不再无条件重置。** 现状 PUT 无条件把 `status` 打回  
`draft`、清 `composite_path`（`shot_grids.py:108-112`）；改为：**仅当 `rows/cols` 与库中不同才重置**，  
相同则一个字段都不动；`status == "confirmed"` 一律拒绝改规格（0098 已要求）。请求体 `SaveShotGridRequest`  
包含 `prompt`（单分镜弹窗手填，可空）、`rows`、`cols`，默认规格 3×3 → **2×2**；`prompt` 变化时一并  
落库（批量路径不调此接口，直接走 generate）。

**D-5 还原 `POST /author-prompt`，返回即落草稿。** 单分镜弹窗里有「AI 生成」按钮，需要服务端把一个  
分镜的规格 / 资产 / 既有 scene 拼成一段宫格提示词回填进输入框供人改，因此保留  
`author_shot_grid_prompt` 同步端点（从 `63daec9` 还原）。返回的 `prompt` 由前端立刻调  
`PUT /shot-grids/draft` 写回 `ShotGrid.prompt`——草稿只写逐格文本，不动 `status` / `composite_path` /  
`cells` 留证 / `scene_revision`；关窗（取消 / Esc / ×）也走同一入口。这样既不会「AI 生成了但关窗就没了」，  
也不会像「生成即提交」那样留下半截生成状态；只有点「确定」才走 `saveShotGrid` + `generateShotGrid`。

**D-6 整图比例由 `(rows, cols, canvas_ratio)` 算出。** 复用 `lib/script/grid/layout.py` 的  
`grid_aspect_ratio_for`，`canvas_ratio` 即项目画布比例（16:9 或 9:16，由 `resolve_video_aspect_ratio`  
取）；方形档取视频比例本身，非方形档的比例取值见 **R4**（已定）。单格比例 `panel_aspect_ratio_for`  
一并写进指令（多宫格模板已有这两个槽位，单分镜宫格此前缺失）。`ShotGrid` 记录须冻结一份  
`video_aspect_ratio`（= 生图时使用的 `canvas_ratio`），供确认切分步骤 center-crop 到该比例，保证  
16:9 / 9:16 单格都不变形（与 `splitter.split_grid_image` 同口径，见 P1 / R4）。

**D-7 `POST /generate` 守卫改为「prompt 或 scene 能解析出至少一格」**，替换现在的「至少一格  
`cells[].prompt` 非空」（`shot_grids.py:126`）——`cells` 是出图之后才写的产物，不能当前置条件；  
单分镜有 `prompt` 用 `prompt`，无 `prompt`（批量或留空）用 `parse_scene_shots(scene)` 兜底。

**D-8 制作进度新增「参考素材」行，step id `shot_grid`，插在 `storyboard` 与 `video` 之间。**

位置由 `lib/workflow/workflow_rules.py:29` 的 `_STEP_IDS` 决定，不在前端拼：

```python
_STEP_IDS = (
    ...,
    "asset_sheets",
    "script_structure",
    "storyboard",
    "shot_grid",  # 新增
    "video_prompt",  # 新增，见 D-13（本步收尾的视频提示词）
    "video",
    "edit",
)
```

- 适用条件与 `storyboard` 相同（`generation_mode == "storyboard"` 才适用，见 `_build_rule`）；
- 行标题复用已有文案 `dashboard:shot_reference_materials`（「参考素材」，即分镜详情那个区标题），  
  不新造词；
- 截图里没有「旁白配音」行，说明短剧这集不是 `narration + storyboard`，插入位置无歧义。

**D-9 整集并行走已有的批量形态，不新造接口。** 复用 `StoryboardBatchDialog` 与  
`server/routers/storyboard_batches.py`：给 `StoryboardBatchKind` 增加 `"shot_grids"`，后端补一份  
`shot_grids` 的 preview / submit 规划（照 `load_storyboard_image_batch_plan` 的写法），端点仍是  
`POST /projects/{p}/episodes/{e}/shot-grids/batch[/preview]` 这一族。目标是**本集缺失参考素材的每一个  
分镜**，规格统一 2×2，**不弹提示词弹窗**。并行不新增机制：批量建 N 个 `shot_grid` 任务，实际并行度  
由现有生成队列决定。

**D-10「参考素材」行的可用口径独立于分镜图。** confirm 会把宫格整图同时登记为 `storyboard_image`  
（`shot_grids.py:225`），若复用该产物集合，两行会同时亮、重复计同一份东西。本行按  
**`ShotGridManager` 记录 + `image_basis` 时效比对**判定，见 **R10**。

**D-11 重出宫格不碰 scene，也不做「旧格合并」。** 改规格或重新生成时，`cells` 整体按新规格重解析  
覆盖：旧格的行列与新规格对不上，合并只会产出一张自相矛盾的图。scene 不动，所以重出永远可复现、可  
回退（**D-3**）。

## 三、单分镜交互（确认弹窗）

分镜详情「参考素材」区点「配置参考素材 / 生成参考素材」打开 `ShotGridDialog`：宫格规格 ToggleGroup  
（2×2 / 2×3 / 3×3）+ 提示词 Textarea +「AI 生成」+「确定 / 取消」。弹窗让作者**选规格、写宫格提示词**  
（可留空走 scene 兜底），确定后才落库入队。

```
分镜详情 · 参考素材
  [ 配置参考素材 ]                      ← 打开 ShotGridDialog

┌─ 生成参考素材 ───────────────────────────┐
│ 宫格规格    ◉ 2×2   ○ 2×3   ○ 3×3        │
│ 宫格提示词                                  │
│ ┌──────────────────────────────────────┐ │
│ │ 第1格（全景）：…                       │ │
│ │ 第2格（近景）：…                       │ │
│ └──────────────────────────────────────┘ │
│ [ AI 生成 ]                              │
│ 手写格数需与规格一致（N 格 vs rows×cols）    │
│                         [ 取消 ] [ 确定 ] │
└──────────────────────────────────────────┘
        ↓ 确定 → saveShotGrid(prompt,rows,cols) → enqueueShotGrid

┌────┬────┐
│ K0 │ K1 │     已生成时的结果区，与现状一致
├────┼────┤
│ K2 │ K3 │
└────┴────┘
已确认                      [ 重新生成 ]   [ 确认参考素材 ]
```

- **弹窗确定**：先 `saveShotGrid({ prompt, rows, cols })` 落库（含 `scene_revision` 指纹），再  
  `enqueueShotGrid` 入队。宫格没有「未生成时的草稿态」展示，但 `prompt` 随 `rows/cols` 一起预存  
  （**D-3 / D-4**）——这是还原 `63daec9` 后的形态，与「批量无 prompt」并存。
- **AI 生成**：点按钮调 `POST /author-prompt`，把规格 / 资产 / 既有 scene 拼成一段宫格提示词回填进  
  Textarea，作者可继续改（**D-5**）。
- **校验**：手写格数（解析 `第N格（景别）`）需与 `rows×cols` 一致，不一致提示「超出 / 不足」再确定  
  （`ShotGridDialog` 内建校验）。
- **改规格**：仅在 `status != "confirmed"` 时可在弹窗内改；confirmed 的宫格锁规格（**D-4**），要换  
  规格得先取消确认——与 0098 同口径。
- **不展示参考资产**：资产已在分镜详情的「引用」区陈述，结果区再列一遍会让人以为可以增改。
- **要改画面**：把提示词写进弹窗的宫格提示词，或改分镜提示词（scene）→ 重出宫格。弹窗 `prompt`

## 十一、视频提示词生成（本次补充）

### 11.1 补的是哪一段

原方案把「这个分镜有没有参考素材」做成看得见、改得动的一步，但没有回答**参考素材之后、视频之前  
那段文本从哪来**。视频提示词（`video_prompt`）今天确实存在，却是分镜详情下方「视频提示词」区里  
一个孤立按钮（`ShotDetail.tsx:626-637`），还要先满足 `hasConfirmedMaterials` 才显示——门控只在  
UI 生效，工作流与批量都不知道有这回事。

结果是一段断裂：参考素材行变绿 → 下一步直接报「视频缺失」→ 点批量，视频批量又把没有  
`video_prompt` 的分镜按 `MISSING_PROMPT` 全部跳过（`storyboard_batch.py:769`）。

### 11.2 判定表

| 现状条目                                                    | 判定            | 说明                                                                                                                                           |
| ------------------------------------------------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 视频提示词已有产线（`prompt_authoring`，`fields=["video_prompt"]`） | ✅ **复用**      | 不新建文本模型通道、不新建计费口径；本步只补输入与入口归位                                                                                                                |
| 字段指令要求「必须基于已确认的参考素材与分镜提示词编写」                            | ❌ **改（P5）**   | 这句只写在指令里（`script_generator.py:238-241`）；drama / narration 的输入块只有 `scene_description` / `utterances` / 原文锚，**既没有 `image_prompt.scene`，也没有宫格** |
| 入口藏在「视频提示词」区、由 `hasConfirmedMaterials` 控制显隐             | ⚠️ **归位（P6）** | 单分镜还能翻到，整集没有任何批次入口                                                                                                                           |
| 空 `video_prompt` 在视频批量里判 `MISSING_PROMPT`               | ✅ **保留**      | 判定本身是对的；缺的是它前面那一步没人负责                                                                                                                        |
| 渲染层已按宫格切图追加 `K0–K(n-1)` 声明                              | ✅ **复用**      | `prompt_utils.py:285-300`，按 `generated_assets.shot_grid.cell_paths` 判                                                                        |
| 正文里的 `K{n}` 引用没有边界校验                                    | ❌ **新增（P7）**  | 写 `K4` 而宫格只有 4 格（K0–K3）时，声明与实际下发的图对不上                                                                                                        |

### 11.3 三个问题

**P5（结构性）模型被要求「基于参考素材与分镜提示词」，输入里两样都没有。**

- `_visual_field_instruction` 对 video 分支写的是「必须基于已确认的参考素材与分镜提示词编写」  
  （`script_generator.py:238-241`），但 drama 的输入由 `render_drama_content_for_prompt_authoring`  
  （`prompt_builders_script.py:163`）渲染，只有 `scene_description`、`utterances`、`source_text`  
  与资产名——`image_prompt.scene` 不在里面；narration 同理，只有 `novel_text` 与资产。
- 参考素材更不在：提示词编写是**纯文本**通道（`TextGenerator`），既看不到宫格图，也看不到逐格文本。
- 后果：视频提示词实际是「第二遍写分镜」。动作从原文再推一遍，与已出的 K 帧各写各的——宫格越准，  
  两边越容易打架；K 帧的景别推进、姿态、光位对 `action` 没有任何约束。

**P6（结构性）入口在页面下半部，工作流与批量都不认。**

- 单分镜：按钮在「视频提示词」区，用户确认完宫格不会自然往下滚；且只有 confirmed 后出现，没有  
  「待生成」的可见状态。
- 整集：`AUTHOR_PROMPTS` 的默认字段是 `image_prompt`（`prompt_authoring_scope.py:16-21`），整集的  
  「补缺」不会补视频提示词；视频批量又因 `MISSING_PROMPT` 跳过它们。
- 工作流：`artifacts` 里没有视频提示词的位置，`shot_grid` 一完成就直接走 `GENERATE_VIDEOS`  
  （`workflow_state.py:1949-1968`）。

**P7 K 引用没有边界。**

- `render_storyboard_video_prompt` 按当前 cells 数追加声明，正文里的 `K{n}` 却没人校验  
  `n < len(cells)`；越界不会在保存时报错，只会在视频请求里变成「声明了不存在的参考图」——  
  与 4. 视频提示词生成方案 **P3** 同一性质：错在计费边缘。
- 2×3 / 3×3 下很容易发生：用户把上一版 9 格宫格的提示词粘到 4 格宫格上，或 AI 按旧宫格写作。


### 11.4 决定

**D-12 视频提示词是本步的收尾产物，正文仍只存正式脚本。**

- `ShotGrid` **不存**视频提示词正文：`cells[]` 只是「本次出图的逐格留证」，属一次性参数；视频  
  提示词是长期内容，与 `image_prompt` 同级，归正式脚本。存两份必然漂移。
- 「依据」挂在条目的 `generated_assets.video_prompt_basis`，因为它描述的是「脚本里这份文本是按哪次  
  宫格写的」，而不是宫格自己的属性。

**D-13 独立成 step `video_prompt`，插在 `shot_grid` 与 `video` 之间。**（并入参考素材行的备选已关闭）

- 一行一产物集合：`_step_done`、`mediaStatus`、`StaleArtifacts`、「重新生成全部 N 件」都是按单产物  
  写的。宫格图与提示词塞进同一行，「共 7 个，已生成 3 个」会同时表示两种东西，「重新生成全部」也  
  指代不清。
- 两种批次不同：宫格走 `shot_grid` 任务队列、逐张报价；视频提示词走 `prompt_authoring`，没有逐张  
  单价。用户点「批量生成」时该期待什么，取决于行是哪一行。

**D-14 不自动：宫格确认之后再显式触发。**

- `POST /{grid_id}/confirm` 只做原来的事（切格、登记、绑 `generated_assets.shot_grid`），  
  **不顺手入队文本任务**：确认是「认下这批图」，不是「再花一次文本模型的钱」；且视频提示词有覆盖  
  语义（`overwrite_revision`），自动跑会盖掉手改。
- 单分镜：`ReferenceMaterialsSection` 在 confirmed 后显示收尾条与「生成视频提示词」，打开**既有**  
  `PromptAuthoringDialog`（`scope="current"`、`fields=["video_prompt"]`、`lockFields`、默认重写）。
- 整集：工作流行下一步 + 批量，见 **D-19 / D-20**。

**D-15 输入补两块：分镜提示词 + 逐格镜头序列。**

### 11.6 输出标准（视频提示词正文，硬约束）

这一步的产出不是「再写一遍分镜」，而是**把已出的 K 帧接成一段动作**。下面六条是验收口径，任一条不满足  
即判不合格产出——重写，不降级、不兜底：

| #  | 标准                                                                                                       | 判定方式                                     |
| -- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| S1 | **与 K 帧同源**：`action` 的时间段必须覆盖 K0→Kn 的整条节拍，不新增、不跳过、不换序                                                    | 人工核对逐段；AI 自检项写进字段指令                      |
| S2 | **写「怎么动」，不复述静帧**：只写段与段之间的位移、发力、形变、因果与镜头推进；每格已写死的姿态 / 表情 / 服装 / 光位不重复                                     | 正文出现大段静态外观复述即不合格                         |
| S3 | **只引用存在的 K**：正文出现的 `K{n}` 必须 `n < 格数`；越界由 `keyframe_reference_problems` 在写回时拒（**D-17**），视频准入再拦一次         | 4 格写 `K4` → 422                          |
| S4 | **台词不进 `action`**：drama 的口播在 `utterances`；narration / ad 的台词只进 `dialogue`，`action` 不复述                   | 与 4. 方案的 P3 同口径                          |
| S5 | **不写系统参数**：不写 BGM、画面比例、时长、模型参数，也不写 `Voice_Profiles` / `Dialogue` / `Avoid` 这些包装段——它们由渲染层追加，写了就会与真实请求叠成两份 | `render_storyboard_video_prompt` 的尾段与配置项 |
| S6 | **时间段时间格式**：`0-3秒：…`、`3-6秒：…`，覆盖完整时长且不重叠（沿用 `shared/action_writing_guide`，不另立一套）                         | 正则可析出连续、无缝、无重叠的段                         |

写法（S1 / S2 / S6 的正例，同时也是 `<keyframes>` 的消费方式；8 秒分镜、2×2 四格）：

```
0-2秒：铁镐入缝的同一刻起手，手腕先沉后拧，刃口在砖缝里压实（对 K0→K1）；
2-4秒：肩背随拧转带起上身，咬肌绷紧、下颌前递（K1→K2）；
4-6秒：右腿蹬直、身体整体上抬，井壁泥层在这一下松动，泥水被带出画面（K2→K3）；
6-8秒：泥浆从上沿倾泻砸落，人留在画面右侧，不回到中央（K3 的余势）。
```

- 段数与段长跟 K 帧节拍走，**不按「每格一句」机械铺开**：4 格 / 8 秒就是四段 2 秒；2 格 / 6 秒是  
  两段 3 秒，不是硬切成四段；
- `K0→K1` 这类标注只是给动作定锚，可以省略；**一旦写就必须真实存在**（S3），不能凭空补一帧；
- `camera_motion` 取 `CameraMotion` 词表原文（`Push In` / `Pull Out` / `Pan Left` …），且与 K 帧的  
  景别变化同向（K 在推近就不要写 `Pull Out`），冲突时以 K 帧为准；
- `ambiance_audio` 只写画内音，声音随动作节点出现，不写配乐与情绪形容词。

### 11.7 最终产物长什么样（一个分镜的完整样例）

以 drama 的 `ep-01 / shot-05`（`duration_seconds = 8`、宫格 2×2、已确认）为例。同一条视频提示词在链路上  
有三种视图，**不是三份数据**：

**① 落盘形态**——正式脚本里的 `video_prompt`，drama 走 `DramaVideoPrompt`（无 `dialogue`）：

```json
{
  "action": "0-2秒：铁镐入缝的同一刻起手，手腕先沉后拧，刃口在砖缝里压实；2-4秒：肩背随拧转带起上身，咬肌绷紧、下颌前递；4-6秒：右腿蹬直、身体整体上抬，井壁泥层在这一下松动，泥水被带出画面；6-8秒：泥浆从上沿倾泻砸落，人留在画面右侧，不回到中央。",
  "camera_motion": "Push In",
  "ambiance_audio": "铁器刮擦砖石的短促摩擦，随后是泥浆落水的闷响"
}
```

**② 编辑形态**——人改过一次之后，`video_prompt` 从结构化退成字符串，正文 + 两行字段一起存：

```
0-2秒：铁镐入缝的同一刻起手，手腕先沉后拧，刃口在砖缝里压实；
2-4秒：肩背随拧转带起上身，咬肌绷紧、下颌前递；
4-6秒：右腿蹬直、身体整体上抬，井壁泥层松动，泥水被带出画面；
6-8秒：泥浆从上沿倾泻砸落，人留在画面右侧。
Camera_Motion: Push In
Ambiance_Audio: 铁器刮擦砖石的短促摩擦，随后是泥浆落水的闷响
```

> 这是**存储**形态，不是屏幕形态。今天它被原样塞进一个 `Textarea`（`ShotDetail.tsx:640-647`），
>   
> 用户看到的就是截图里那一整段字；而且 `videoPromptText`（`ShotDetail.tsx:117`）只取 `prompt.action`，
>   
> 手改一次就把 `Camera_Motion` / `Ambiance_Audio` 丢掉（运镜回落 `Static`、环境音清空）。
>   
> 屏幕上应该长什么样，见 **11.8**。

**③ 下发形态**——`render_storyboard_video_prompt` 的逐字输出，这才是供应商看到的东西：

```yaml
Voice_Profiles:
- Speaker: 沈昭
  Voice_Style: 低沉沙哑，气声偏多，句尾下沉
Action: 0-2秒：铁镐入缝的同一刻起手，手腕先沉后拧，刃口在砖缝里压实；2-4秒：肩背随拧转带起上身，咬肌绷紧、下颌前递；4-6秒：右腿蹬直、身体整体上抬，井壁泥层松动，泥水被带出画面；6-8秒：泥浆从上沿倾泻砸落，人留在画面右侧。
Camera_Motion: Push In
Ambiance_Audio: 铁器刮擦砖石的短促摩擦，随后是泥浆落水的闷响
Dialogue:
- Speaker: 沈昭
  Line: 再使把劲。

Avoid: BGM、文字字幕、水印、Logo

Keyframe references K0–K3 correspond to the 4 reference images in their supplied order. They are consecutive moments of one shot, from opening to ending. Follow this temporal order and preserve character, setting and action continuity.
```

三段的职责边界，以及它们各自由谁决定：

| 段                                             | 谁写       | 依据                                                          |
| --------------------------------------------- | -------- | ----------------------------------------------------------- |
| `Voice_Profiles` / `Dialogue`                 | 渲染层      | 条目 `utterances` × 角色资产的声音风格；**AI 不写**（S4 / S5）              |
| `Action` / `Camera_Motion` / `Ambiance_Audio` | AI 写、人可改 | `<keyframes>` + 分镜提示词（**D-15**）                             |
| `Avoid: …`                                    | 渲染层模板    | `shared/video_avoid`，写死                                     |
| `Keyframe references K0–K3 …`                 | 渲染层      | `generated_assets.shot_grid.cell_paths` 的顺序；宫格换了几格，这一行自动跟着变 |

要点：

- **K 的编号不由人定**，也不由 AI 定：`K0…Kn` 就是 `cell_paths` 的下标序，正文只能引用、不能重排  
  （**D-17**）。这也是为什么正文里写 `K4` 会在写回时被拒——那一帧根本不存在。
- **最终文本里没有「画面比例 / 时长 / 模型参数」**：它们在请求体里，不在提示词里（S5）。谁写进正文，  
  谁就在给供应商制造两套互相打架的指令。
- **结构化与文本形态逐字同构**：上面 ② 改过之后，③ 里 `Action` 的内容与 ② 的正文一致，`Avoid` 与  
  `K0–K3` 段照旧由渲染层补——所以「改了的文本会不会丢约束」的答案是：不会。
- 若该分镜**没有**已确认宫格，③ 里就没有最后那段 `Keyframe references …`，视频按首帧图生成；这也是  
  「先确认参考素材、再写视频提示词」这个顺序的实际后果。

### 11.8 视频提示词输入框（用户看到什么）

现状就是截图：一个 `Textarea` + 工具条「引入参考素材 ⌄ / 生成视频提示词 / 查看提示词」，里面是五六百字  
一整段，`@[柳玉茹]` 这类引用记号混在句子里。问题不是"不好看"，是**没法核对**——用户要判断的其实是四  
件事：这几段动作是不是分别对上 K0–K3、运镜跟不跟得上、时长够不够、台词有没有混进正文。一坨文本里，  
这四件事一件都看不出来；写错一个 `K4` 也要等保存后才知道。

设计要求：**输入框的组织单位是 K 帧，不是段落。**

```
视频提示词                                       宫格 2×2 · 已确认
┌────────────────────────────────────────────────────────────────────┐
│ [ 引入参考素材 ⌄ ]    [ 生成视频提示词 ]    [ 查看提示词 ]          │
├────────────────────────────────────────────────────────────────────┤
│ 0-2秒  K0→K1 │ 铁镐入缝的同一刻起手，手腕先沉后拧，刃口在砖缝里压实 │
│ 2-4秒  K1→K2 │ 肩背随拧转带起上身，咬肌绷紧、下颌前递               │
│ 4-6秒  K2→K3 │ 右腿蹬直、身体整体上抬，井壁泥层松动，泥水被带出画面   │
│ 6-8秒  K3    │ 泥浆从上沿倾泻砸落，人留在画面右侧                     │
├────────────────────────────────────────────────────────────────────┤
│ 运镜 [ Push In ▾ ]              环境音 [ 铁器刮擦砖石…         ]   │
├────────────────────────────────────────────────────────────────────┤
│ 台词 · 来自剧本，只读：沈昭「再使把劲。」                            │
└────────────────────────────────────────────────────────────────────┘
```

| 项         | 规则                                                               | 为什么                                          |
| --------- | ---------------------------------------------------------------- | -------------------------------------------- |
| 时间段列      | 段数 = 当前宫格格数；时间按 `duration_seconds` 均分（4 格 / 8 秒 → 每段 2 秒），只读     | **S1** 的「逐段对上 K0→Kn」在界面上就是这一列，不靠人自己数         |
| K 徽标      | `K0→K1` 只读，由格数算出；点击高亮上方对应格                                       | K 编号不许人编、也不许 AI 编（**D-17**）                  |
| 运镜        | 下拉，`CameraMotion` 词表（中文标签 + 英文值），不给自由输入                          | 避免 `push_in` / `dolly in` 这类漂移值进正文（S1 的写法约束） |
| 环境音       | 单行输入                                                             | 只写画内音，不写 BGM（S5）                             |
| 台词        | drama 只读（来自 `utterances`），要改去剧本；ad / narration 的 `dialogue` 可增删行 | 台词不在这步产生（S4）                                 |
| 越界        | 段内手打 `K4` 当场标红并阻断保存；写回 422 兜底                                    | 错误从"计费后"提前到"编辑时"                             |
| 改时长 / 改格数 | 段按新时长重排、段内文本不动；格数变了则新增段留空，被删段的内容并进末段                             | 不静默丢字，也不做旧格合并（**D-11**）                      |
| 查看提示词     | 只读抽屉，展示 ③ 的下发全文（含 `Voice_Profiles` / `Avoid` / K 声明），可复制         | 用户不需要在输入框里看到 YAML 字段名                        |
| 退化        | 存量条目解析不出 `0-x秒：` 前缀 → 整段退化为单文本框，并提示「按 `0-2秒：` 分段后可逐格核对」          | 老数据不强转、不清空                                   |

- 分段契约就是 **S6**：`0-2秒：…` 既是给模型的写法，也是编辑器切段的依据——规范和界面同一只手，  
  不会出现"规范要求分段、界面却是一整块"。
- 存储不变：段内编辑只改 `action` 里对应那一段，结构化字段照旧（`action` / `camera_motion` /  
  `ambiance_audio`）；只有出现无法归段的自由文本时才整体退成字符串形态（**②**）。
- 两个按钮留在原处（截图里就在工具条），用户视线不用重找。

## Considered Options

- **宫格纯生成、单分镜也不弹窗**（旧版 `73971bb` 的走向）：少一份可编辑文本、少一个端点、没有半截状态  
  路径；但代价是作者**完全不能**微调逐格画面意图，只能回去改 scene 再整张重出——单分镜作业下体验过重。  
  已还原 `63daec9` 的**确认弹窗**（输入框 + AI 生成 + 确定），用「`prompt` 优先、`scene` 兜底」消解双  
  真相源问题（**D-3**）：弹窗手填 `prompt` 时它就是这次出图的文本，留空则与纯生成等价，不存在「两份  
  各自生效」的冲突。
- **不为「AI 生成」建端点，让前端自己拼提示词**：能省一个端点；但前端没有资产编号 / scene 导语这类  
  服务端上下文，拼出的文本质量差且不统一——保留 `POST /author-prompt`（**D-5**），由服务端把规格 /  
  资产 / scene 拼成可编辑宫格提示词回填。它只产出 `prompt` 文本，前端随即存成草稿（`PUT /draft`），  
  不另存第二份文本，也不在草稿阶段触发一次生成。
- **把镜头提示词写回 `image_prompt.scene`**：会让 scene 同时承担"意图"与"某次出图参数"两种语义，  
  与 0098 D-A 的镜头序列格式冲突——放弃，解析结果只留在 `cells` 留证。
- **把视频提示词正文也存一份进 `ShotGrid`**：与宫格的一次性出图留证混在一起，且与正式脚本形成双  
  真相源，改哪份生效说不清——放弃，只存「依据」（**D-12 / D-18**）。
- **在 `confirm` 里顺手入队视频提示词编写**：确认动作会被用来"认图"，却暗地里产生一次文本模型费用，  
  且绕过覆盖确认——放弃，改为确认后显式触发（**D-14**）。
- **视频提示词继续用一个 `Textarea` 装整段文本**：实现省事，但用户核对不了「哪段对哪一格」，越界要  
  等保存才报，运镜与环境音在文本形态里也没法结构化编辑——放弃，改成分段编辑器（**11.8**）。
- **视频提示词批量复用 `StoryboardBatchDialog`**：那一套是"逐张图 + 每张单价"的形态，视频提示词是  
  一次文本批次，报不出逐张价格，弹窗里的"预估费用"会变成空话——放弃，复用 `PromptAuthoringDialog`  
  并预选条目（**D-20**）。
- **让文本模型直接看宫格图（多模态）**：质量上限更高，但会把提示词编写从 `TextGenerator` 迁到多模态  
  通道，配置、计费、降级全要重做——本期放弃，用逐格文本作代理（**D-15**），列为后续选项。

## Consequences
