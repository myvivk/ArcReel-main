# 5. 视频提示词独立步骤生成设计

> 唯一链路约束（2026-10-23）：以《短剧工厂唯一链路删除清单》为准。生产只保留「工厂质量闭环与七类工件入库 → 资产 → AI 分镜 → 逐镜 ShotGrid / K 帧确认 → 独立视频提示词 → 视频与声音 → 剪辑导出」。旧单集／批量正文导入、源稿直接保存、普通源文规划、旁白／广告模式、参考单元和跨分镜联合图的页面、HTTP、Agent 与任务入口全部删除。文中基线问题和旧源码定位只用于说明设计依据，不构成保留旧生产入口的要求。
>
> 历史项目保留源文、媒体、版本、读取、归档、已有剪辑和已提交付费任务恢复；不改写旧模式字段，不从旧 JSON 拼造七类工件。工厂剧情与台词以 `source/short_drama/` 为真相源，`scripts/episode_N.json` 只保存视觉派生状态；生产要求工厂源稿修订与派生来源一致。

> 目标：把 `video_prompt` 定义为「参考素材确认之后、视频生成之前」的独立文本生成步骤，并按短剧工厂口径澄清输入、数据源、产出位置和当前实现差距。
> 核心校正：短剧工厂链路没有「正式脚本」概念。Markdown 源稿就是剧情、对白、节奏和连续设定的数据源；视觉制作可以有派生状态，但派生状态不能反过来成为工厂链路的真相源。

## 一、结论

视频提示词独立成步骤是合理的，但上一版方案把它错误地绑定到了「正式脚本 / `scripts/episode_N.json`」口径。按工厂链路应改为：

1. **工厂真相源是 Markdown**：集级剧本源稿固定读取 `source/short_drama/episodes/episode_NN.md`。这是短剧工厂链路的剧情、对白、动作、节奏和连续设定来源，不迁移到 `scripts/episode_N.md`。
2. **`image_prompt` 不是单帧描述**：它是 12-15 秒分镜段的画面提示词，描述这一段里可见的人物、环境、动作节拍、景别、机位、运镜和视觉参考；可以包含多个 `【镜头N】` 块。它不是某一帧静态画面说明。
3. **`video_prompt` 依赖参考素材确认**：`video_prompt` 描述这一段画面如何运动、角色动作如何从 K0 到 Kn 承接、运镜和环境音如何变化。它不应和 `image_prompt` 同时生成。
4. **当前代码仍有兼容投影层**：工厂产物入库已经按 Markdown 原样保存，但 AI 分镜、宫格、视频提示词和视频生成仍大量复用原生 `scripts/episode_N.json` 结构。这个 JSON 只能视为视觉制作派生状态，不能被文档继续称为工厂链路的正式脚本。

因此，本设计的判断是：**方案文档应统一按「Markdown 源稿是真相源、视觉制作状态是派生层」书写；代码实现处于「工厂入库正确，视觉制作仍依赖 JSON 派生层」的过渡态。**

## 二、概念边界

| 概念 | 工厂链路目标语义 | 当前实现状态 | 结论 |
| --- | --- | --- | --- |
| Markdown 源稿 | 工厂剧本数据源，承载剧情、对白、动作行、人物 / 场景 / 道具标记 | `lib/short_drama_ingest.py` 原样写入 `source/short_drama/`；`lib/script/short_drama_source.py` 读写 `source/short_drama/episodes/episode_NN.md` | 语义与路径均符合本次确认要求 |
| 正式脚本 | 工厂链路不应存在该概念 | `server/services/short_drama_workflow.py` 会把 Markdown 转成 `scripts/episode_N.json` 供时间线、宫格和视频复用 | 只能称为视觉制作派生状态，不应作为工厂真相源 |
| `image_prompt` | 12-15 秒分镜段的画面提示词 | AI 分镜代码按 12-15 秒生成；共享模板、字段说明和输入框占位已统一为分镜段口径 | 符合本次语义要求 |
| 参考素材 / K 帧 | 由 `image_prompt` 生成、确认后的关键帧序列 | `ShotGrid` 保存 cells 和切图，确认后写入派生脚本条目 | 可用，但应只作为视觉制作输入 |
| `video_prompt` | 基于 `image_prompt` + 已确认 K 帧生成的动作 / 运镜 / 环境音文本 | 当前写回派生 JSON 条目的 `video_prompt` | 步骤顺序合理，存储位置仍未按工厂源稿收口 |

## 四、步骤边界

### 4.1 上游

视频提示词生成前必须满足：

1. 本集 Markdown 源稿存在，且是本集剧情与对白的数据源。
2. 本集已有分镜段，分镜段来自 Markdown 源稿的 AI 分镜或人工分镜。
3. 分镜段已有 `image_prompt`。`image_prompt` 描述的是这一段 12-15 秒画面内容，不是一帧图片。
4. 参考素材宫格已生成并由用户确认，K 帧顺序稳定。

当前兼容实现还要求目标分镜存在于 `scripts/episode_N.json` 派生状态里，这是实现限制，不是工厂链路概念。

### 4.2 下游

视频提示词完成后，视频生成才允许提交。视频生成继续校验：

1. 目标分镜段已有 `video_prompt`。
2. 分镜图、参考素材切图、尾帧等图片输入可解析且仍可用。
3. `video_prompt` 渲染后不超过模型提示词长度限制。
4. 文本中的 `K{n}` 引用没有越界。
5. 当前视频模型支持本次请求需要的参考图数量、首尾帧、时长和音频能力。

## 六、流程

### 6.1 状态规划

工作流读取 Markdown 源稿、分镜段和 ShotGrid 记录后，生成视频提示词目标集合：

1. 没有 Markdown 源稿：拒绝，提示先生成或导入本集源稿。
2. 不是 `storyboard` 生成路线：本步骤不适用。
3. 目标分镜没有已确认参考素材：进入 `awaiting_grid_ids`，不纳入本批。
4. 目标分镜有已确认参考素材，且 `video_prompt` 为空：进入 `missing_ids`，可批量生成。
5. 目标分镜有 `video_prompt`，但 `video_prompt_basis` 与当前参考素材不一致：进入 `stale_ids`，提示建议重写。
6. 目标分镜有 `video_prompt`，且依据仍匹配：进入 `current_ids`。

### 6.2 构造文本模型输入

模型输入只给两类信息：

1. **分镜段上下文**：分镜 ID、Markdown 原文锚、时长、角色、场景、道具、`image_prompt`。
2. **参考素材上下文**：按 `K0…Kn` 顺序列出每格景别和画面文本。

关键约束：

- 只在 `fields == {"video_prompt"}` 时注入参考素材上下文。
- 不把参考素材上下文注入 `image_prompt` 编写任务。
- 不把图片二进制发给文本模型；文本模型看到的是 K 帧的文本代理。
- 模型只输出 `video_prompt`，不输出 `image_prompt`，不重写台词、时长、资产引用和生成产物字段。

示例输入块：

```text
分镜提示词：12 秒段落。沈昭@[沈昭] 在井壁下方抓住铁镐，泥水不断落下；镜头从全景切到近景，再仰拍井口压力。
关键帧（2x2，按 K0→K3 顺序，与视频请求下发的参考图同序）：
  K0（全景）：沈昭左手将铁镐斜插进砖缝，身体贴近井壁。
  K1（近景）：面部特写，咬肌绷紧，手腕开始发力。
  K2（中景）：右腿蹬住湿滑砖面，身体向上撑起。
  K3（仰拍）：井口灰白泥浆倾泻，沈昭稳住身体避开落点。
```

### 6.3 模型输出与结构校验

| 内容模式 | 输出字段 | 说明 |
| --- | --- | --- |
| drama | `action`、`camera_motion`、`ambiance_audio` | 不含 `dialogue`；台词由 `utterances` 在最终渲染阶段注入 |
| narration | `action`、`camera_motion`、`ambiance_audio`、`dialogue` | `dialogue` 仅表达分镜内实际需要视频模型处理的人声 |
| ad | `action`、`camera_motion`、`ambiance_audio`、`dialogue` | 若纳入此步骤，按广告分镜 schema 处理 |

**文本口径：`action` 是增量文档，不是第二遍画面。** 分镜提示词与已确认 K 帧已经固定了主体长相、
服装、构图、景别、机位、光线和动作的起止状态；`action` 只写 K0→Kn 之间这些状态**怎么变**
（触发、过程、落点），并且不出现任何镜头语言——运镜只由 `camera_motion` 承载。每个 K 间隔至少保留
一个分镜已经写出的必要动作；删的是静帧复述，不是动作本身。静态外观、镜头复述与整句复述由编写闸
拦截，把原因回喂给模型做局部返修。

校验要求：

1. 输出必须覆盖本次所有目标 ID。
2. 不得输出本次范围之外的 ID。
3. 同一 ID 不得重复。
4. 输出中出现的 `K{n}` 必须小于当前参考素材格数。
5. `action` 不能为空。
6. 不得把系统包装字段写进正文，例如 `Avoid`、`Voice_Profiles`、`Dialogue`、画面比例、模型参数。
7. `action` 不得出现景别 / 机位 / 运镜等镜头语言；这些由分镜提示词与 `camera_motion` 承载。
8. `action` 的静态外观词密度不得超过阈值；与分镜提示词或 K 帧的整句相似度、逐字重合长度不得超过阈值
   （词表与阈值见 `lib/script/shot_prompt_standard.py`）。接近阈值但未阻断的复述记入评分指标的
   `warnings`，用 `scripts/score_video_prompts.py` 汇总到集级报告。
9. 正文写了 `0-x秒` 时间段时，必须从 0 起连续衔接并覆盖完整 `duration_seconds`；缺口、重叠或
   与分镜时长对不上都按可回喂原因返修。没有时间段的存量文本不判。

### 6.4 写回

目标态应把 `video_prompt` 写入分镜段的视觉制作状态，并记录 `video_prompt_basis`：

```json
{
  "video_prompt": {
    "action": "0-3 秒：沈昭贴墙稳住重心，铁镐先压入砖缝；3-6 秒：手腕拧转带动肩背发力，身体向上撑起；6-12 秒：泥浆从井口倾泻，他侧身避开并保持上爬节奏。",
    "camera_motion": "Push In",
    "ambiance_audio": "铁器摩擦砖石的短促声，泥浆落水的闷响"
  },
  "generated_assets": {
    "video_prompt_basis": {
      "grid_id": "shot_grid_123456789abc",
      "layout": "2x2",
      "cells_revision": "9f3c1a0b7d2e",
      "written_at": "2026-10-22T00:00:00+00:00"
    }
  }
}
```

当前实现会把这段写回 `scripts/episode_N.json`。在工厂链路说明里应把它称为「视觉制作派生状态」，不要称为工厂正式脚本。

## 七、产出

### 7.1 主要产出

主要产出是目标分镜段的 `video_prompt`。

支持两种存储形态：

- 结构化对象：AI 生成默认形态，保留 `action`、`camera_motion`、`ambiance_audio`、`dialogue`。
- 字符串：人工自由编辑后的兼容形态，最终仍由 `render_storyboard_video_prompt` 包装。

### 7.2 附属产出

附属产出是 `generated_assets.video_prompt_basis`：

- `grid_id`：写这条提示词时使用的 ShotGrid。
- `layout`：写入时的宫格规格。
- `cells_revision`：逐格文本的摘要。
- `written_at`：写入时间。

### 7.3 非产出

本步骤不产出以下内容：

- 不生成视频文件。
- 不生成或修改参考素材图片。
- 不修改 Markdown 源稿。
- 不修改 `image_prompt`。
- 不修改台词、原文、时长、资产引用。
- 不登记新的媒体产物文件。
- 不在 `ShotGrid` 里保存第二份 `video_prompt` 正文。

## 八、失败与恢复

| 失败类型 | 触发条件 | 恢复方式 |
| --- | --- | --- |
| Markdown 源稿缺失 | 项目内没有对应集源稿 | 先生成、导入或保存本集 Markdown |
| 分镜段缺失 | 源稿还没有完成 AI 分镜或人工分镜 | 先执行 AI 分镜或手动创建分镜段 |
| 参考素材缺失 | 目标分镜没有已确认 ShotGrid | 先生成并确认参考素材 |
| 覆盖确认缺失 | `rewrite=true` 会覆盖已有 `video_prompt`，但没有有效 `overwrite_revision` | 向用户展示覆盖清单，确认后重试 |
| K 引用越界 | 文本引用了不存在的 `K{n}` | 修改提示词或重新生成，确保 `n < 格数` |
| 活动任务冲突 | 同一集已有提示词编写任务运行中 | 等任务完成后重试 |
| 队列 worker 离线 | 请求合法但无法提交或执行异步任务 | 恢复 worker 后重试；不要误改源稿 |
| 模型能力不匹配 | 后续视频模型不支持当前参考图、尾帧或时长 | 改宫格规格、改视频模型或调整分镜段 |
