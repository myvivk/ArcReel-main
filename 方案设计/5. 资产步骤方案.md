# 资产步骤方案

> 在「剧本」与「分镜」两个集页步骤之间新增一个「资产」步骤：页内含 **角色集 / 场景库 / 道具库** 三个 tab 切换；内容由**本集剧本（工厂源稿）+ 故事规划抽取**；与侧栏既有的独立入口「角色集 / 场景库 / 道具库」（项目全部资产）构成 **本集资产 ⊆ 全部资产** 的包含关系。
>
> **概念约定（本次优化）**：
>
> - 本文中「剧本」即「工厂源稿」——指项目 `source/short_drama/*.md` 下的工厂 Markdown 源稿（各集 `[人物]/[场景]/[道具]` 标记稿、角色段落、场景名行等），是逐集的定稿脚本（场景 + 台词）。其中 `[人物]/[场景]/[道具]` 标记行形如 `名称｜外观描述`（如 `[人物]：沈昭（冷醒·重生者｜藕荷色西装套裙）`、`[场景]：…｜白墙、输液架、监护仪绿线`），**本身已带视觉 / 外观描述**，是生成描述的主素材——它不是「只写名字」，名字后面跟的就是外观。
> - 「故事规划」指项目级规划 / 设定文档集合：**人物圣经（character-bible）、全剧大纲（series-outline）、连续性台账、分集规划**。它是剧本之外的第二权威来源，补足角色背景、世界观与跨集一致性。
> - 原方案里与之并列的「本集正式剧本（`scripts/*.json`）」「项目设定 canon」不再作为独立来源；抽取与 AI 生成描述统一为 **剧本（工厂源稿）> 故事规划 > 题材补全** 三级优先级（原 D-35 的 episode 翻转逻辑因此消解）。

> **范围（不在本方案内）**：本方案只覆盖 **角色 / 场景 / 道具** 三类资产；**商品（product）不在此列**，广告集不显示资产视图（详见 D-28 / D-30）。

## 核心流程（先描述，后出图）

两条前置概念先讲清：

- **登记**：把抽取出来的资产**名字**，在资产库里建成一条「可操作条目」。它解决的是「剧本里写的词 → 系统认识的资产」这一步跨越。
  - **输入**：上一步「抽取」得到的「名字 + 类型」对，例如「阿岚 / 角色」「客厅 / 场景」「玉佩 / 道具」。类型由来源决定（剧本 `[人物]` 标记 → 角色，`[场景]` → 场景，`[道具]` → 道具；故事规划里的角色清单 → 角色）。
  - **动作**：到对应桶（`characters` / `scenes` / `props`）按名字查重——**已有就跳过，没有就新建一条** `{ name, type, description: "" }`。此时条目只有名字、描述为空白。
  - **为什么必须先登记**：剧本里写的「阿岚」只是一段文本，系统并不认识它。只有登记成条目，它才成为资产库里的**一等公民**——之后才能给它生成描述、生成资产图、在画廊里被引用。没登记 = 只是一句话里出现的词，什么也做不了。所以「抽取」只是认出名字，「登记」才是把它变成能操作的资产。
  - **幂等**：只补不存在的，已登记的条目、描述、资产图一律不动；重复点按钮不会覆盖你已写好的内容，可放心反复跑。
- **生成描述**：用 AI 把工厂源稿里已有的描述**强化、规范**成资产 `description`。工厂源稿的 `[人物]/[场景]/[道具]` 标记行（如 `[人物]：沈昭（冷醒·重生者｜…藕荷色西装套裙）`、`[场景]：…｜白墙、输液架、监护仪绿线`）**本身就带外观描述**，所以 AI **不是凭空写**，而是**以标记行描述为基础、结合该资产在剧本里出现的场景 / 台词 / 动作来强化**，再按 `asset_description_rule` 规范成 `description`。AI **只填空字段、绝不覆盖你已写好的描述**。

所有资产动作都围绕一条不可打破的主线：

> **资产图必须基于描述出图**——`asset_description_required` 准入会挡下「无描述」的资产生成。工厂源稿标记行已带外观描述，但它是零散原始文本，需 AI 强化规范成资产图可用的 `description`；只有「无标记行、故事规划也兜底不了」的名字才会真缺描述。所以 **「先生成描述、再出资产图」是出图前置**。

一键「生成本集资产」链路固定顺序：

1. **抽取** 名字 + 类型（来自本集剧本 · 工厂源稿的 `[人物]/[场景]/[道具]` 标记行 + 故事规划），标记行 `｜` 后的外观描述一并作为生成描述的素材
2. **登记** 未登记的资产（幂等，建条目）
3. **生成描述**：本集引用到、描述为空的资产，以 **工厂源稿标记行描述（基础）＋ 剧本上下文（强化）** 为主、故事规划补漏，由 AI 规范写出 `description`（只填空字段）
4. **出图**：**仅对第 3 步已生成描述的资产**走既有资产图批量生成；仍缺描述的资产不进队列

> ⚠️ 第 3 步不能外置、不能省略：把它留在链路外，等于一键只完成「登记」，最终「登记了 N 个、出图 0 张」——把一键做成半截。**缺描述就不出图**，所以必须先有描述、再出图。

## 页面入口与弹窗（去哪点、点完为什么弹窗、弹窗里有什么）

**1. 去哪点按钮**
- 打开某集详情页（从侧栏「剧集」进入）→ 切到「资产」步骤，URL 即 `episodes/{episode}?view=assets`（或点制作进度面板「待生成资产图 N」直接跳转）。
- 该资产步骤页**顶部工具栏**（三个 tab 之外）有**唯一一个**「生成本集资产」按钮。不在侧栏、不塞进任何 tab。

**2. 为什么点按钮后弹窗、而不是直接生成**
- 点按钮**不会立刻生成**。生成本集资产 = 一次性跑「抽取 → 登记 → 生成描述 → 出图」四步，要调多次文本模型 + 图像模型，是**有成本、且会落盘写资产**的批量操作。
- 而工厂源稿的标记行**本身已带外观描述**（如 `[人物]：沈昭｜藕荷色西装套裙`、`[场景]：…｜白墙、输液架`），AI 会据此强化，无需用户手写；故事规划补漏跨集背景。用户只需先看清「这集要处理多少资产、花多少模型调用」再决定要不要跑。
- 所以按钮和真正生成之间，**必须有一个确认关卡**——这就是弹窗。它的**唯一目的是把本批范围和预计花费摆出来给你确认**（有成本、会落盘，不能误点就跑）；不收集任何额外输入，直接「确定」即按既有素材（工厂源稿标记行描述 + 剧本上下文 + 故事规划）生成。

**3. 弹窗里有什么（就一块：本批清单）**

- **确认区 · 本批清单（只读，不能改）**
  弹窗底部显示：「将处理 N 个资产（角色 X / 场景 Y / 道具 Z），预计文本模型 N 次、图像模型 M 次」。
  - *为什么只显示不能改*：只是让你「确定」前心里有数、别误跑整集；范围是按钮语义固定的（整集三类全跑），不需要你筛，所以不做成可编辑字段。

> 弹窗**没有别的输入框**：不设「类型筛选」（按钮就是整集全跑，想只跑某类用单资产卡）、不设「覆盖已有描述」开关（AI 只填空字段、绝不覆盖你写好的）、不设「画幅 / 比例」（按资产类型自动定，角色竖版、场景横版）。

**4. 点「确定」→ 开始生成**
- 点「确定」才真正发请求（见「开始生成后的流程」），按 `batch_id` 跟踪整批。

**不在弹窗范畴的两个入口**
- **单资产操作**：每张资产卡上的「生成描述」「生成资产图」两步可单独跑，用于只补某一个、或补完缺描述项再出图。
- **全部资产入口**：侧栏「角色集 / 场景库 / 道具库」是项目全集入口，与当前集子集互补、共用同一份资产桶。

## 开始生成后的流程（点「确定」之后）

1. **提交**：前端发 `POST /projects/{name}/episodes/{episode}/generate-assets`，请求体不带额外参数（外观素材来自工厂源稿标记行描述 + 剧本上下文 + 故事规划）。
2. **服务端一次性跑完四步**（同一请求内）：
   - 抽取名字（本集剧本 · 工厂源稿 + 故事规划）
   - 登记未登记资产（幂等，建条目）
   - 生成描述：仅对「本集引用到且描述为空」的资产，按 **剧本（工厂源稿）> 故事规划** 优先级由 AI 写 `description`（标记行已带外观则强化而非重写），只填空字段，一次批量写回
   - 出图：**只对已生成描述的资产**入队资产图生成任务；仍缺描述的资产**整体不进队列**
3. **立即回执 `batch_id`**：接口返回本批清单——登记了几个、生成了几条描述、几个缺描述（`without_description`）、冲突几个（`conflicts`）、生成描述失败几个（`description_fill_failed`）。**此刻图还没出完，是异步任务。**
4. **前端跟踪整批**：拿 `batch_id` 轮询 / 订阅任务状态，本集资产列表**实时刷新**；每个资产卡显示当前状态：已登记 → 描述生成中 → 出图中 → 已完成 / 失败。
5. **收尾**：出图完成的资产图出现在三 tab 画廊，制作进度面板的「待生成资产图 N」随完成数递减；**缺描述 / 生成描述失败的项留在「缺描述」状态、不生成图**，用户可单独点该卡「生成描述」补齐后，再点「生成资产图」。

> 生成描述失败是**单资产**失败，不中断整批：该项保持「缺描述」、不进图队列，界面如实提示，不静默吞掉。

## AI 怎么参与 / 质量怎么保证

AI 在两处参与，质量由四层保证：

- **AI 参与点 1 · 生成描述**（文本模型）：给「描述为空的资产」写出 `description`。
- **AI 参与点 2 · 出图**（图像模型）：按 `description` 生成资产图。

质量保障：
1. **素材充分**：描述与出图都按 **剧本（工厂源稿标记行描述＋剧本上下文）> 故事规划** 取上下文。工厂源稿标记行已是外观描述、再结合剧本上下文强化，故事规划补漏跨集背景——AI 是「强化 / 规范」而非「凭空编外观」。
2. **规范约束**：描述受 `shared/asset_description_rule` 模板约束，只写规范允许的事实、不允许编造；出图受 `asset_description_required` 准入约束——**没有描述就根本不进图队列**，从源头挡住「无依据出图」。
3. **尊重人工**：AI 只写「描述为空」的字段，绝不覆盖你已写好的描述；资产图有 `pending/stale/done` 状态与重生成机制，出了不满意的图可重跑。
4. **失败隔离**：单资产生成描述或出图失败，只影响该项（留「缺描述」或不生成），不拖垮整批、不静默吞错。

## 一、背景与触发

1. 集页现有「剧本 → 分镜 → 剪辑」等步骤；要求在 **剧本与分镜之间插入一个「资产」步骤**。
2. 侧栏已有独立顶层入口「角色集 / 场景库 / 道具库」（对应项目全部资产）。新增的集页「资产」步骤与它们的**关系定义为包含**：本集资产是全部资产的一个子集，即子集只能看到该集的资产。

据此落地的三条产品语义：

- 集页「资产」步骤页内用 tab 切换：**角色集、场景库、道具库**。
- 该页展示的内容来自**本集剧本（工厂源稿）+ 故事规划抽取**（本集剧本里引用到、以及故事规划中定义/提及的角色 / 场景 / 道具）。
- 与侧栏「角色集 / 场景库 / 道具库」全量入口是**子集 / 包含**关系：集页资产视图 = 本集用到的那部分；侧栏入口 = 项目全部资产。二者互补，不重复造数据。

## 二、现状核实（代码级）

### 2.1 集页视图路由体系

集页视图的取值、可用条件、排序**只在一处定义**：`frontend/src/components/canvas/episode-page/episode-view.ts`。

- `EPISODE_VIEWS = ["setting", "plan", "grid", "board", EPISODE_VIEW_SOURCE, EPISODE_VIEW_EDIT]`（行 19）。
- `episodeViewTabs(facts)`（行 60）按显示顺序产出 tab：**普通集** = `plan → source → grid（若开启）→ board → edit`；**广告集** = `setting → board → edit`；**演示集** = `board`。
- `CanvasView = Exclude<EpisodeView, "setting" | "edit" | "source">`（行 22）：`setting`/`edit`/`source` 由 `EpisodePage` 直接整体替换画布；其余（`plan`/`grid`/`board`）经 `renderCanvas` 走 `TimelineCanvas` / `GridImageToVideoCanvas` / `ReferenceVideoCanvas`。
- `defaultEpisodeView`：有正式剧本时为 `board`（行 86），缺省视图不写 `?view=`。

分派落点：

- `frontend/src/components/canvas/episode-page/EpisodePage.tsx`：`view === "edit"/"setting"/"source"` 各自分支（行 210/241/247），其余走 `renderCanvas({ view, ... })`（行 273）。
- `frontend/src/components/canvas/StudioCanvasRouter.tsx`：`<Route path={EPISODE_ROUTE_PATH}>` 渲染 `EpisodePage`，`renderCanvas` 回调（行 546）按 `route`（reference_video / grid / 默认）分派到三个重画布组件。

> 关键结论：新增「资产」视图只要（1）在 `EPISODE_VIEWS` 加一个值并在 `episodeViewTabs` 排序里插入；（2）在 `renderCanvas` 回调里加一个 `view === "assets"` 分支，返回一个新的轻量 `EpisodeAssetsView`（不必加载 Timeline/Grid 重画布）。`EpisodePage` 主体无需改动（它只调 `renderCanvas`）。

### 2.2 本集资产计算（已存在单一事实源）

`lib/project/episode_asset_references.py` 的 `episode_referenced_assets(project, script) -> frozenset[ReferencedAsset]`（行 35）**就是「本集引用资产」的唯一计算点**：

- 输入：项目数据 + 本集剧本（工厂源稿）+ 故事规划（人物圣经 / 全剧大纲 / 连续性台账 / 分集规划）。无剧本时返回空集。
- 过程：
  - **主来源 · 剧本（工厂源稿）**：遍历剧本中的引用（`payload_reference_names`，含引用数组 + `speaker` + 正文 `@[名称]`；工厂源稿中以 `[人物]/[场景]/[道具]` 标记行与引用数组两种形式存在），经 `ReferenceCatalog.resolve` 决议落盘真名。
  - **补充来源 · 故事规划**：人物圣经的角色清单、分集规划中的资产提及一并纳入，确保登记完整性——剧本尚未点名但规划已定义的角色 / 场景 / 道具也能被本集引用。
  - 衍生 `本体/衍生` 同时算引用了本体（行 53–66）；未登记的名字不算。
- 输出：`ReferencedAsset(asset_type, name, owner)`——已登记资产的落盘真名集合。

调用方（三处共用这一份，不各自拼集合）：

- `lib/workflow/workflow_state.py:1615` `_referenced_sheet_facts()`：计算本集资产图完成度。
- `server/services/admission/asset_sheet_batch.py:467` `load_asset_sheet_batch_plan()`：episode scope 的批量资产图生成计划。
- 制作进度面板 `step-list.ts` 的 `assetsRow`（行 635）读 `WorkflowContent.referenced_assets_without_sheet` / `referenced_assets_without_description` / `referenced_assets_with_sheet_stale`。

> 关键结论：**本集资产抽取已有现成实现，前端「资产」视图只需调用这个计算结果（按类型分组），无需新建数据模型**；抽取来源统一为「剧本（工厂源稿）+ 故事规划」，与全项目资产桶（`project["characters"/"scenes"/"props"]`）天然构成子集关系。

### 2.8 AI 生成描述（ai-fill）的现状：读取内容与优先级

资产描述（`description`）由专门的 `ai-fill` 端点生成（`POST /projects/{name}/{subdir}/{entry_name}/ai-fill`，`_asset_router_factory.py:576`），只写回当前为空的字段、绝不覆盖已有内容。其上下文搜集与 prompt 构造如下：

- **上下文来源**（`_collect_asset_context` + `_collect_story_plan`）：
  1. **剧本（工厂源稿，最高优先级）**：来自 `source/short_drama/*.md` 工厂源稿中各集 `[人物]/[场景]/[道具]` 标记稿，以及剧本里的场景与台词——用 `_scene_mentions` 命中该资产的场景，抽取 `scene` / `scene_description` / `dialogue`（`speaker:line`），上限 6 段或 6000 字符。剧本是定稿、最具体、最权威的来源。
  2. **故事规划（次优先级）**：人物圣经（character-bible，角色设定段落）、全剧大纲（series-outline，场景名所在行与全局设定）、连续性台账（跨集一致性约束）、分集规划（本集叙事规划与资产预期）。四类规划文档作为剧本之外的第二权威来源，补足剧本未展开的角色背景、世界观与跨集一致性。
  3. **已有字段**：当前 `description` / `voice_style` / `aliases` / `derivatives`，原样回灌并标注「已有，勿改」。
  4. **项目元数据**：`title` / `premise` / `logline`。
  5. **资产描述规范**：`shared/asset_description_rule` 模板，约束描述只写规范允许的事实。
- **prompt 优先级**：**剧本（工厂源稿）> 故事规划 > 题材补全**。剧本为顶块，故事规划四类文档紧随其后，题材补全兜底。集页资产视图与侧栏「全部资产」入口口径统一，**无需按视图翻转**（原 D-35 的 episode 翻转逻辑因此消解）。
- **填充范围**：`description` 全类型生成；`aliases` 全类型生成；`voice_style` 与 `derivatives` **仅角色**生成；模型只输出 JSON `{description, voice_style, aliases, derivatives}` 且只写回空字段。

> 现状（已实现）：生成描述逻辑在 `server/services/asset_ai_fill.py`，单资产端点（资产详情「生成描述」）与集页一键链路共用同一份。上下文分组：`episode_excerpts`（本集剧本）/ `story_plan`（故事规划）/ `genre`（题材补全）；`build_ai_fill_prompt` 固定「剧本 > 故事规划 > 题材补全」块序。场景命中口径与抽取口径对齐（`scene_mentions`）：各骨架引用数组写法不同（`props` / `props_in_scene`、`dialogue` / `utterances`）都要认；引用项写 `本体/衍生` 时算作本体被提到——否则剧本写「阿岚/战损」时按本名「阿岚」检索不到，本集摘录会整段落空。

## 三、设计决定（D-）

### D-28 新增集页视图 `"assets"`，置于「剧本」之后、「分镜」之前

- `EPISODE_VIEWS`（episode-view.ts 行 19）追加 `"assets"`。
- `episodeViewTabs`（行 60）普通集排序调整为：**`plan → source → assets → grid（若开启）→ board → edit`**。即资产视图紧跟剧本（source / 脚本规划域）之后、分镜（grid/board）之前——逻辑上资产图须在分镜生成前就绪（引用准入只校验 c/s/p 三类 sheet），顺序吻合。
- 文案：`episode_view_assets: '资产'`（dashboard.ts 新增）。
- **缺省视图不变**：有剧本仍为 `board`（D-28 不抢缺省落点，避免改变既有「生成剧本后停在分镜」的体验）；资产视图作为剧本与分镜之间的显式步骤，由用户主动进入，或系统在进度面板提示「待生成资产图」后跳转。
- 广告集：无 `plan`/`source`，剧本语义落在 `setting`；资产视图是否出现见 **P10**，本方案默认广告集**不显示**资产视图（广告项目通常无逐集剧本抽取需求），保持 `setting → board → edit`。

### D-29 资产视图内三 tab 复用 AssetGallery，按本集引用过滤

- 新增组件 `frontend/src/components/canvas/episode-page/EpisodeAssetsView.tsx`：内部用 tab 切换 `assetType`（`character / scene / prop`），每个 tab 渲染一个过滤后的 `AssetGallery`。
- `AssetGallery` 新增可选 prop `scopeNames?: Set<string>`（或 `scope: "episode"`）：仅展示 `name ∈ scopeNames` 的条目；徽标计数仍基于全量库以体现子集/全集关系（见 D-30）。
- **名字集合来源**：后端新增轻量端点 `GET /projects/{name}/episodes/{episode}/referenced-assets`，内部调用现成的 `episode_referenced_assets(project, script)`，按 `asset_type` 分组返回 `{ character: [...], scene: [...], prop: [...] }`（落盘真名）。前端 `EpisodeAssetsView` 拿到后分别传给三个 tab 的 `scopeNames`。**不新建抽取逻辑，复用单一事实源；抽取输入即本集剧本（工厂源稿）+ 故事规划。**
- `StudioCanvasRouter.tsx` 的 `renderCanvas` 回调（行 546）最前面加分支：`if (view === "assets") return <EpisodeAssetsView projectName episode scriptFile ... />`，置于 `route` 分派之前，避免加载 Timeline/Grid 重画布。

### D-30 包含关系：本集资产 ⊆ 全部资产（导航 + 计数表达）

- 资产视图每个 tab 显示角标 **「本集 N / 全部 M」**：`N` = 本集引用命中数（scopeNames 大小），`M` = 该类型全量库条目数（AssetGallery 既有全量数据可得）。一眼表达子集/包含。
- 每个 tab 提供入口「查看全部角色集 / 场景库 / 道具库」，跳转到侧栏对应的全部资产页（`/characters` `/scenes` `/props`），形成 **子集视图 ↔ 全集视图** 的双向导航。
- **不纳入 product（商品）tab**：本集抽取经 `episode_referenced_assets` 只覆盖 `character/scene/prop`，与引用准入 `SHEET_REQUIRED_ASSET_TYPES` 一致；商品不在「剧本→分镜」资产准备链路内（见 P11）。

### D-31 侧栏独立入口保留，语义收敛为「全部资产」

- `AssetSidebar` 的 `characters / scenes / props / products` 顶层入口**保持不变**，承载「项目全部资产」。
- 不删除、不合并侧栏入口；在侧栏文案或 tooltip 注明其与集页资产视图的「全集 / 子集」关系（可选微调 `AssetSidebar` 文案，见 §四 改动点 9）。
- 关系收口：**侧栏 = 全集（跨集），集页资产视图 = 当前集的子集**，两者共用同一份资产桶与同一份 `episode_referenced_assets`，无数据冗余。

### D-32 资产视图与制作进度面板 assets 行对齐

- 资产视图 tab 的资产图状态 marker（`GalleryStatusMarker`）与角标「待生成资产图 N」**复用** `WorkflowContent` 的 `referenced_assets_without_sheet` / `referenced_assets_without_description` / `referenced_assets_with_sheet_stale`（同一份 `_referenced_sheet_facts` 产出），与 `step-list.ts` 的 `assetsRow` 口径完全一致，不另算。
- 进度面板 `assets` 行可加跳转：点击直接进当前集 `?view=assets`，把「进度提醒」与「资产步骤」打通（改动点 8 可选）。

### D-33 资产视图可用性条件

- **依赖剧本（工厂源稿）**：`episode_referenced_assets` 在无剧本时返回空集；因此资产视图的可用性条件与 `board` 对齐——**有剧本（工厂源稿）时可用，无剧本时置灰**（与 `episodeViewTabs` 里 `board` 的 `disabled` 条件同源：见 episode-view.ts 行 80 注释「有脚本规划却还没有正式剧本时不可选」）。
- 工厂 / 短剧导入集：本集剧本即工厂 Markdown，同样可抽取（与 `hasShortDramaSource` 路径一致），资产视图照常可用。

### D-34 批量资产图生成入口复用

- 资产视图内复用 `AssetSheetBatchControls`（已挂在 `AssetGallery` 行 169），作用域限定为「本集引用且缺图」——即对 `scopeNames` 中 `status === "missing"/"stale"` 的条目批量生成 / 重生成资产图。这与 `asset_sheet_batch` 的 episode scope 计划（`load_asset_sheet_batch_plan`）天然对接。

### D-35 本集资产视图的 AI 生成描述，以「剧本（工厂源稿）> 故事规划」为统一三级优先级

- **决定**：集页资产视图内触发 AI 生成描述时，统一以 **剧本（工厂源稿）为最高优先级**、**故事规划（人物圣经 / 全剧大纲 / 连续性台账 / 分集规划）为次优先级**、题材补全兜底。剧本优先级最高的原因：其 `[人物]/[场景]/[道具]` 标记行（如 `沈昭｜藕荷色西装套裙`）**已自带外观描述**，是每集最贴合、最权威的描述来源；故事规划（人物圣经等）只补标记行没写到的跨集背景。集页视图与侧栏「全部资产」入口口径一致，**无需按视图翻转**——原方案「本集正式剧本 > 项目设定 canon」的 episode 翻转逻辑，因概念统一（剧本 ≡ 工厂源稿、故事规划 ≡ 原 canon 结构化）而消解。
- **实现落点**：
  - ai-fill 端点上下文搜集：顶块 = 本集剧本（工厂源稿）；第二块 = 故事规划四类文档；两块的读取与优先级排序在 `build_ai_fill_prompt` 内固定为「剧本 > 故事规划 > 题材补全」，不再依赖 `episode` 参数翻转。
  - 「剧本」即 `_collect_asset_context` 已扫描的 `source/short_drama/*.md` 剧本；「故事规划」即人物圣经 / 全剧大纲 / 连续性台账 / 分集规划，由统一的规划读取接口（`_collect_story_plan`）汇总。
  - 若代码层已落地的 `episode` 参数仅用于优先级翻转，可保留为 no-op 或直接清理（不影响功能）。


### D-36 一键「抽取 → 登记 → 生成图」合成一个请求

- **触发**：本集资产视图空有剧本（工厂源稿）+ 故事规划却没有已登记资产时（剧本/规划写了名字、资产表里没有），用户要的不是「去别处登记再来」，而是一个入口把三步走完。
- **决定**：新增 `POST /projects/{name}/episodes/{episode}/generate-assets`，服务端一次做完：
  1. **抽取**：由本集剧本（工厂源稿）的引用数组 / `[人物][场景][道具]` 标记行，以及故事规划（人物圣经角色清单、分集规划资产提及）读出名字，名字自带类型，因此可直接登记；写 `本体/衍生` 的只取本体。台词说话人与正文 `@[名称]` 不算——说话人可以是未登记的群演，正文记号只指认已声明的资产。
  2. **登记**：`register_missing_assets` 只补未登记的，已登记条目与其描述、资产图一律不动；名字被别的类型占着时记进 `conflicts` 不中断。落盘走 `update_project`（项目锁内重读 + 原子写），变更源标记 `webui`。
  3. **生成描述**：本集引用到、描述为空的资产，以 **工厂源稿标记行描述（基础）＋ 剧本上下文（强化）** 为主、故事规划补漏，由 ai-fill 规范写出 `description`（D-35）；标记行已有描述则强化而非重写，只填空字段；出图只对已生成描述的资产入队。N 个资产并发调模型、但只在一次项目锁里批量写回。
  4. **生成**：以 `AssetSheetScope(episode_id=episode)` 走既有 `load_asset_sheet_batch_plan` + `submit_asset_sheet_batch`，与画廊、Agent 的 `generate_assets` 同一份规划。
- **不预览**：本集引用只算已登记资产，未登记的名字读不出来，要给出名单与预估费用就必须先登记。登记是幂等的补条目（不覆盖、可删），先于确认执行是可接受的。
- **交互形态（单按钮 + 弹窗）**：**集页资产步骤页（`episodes/{episode}?view=assets`）顶部工具栏只暴露一个「生成本集资产」按钮**（不要工具栏 / 空状态各放一个，也不要放进某个 tab）。点击弹出的对话框口径见上文「页面入口与弹窗」一节：纯确认框——只读本批清单 + 取消 / 确定按钮，**不收集任何输入框**；点「确定」才真正发起 `POST .../generate-assets`（按工厂源稿标记行描述 + 剧本上下文 + 故事规划生成）。
- **第 3 步不可省**：资产图按描述出图，缺描述会被 `asset_description_required` 准入挡下。工厂源稿标记行已带外观描述，但它是零散原始文本，需 AI 强化规范成资产图可用的 `description`；不生成描述就是「登记了 N 个、出图 0 张」——把生成描述留在链路外等于把一键做成半截。（原记为 P14，现**已并入**，默认执行。）
- **回执**：`batch_id` + `members`（含 `task_id` / `status` / `problem_code`）+ `registered` + `conflicts` + `description_filled` + `description_fill_failed` + `without_description`。生成描述失败是**单资产**失败：不中断整批，该项仍进 `without_description`，界面如实提示，不静默吞掉。

## 五、问题（P-）与待拍板（R-）

**P10**：资产视图在**广告集**是否出现？广告集无 `plan`/`source`，剧本语义落在 `setting`，没有独立「剧本」步骤可供「之后插入」。本方案默认广告集不显示资产视图（D-28）；若产品希望广告集也支持逐集资产抽取，需另定插入位置（如 `setting` 之后）。

**P11**：资产视图是否纳入 **商品（product）** tab？当前 `episode_referenced_assets` 抽取覆盖 `character/scene/prop` 三类，与引用准入 `SHEET_REQUIRED_ASSET_TYPES` 一致；商品不在「剧本→分镜」资产准备链路内。本方案默认**不纳入 product tab**（D-30）；若需一并管理本集商品，需扩展抽取与 tab。

**P12**：资产视图的「批量生成资产图」是否直接复用 `AssetSheetBatchControls` 并限定本集作用域（D-34）？建议复用，但需确认 UI 上「本集批量」与侧栏「全部批量」的区分是否足够清晰。

**R22（已拍板）**：资产视图位置定在「剧本（source/脚本规划域）」之后、「分镜（grid/board）」之前；`grid` 作为分镜的子形态随分镜置于其后。

**R23（已拍板）**：保留侧栏独立「角色集 / 场景库 / 道具库」入口，语义为「项目全部资产」；与集页资产视图形成 **全集 / 子集** 的包含关系，二者共用同一份资产桶与 `episode_referenced_assets` 计算，不重复造数据。

**P13（已消解）**：原问「D-35 的优先级翻转是否也适用于全局 ai-fill」。本次优化统一「剧本（工厂源稿）> 故事规划 > 题材补全」三级优先级后，集页视图与全局口径一致，**无需任何翻转**，P13 不再构成待拍板项。

**P14**（**已决并落地**）：并入，且**默认执行、不做开关**。理由：不生成描述就无法出图，把生成描述留在链路外等于一键只完成前两步，用户还得逐个点「生成描述」再生成一次，逻辑上不成立。实现上生成描述依据为「本集剧本（工厂源稿）> 故事规划」优先级。代价（N 次文本模型调用）用并发上限 4 + 一次批量写回消化；失败按**单资产**处理——不中断整批，该项进 `description_fill_failed` 与 `without_description`。
  - **未做的部分**：「可勾选」UI 没做。生成描述是出图的前置条件而非可选项，开关只会让用户再踩一次「登记了不出图」的坑；若后续要控制成本，应在批量确认框里告知将调用 N 次文本模型，而不是给一个默认会导致失败的开关。

**P15**（新）：生成出来的描述要不要让用户**确认后再出图**？当前链路直接拿着生成结果入队，用户看到的是「已生成 N 个描述 + 已入队 M 张」的回执。优点是点击即走完；缺点是描述未经人眼、出图后才发现不对要重生成。若产品要求先审描述，需把链路拆成「登记 + 补全（可编辑）」与「确认后生成」两次请求。当前默认**不拆**。

**P16**（新）：**故事规划四类文档的存储位置与统一读取接口待定**。人物圣经（`character-bible.md`）/ 全剧大纲（`series-outline.md`）多已存在于 `source/short_drama/*.md`；连续性台账、分集规划可能是新增的项目级规划区（建议独立于工厂源稿，避免与逐集剧本混淆）。需明确：四类文档的落盘路径、由谁写入（用户编辑 / 导入生成）、以及统一的 `collect_story_plan` 加载器如何汇总，供 §2.2 抽取与 §2.8 ai-fill 共用，避免各处各读一份。
