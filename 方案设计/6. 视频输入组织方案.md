## 一、背景与触发

三条已定决策（截图确认）：

1. **参考生视频路线整体废止**（`reference_video`）。视频输入面收窄；但**参考音频能力保留**——音色复刻不退场。
2. **图片输入 = `start_image`（接续点）+ 连续的关键帧 + 尾帧（本镜终点）**：除接续点外，宫格各格按时间序进关键帧序列、末格进尾帧槽；**首帧槽放上一个分镜的尾帧**作接续点，保证视频生成的连续性；参考宫格图与视频提示词里的 `K0…Kn` 共用同一套编号。
3. **文本包含资产引用链接**：提示词除正文外携带对资产表条目的引用，主体参考图退场后由它承担资产身份锚点。

本方案把这几条决策落成可实施的输入组织：请求字段怎么填、图片槽位的语义、提示词与 K 编号怎么同源、门禁怎么拦、系统要改哪些地方。

## 二、现状核实（代码级）

### 2.1 统一契约与生产路线

所有视频生成——无论哪条路线——最终都收敛到同一个请求契约：

- 契约定义：`packages/arcreel-market-core/src/arcreel_market_core/video_backend_contract.py:282`（`VideoGenerationRequest`）
- 执行入口：`MediaGenerator.generate_video_async`（`lib/generation/media_generator.py:791`）

生产侧只有两个调用点；另有一条上传旁路不经过生成：

| 路线 | 调用点 | 项目 `generation_mode` | 任务桶 |
| --- | --- | --- | --- |
| 分镜生视频（首帧驱动） | `server/services/tasks/generation_tasks.py:1332` | `storyboard` | i2v |
| 参考生视频（本文废止） | `server/services/tasks/reference_video_tasks.py:639` | `reference_video`（无参考图时降级 i2v） | r2v / i2v |
| 旁路：手动上传视频 | `server/services/currency/upload_finalize.py:253` | —（raw-only：保留原文件、不生成、不登记派生产物） | — |

内容上游：上传的源稿（txt/md/docx/epub/pdf，`lib/script/source_loader/`）或短剧工厂工件（`lib/short_drama_ingest.py`）→ 规划成剧本（segments/scenes/video_units）→ 角色/场景/道具/商品资产表 + 分镜图/宫格图（图像生成）→ 本文的视频输入。

### 2.2 请求字段清单（今天实际下发）

| 通道 | 字段 | 说明 |
| --- | --- | --- |
| 文本 | `prompt` | 唯一必填内容输入；两条路线各自的渲染出口产出；**含资产引用链接**（对资产表条目的指认，参考生视频路线以 `@图片N` / `@音频N` 承载主体与音色绑定） |
| 图片 | `start_image` / `end_image` / `reference_images` | 首帧 / 尾帧 / 参考图数组 |
| 音频 | `reference_audio_files` / `reference_audio_targets` | 音色复刻段（顺序即 prompt 中「音频N」指认契约）；后者为音频↔参考图下标绑定，仅 per-image 后端需要 |
| 参数 | `aspect_ratio` / `duration_seconds` / `resolution` / `generate_audio` / `seed` / `service_tier` / `poll_timeout_seconds` | 未设置则不下发 |
| 执行上下文 | `output_path` / `project_name` / `task_id` / `execution_endpoint` / `submitted_base_url` | 自定义供应商续跑用 |

### 2.3 分镜路线的输入怎么来（保留路线）

- **提示词**：剧本条目的 `video_prompt`（结构化 YAML / 纯文本 / `shot_sequence` 多镜头三种形态），经 `render_storyboard_video_prompt`（`lib/prompts/prompt_utils.py:251`）统一渲染；drama 模式按分镜级 `utterances` 注入台词与 Voice_Profiles（取自角色资产的 `voice_style`）；有宫格时追加「Keyframe references K0–Kn」时序声明。
- **首帧图**：宫格首格（`start_cell`）；无宫格取分镜图。
- **尾帧图**：条目 `end_frame_image` 或宫格格位（`end_cell`）。
- **参考图**：宫格切图 `shot_grid.cell_paths` 全量（K0…Kn）。

### 2.4 参考生视频路线的输入怎么来（废止路线）

- **提示词**：unit 正文 `text` 三段论渲染（`lib/script/reference_video/prompt_render.py`）：① `<X>@图片N` 主体绑定 + `@音频N` 音色声明（含声音特征）；② 正文 + `<X>说 {台词}`（无归属旁白整段丢弃，走 TTS）；③ 共享风格块 + `Avoid` 负向约束 + 商品高保真声明 + 多角色同帧排除。
- **参考图**：正文 `@[名称]` mention 按首现顺序派生，经 reference catalog 展开为资产表图（角色/场景/道具/商品的 sheet 图；商品无 sheet 时可退原图，其余类型缺图即阻断），按后端 `max_reference_images` 裁剪。
- **参考音频**：角色参考音频文件（`characters/refs_audio/`），顺序 = 台词 speaker 首现顺序。

### 2.5 付费前的硬门禁

`gate_video_request`（`lib/backends/video_frame_slots.py:105`）对每次请求校验：prompt 字符上限、纯文生能力、尾帧支持、参考图数量、参考音频段数与总时长——违约一律硬失败，不静默降级。供应商/模型由 `ConfigResolver` 按任务桶（i2v/r2v）解析，能力（时长档、音轨形态、参考图/音频上限）以实际 backend 身份求值（ADR 0086）。

### 2.6 两处现存问题（新组织要修掉）

**P8 已确认宫格：K0 与 Kn 各下发两次。** confirm 写 `video_reference_mode: "start_end_cells"`（`server/routers/shot_grids.py:425`），`resolve_storyboard_video_inputs` 据此取 `start_cell=0` / `end_cell=count-1`（`lib/script/storyboard_sequence.py:168`）；而 `resolve_storyboard_video_reference_images` 把**全量格**放进参考数组（`storyboard_sequence.py:117-150`）。同一张 K0 既是首帧又是第 1 张参考图，Kn 既是尾帧又是最后一张参考图；声明段还说 "correspond to the 4 reference images"——槽与数都对不上。新组织下每格只占一个槽——非首镜：K0 进参考数组打头、K1…K(n-1) 随后、Kn 进尾帧槽，首帧槽让给上一镜尾帧；首镜：K0 进首帧槽、K1…K(n-1) 进参考数组、Kn 进尾帧槽（D-23 / D-24），重复下发消除。

**P9 无宫格：同一张分镜图同时作首帧与唯一参考图。** 无宫格时 `resolve_storyboard_video_reference_images` 返回 `(storyboard_file,)`（`storyboard_sequence.py:150`）；worker 路径暂存时虽按「单张且等于分镜图则跳过」过滤（`generation_tasks.py:1217` 附近），但随后 `or list(reference_images)` 的回落又把它放回请求（`generation_tasks.py:1343`）。后果不只是多传一张图：首帧型后端（`max_reference_images=0`）会被 `gate_video_request` 以 `video_reference_images_unsupported` 硬拒（`video_frame_slots.py:160-163`）——没有宫格的分镜在这些模型上根本生不出视频。

## 三、新路线的输入组织

### 3.1 D-22 参考生视频路线整体废止（音频能力保留）

视频输入面收窄，但**参考音频能力保留**。

- **随路线退场的输入**：主体参考图（资产表图按 mention 首现序进 `reference_images`）、三段论渲染、`@图片N` 主体绑定——它们只属于参考生视频。
- **保留**：`reference_audio_files` / `reference_audio_targets`（音色复刻，D-25）；TTS 旁白配音链路、`generate_audio`（成片音轨开关）、`utterances` / `Dialogue` / `Voice_Profiles`。**废止参考生视频不等于废止配音，也不等于废止音色复刻。**
- 存量 `reference_video` 项目的处置见 **R20**，不在本方案范围；本文只定 storyboard 路线怎么填这份统一请求。

### 3.2 判定表：同一份 `VideoGenerationRequest`，新路线怎么填

| 请求字段 | 参考生视频（废止） | 分镜路线现状 | 新路线 |
| --- | --- | --- | --- |
| `prompt` | 三段论渲染（`@图片N` 主体绑定 + `@音频N` 音色声明 / 正文 / 风格块） | `render_storyboard_video_prompt` 输出 | 同现状；**含资产引用链接**（D-27） |
| `start_image` | 不用 | 已确认宫格 = 首格 K0；无宫格 = 分镜图 | **接续点：上一个分镜的尾帧**（首镜回落 K0 / 分镜图；D-24） |
| `end_image` | 不用 | 已确认宫格 = 末格；或条目 `end_frame_image` | **本镜末格 Kn**（`cell_paths[-1]`；无宫格、首镜仅一格不设） |
| `reference_images` | 主体参考图（资产表图，mention 序） | 全量格 K0…Kn；无宫格 = [同一张分镜图] | **连续关键帧**：非首镜 K0…K(n-1)（`cell_paths[:-1]`）、首镜 K1…K(n-1)（`cell_paths[1:-1]`）；无宫格 / 仅一格为空 |
| `reference_audio_files` / `reference_audio_targets` | 角色音色文件 | 不用 | **保留**（D-25；能力不退场） |
| `aspect_ratio` / `duration_seconds` / `resolution` / `generate_audio` / `seed` / `service_tier` | 用 | 用 | 同现状 |

图片输入的组织因此收敛为一句话：**`start_image`（接续点）+ 连续的关键帧 + `end_image`（本镜末格）**——非首镜的时间线是「上一镜尾帧 → K0 → … → K(n-1) → Kn」，首镜把 K0 放进首帧槽（D-23 / D-24）。宫格图与视频提示词都照这一组织对齐——除接续点与末格外，各格按序进关键帧序列；视频提示词里的 `K0…Kn` 引用同一套编号（D-17 / D-26）。

> 参数行口径不变。个别后端在带首帧时把 `aspect_ratio` 改写为 `adaptive`（`resolve_first_frame_aspect_ratio`），属后端适配，不改变本表的组织。

### 3.3 D-23 图片输入固定两槽 + 尾帧槽（三槽分工）

**`start_image` = 接续点（上一镜尾帧），`reference_images` = 连续关键帧，`end_image` = 本镜末格 Kn。**

- 派生只认 `cell_paths` 的顺序：末格 `[-1]` 进尾帧槽，其余进关键帧序列，接续点进首帧槽；不再读 `start_cell` / `end_cell` / `video_reference_mode`，`storyboard_sequence.py` 的 `start_end_cells` 读取分支与 confirm 写的这三个字段一并退场。
- 接续点（首帧槽）按镜头位置分两种：**非首镜** = 上一个分镜的尾帧（D-24），**首镜** = 本镜 K0（`cell_paths[0]`；无宫格取 `storyboard_image`）。关键帧序列因此是非首镜取 `cell_paths[:-1]`（K0 打头）、首镜取 `cell_paths[1:-1]`（K1 打头）——每格仍只占一个槽。
- 无宫格：只发首帧（非首镜 = 上一镜尾帧，首镜 = 分镜图），关键帧与尾帧槽都为空；只有一格：非首镜发首帧（上一镜尾帧）+ 尾帧（K0），首镜只发首帧（K0，尾帧省略避免与首帧同图）。P9 的重复与首帧型后端的误拒由此消除。
- `reference_images` 的语义从此是「连续关键帧（时间锚定）」，不再是「主体参考图（身份锚定）」——同名不同物，声明段与准入口径都按后者重写（D-26）；身份锚点改由提示词中的资产引用链接承载（D-27）。

### 3.4 D-24 首帧槽锚上一镜尾帧（接续点），尾帧槽锚本镜末格 Kn

上一镜尾帧进 **`start_image`**（供应商首尾帧模式的通行语义：首帧 = 接续点；R21 已定），`end_image` 锚**本镜末格 Kn**。

- 接续点来源按优先级：上一镜**成片的实际尾帧**（已成片时连续性最强）→ 上一镜 `end_frame_image` 尾帧快照 → 上一镜宫格末格；都无则回落本镜 K0 / 分镜图，连续性降级但不阻断。
- 首镜没有上一镜：`start_image` 回落本镜 K0（宫格）或分镜图（无宫格）。
- 本镜的 `end_frame_image` 快照消费方从「本镜视频」改为「**下一镜**视频」——且进的是下一镜的 `start_image`（接续点），不再是 `end_image`。
- **生产端链路（现状核实，实现时不变）**：分镜卡片「尾帧」折叠行（`frontend/src/components/canvas/timeline/EndFrameRow.tsx:178`，摘要读 `segment.end_frame_image`）经三个端点（`api.ts:1943-1980`：upload / select / clear）落到 `server/services/project/end_frame.py`——快照复制为 `end_frames/scene_{id}.png`（原地覆盖），字段写在**本镜**剧本条目的 `end_frame_image`（顶层字段，刻意不进 `generated_assets`；通用 PATCH 白名单不含它，防悬空引用）。今天它喂本镜视频请求的 `end_image`（`generation_tasks.py:1086` → `storyboard_sequence.py:198-219` → `generation_tasks.py:1175/1337`；宫格 `start_end_cells` 模式下被 `end_cell` 旁路）。新路线只改消费方：UI、字段、快照路径全部保留，界面上「尾帧」的语义建议改注为「本镜尾帧（作下一镜首帧接续点）」。
- 时间线（非首镜，多格）：上一镜尾帧 → K0 → K1 → … → K(n-1) → Kn，每一帧只占一个槽；首镜特例（K0 进首帧槽）见 3.3。

### 3.5 D-25 主体参考图退场，参考音频保留

- **退场的只有主体参考图**（资产表图按 mention 首现序进 `reference_images`）——资产身份锚点改由提示词中的**资产引用链接**承载（D-27）；`reference_images` 只承载时间序列（D-23）。
- **参考音频保留**：`reference_audio_files` / `reference_audio_targets` 不随参考生视频废止而退场；音色复刻能力继续可用，角色参考音频（`characters/refs_audio/`）与 prompt 中「音频N」的顺序指认契约不变。台词、旁白同样保留——经提示词文本与 TTS 链路交付。

### 3.6 D-26 K 声明段与实际下发同源；关键帧超限直接报错

- 措辞按新组织描述「接续点 + 关键帧 + 结尾帧」（草案见 3.8），枚举的编号必须是**实际下发**的那些。
- 形态（按镜头位置 × 宫格规格）：

| 形态 | 图片请求 | 声明段 |
| --- | --- | --- |
| 多格宫格 · 非首镜 | `start_image`=上一镜尾帧，`reference_images`=[K0…K(n-1)]，`end_image`=Kn | 接续句 + 关键帧 K0–K(n-1) + 结尾帧 Kn |
| 多格宫格 · 首镜 | `start_image`=K0，`reference_images`=[K1…K(n-1)]，`end_image`=Kn | 首帧 K0 + 关键帧 K1–K(n-1) + 结尾帧 Kn |
| 仅一格 · 非首镜 | `start_image`=上一镜尾帧，`end_image`=K0，参考为空 | 结尾帧 K0 |
| 仅一格 · 首镜 | `start_image`=K0，参考与尾帧均为空 | 无（或仅「K0 首帧」） |
| 无宫格 | `start_image`=上一镜尾帧（首镜 = 分镜图），其余为空 | 无 |
| 关键帧超后端上限 | —（入队即报错，无下发） | — |

> 接续点（上一镜尾帧）与宫格形态正交：非首镜且有来源时进 `start_image`，首镜回落 K0；声明段对非首镜需说明首帧是上一镜的结尾（接续句）。`end_image` 恒为本镜末格 Kn，随宫格规格变化。

- 正文 K 引用校验（D-17 的 `keyframe_reference_problems`）：每格都被下发到某个槽（首帧 / 参考 / 尾帧），判据「`n < 格数`」继续有效；无宫格（格数 0）时任何 K 引用都非法——文本承诺与请求载荷不允许再分叉。
- **关键帧数超过后端上限：直接报错**（R18 定论），不做等距抽样、截尾等任何收窄；报错文案引导改规格或换模型（见五）。

### 3.7 D-27 提示词文本包含资产引用链接

- 文本通道除画面 / 运镜 / 环境音 / 台词正文外，携带对资产表条目的**引用链接**：主体参考图退场后（D-25），资产身份与风格锚点经文本侧的资产引用交付。
- 参考生视频时代的 `@图片N` / `@音频N` 指认契约不复存在；新路线下资产引用以「资产条目链接」形态进入下发文本，具体格式随渲染出口定稿，与 R19 的英文措辞一并实测。
- 与 K 编号的分工：资产引用链接承载**身份**锚点（谁 / 什么），K 编号承载**时间**锚点（哪一帧）——两条锚点线同在提示词内，互不替代。

### 3.8 下发形态：K 声明段

非首镜（多格）：

```
The first frame is the ending frame of the previous shot; continue from it. K0 is the opening frame of this shot. The reference images are K0–K{n-1} in their supplied order: the consecutive keyframes from the opening through to the penultimate moment. The final keyframe K{n} is supplied as the last frame. Follow this temporal order and preserve character, setting and action continuity.
```

首镜（多格）：

```
K0 is the opening frame of this shot, supplied as the first frame. The reference images are K1–K{n-1} in their supplied order: the consecutive keyframes that follow. The final keyframe K{n} is supplied as the last frame. Follow this temporal order and preserve character, setting and action continuity.
```

> 英文措辞是草案，按供应商对 "first frame / keyframe / last frame" 的实际响应定稿（R19）；中文界面不出现这段，它只存在于下发文本。R21 已定为通行语义版（首帧 = 接续点、尾帧 = 本镜末格 Kn），故关键帧编号为非首镜 K0–K(n-1)、首镜 K1–K(n-1)，结尾帧 Kn 单独一句——与 `end_image` 一致。

### 3.9 与视频提示词的关系

- 视频提示词里的 `K0…Kn` 引用（D-17）与图片请求的槽位是同一套编号，且每格都被下发：非首镜 K0 在参考数组打头、Kn 在尾帧槽、首帧槽是上一镜尾帧；首镜 K0 在首帧槽、K1…K(n-1) 在参考数组、Kn 在尾帧槽。
- 连续性由两个槽表达：`start_image` 锚上一镜尾帧（接续点），`end_image` 锚本镜末格 Kn（D-24）——首镜的 `start_image` 回落 K0 / 分镜图。
- 资产引用链接（D-27）与 K 编号（D-17）分别承载身份与时间锚点；`<keyframes>` 块（D-15）仍是写 `action` 用的文本代理，不改变图片请求的组织。
- 「查看提示词」抽屉展示的下发全文里，这段声明与槽位一一对应。抽屉和编辑器形态由《5. 视频提示词独立步骤生成设计》定义；本方案只要求最终下发文本与图片槽位一致。

### 3.10 最终下发顺序（一次视频请求的完整时序）

R21 已定（通行语义版：首帧 = 接续点、尾帧 = 本镜末格 Kn）：

| 序 | 请求字段 | 内容 | 来源 |
| --- | --- | --- | --- |
| 1 | `prompt` | 渲染后的正文：分段动作/运镜/环境音 + 台词 + **资产引用链接** + K 声明段 | `render_storyboard_video_prompt`（D-27 / D-26） |
| 2 | `start_image` | **上一个分镜的尾帧**（接续点） | 上一镜成片实际尾帧 → 上一镜 `end_frame_image` 快照 → 上一镜宫格末格；首镜回落本镜 K0 / 分镜图 |
| 3 | `reference_images` | **连续关键帧**：非首镜 K0…K(n-1)、首镜 K1…K(n-1) | 宫格 `cell_paths[:-1]`（首镜 `[1:-1]`）；无宫格 / 仅一格为空数组 |
| 4 | `end_image` | **本镜末格 Kn** | 宫格 `cell_paths[-1]`；无宫格、或首镜仅一格（与首帧同图）不设 |
| 5 | `reference_audio_files` / `reference_audio_targets` | 角色参考音频（音色复刻） | `characters/refs_audio/`，顺序 = prompt「音频N」 |
| 6 | 参数 | `aspect_ratio` / `duration_seconds` / `resolution` / `generate_audio` / `seed` / `service_tier` | 同现状口径 |

「本镜尾帧」的两跳落地：用户在尾帧行设置 → 落在**本镜**剧本条目字段 `end_frame_image`（快照 `end_frames/scene_{id}.png`，§3.4 生产端链路）→ 被**下一镜**的视频请求取进第 2 行 `start_image` 槽。

时间线（非首镜，2×2 示例）：`上一镜尾帧 → K0 → K1 → K2 → K3`——五帧分别落 首帧槽 / 参考数组×3 / 尾帧槽，每帧只占一个槽。

边界形态：

- **首镜（多格）**：第 2 行 K0、第 3 行 K1…K(n-1)、第 4 行 Kn；
- **首镜仅一格**：只发第 2 行 K0（尾帧省略，避免与首帧同图）；
- **无宫格的非首镜**：只发第 2 行（上一镜尾帧），第 3、4 行为空；
- **无宫格的首镜**：只发第 2 行（分镜图），第 3、4 行为空。

## 四、视频提示词消费口径

本步骤不生成或编辑 `video_prompt`，只消费上一环节已经写入视觉制作状态的提示词。

消费规则：

- `video_prompt` 为空时，视频生成准入失败，不入队、不计费。
- `video_prompt` 可以是结构化对象或兼容字符串，统一由 `render_storyboard_video_prompt` 渲染。
- drama 模式的台词来自分镜 `utterances` 与角色声音资产，由渲染层注入；`video_prompt.action` 不负责改写台词。
- `video_prompt` 中出现的 `K{n}` 必须落在当前已确认参考素材的格数范围内；越界时阻断视频生成。
- `video_prompt_basis` 过期时页面提示建议重写，但本步骤仍以当前宫格图片组织请求；是否允许继续提交由产品准入口径决定。

## 五、门禁与准入口径更新

- K 引用越界：`video_prompt_keyframe_out_of_range`，整条不落盘；视频准入在计费前再拦一次。
- 关键帧数超后端上限：**直接报错**（R18 定论），不做收窄——入队期与计费前各拦一次，文案「该模型最多 N 张关键帧，3×3 请改 2×2 或换模型」。卡的是参考数组长度：3×3 非首镜 = 8 张关键帧（K0–K7）+ 尾帧 K8，首镜 = 7 张（K1–K7）+ 首帧 K0 + 尾帧 K8；`gemini.max_reference_images=3` / `grok=7`。
- `gate_video_request` 的参考图数量校验按「实际下发的关键帧数」求值；音频段数 / 总时长校验继续有效（D-25 保留参考音频）；尾帧支持校验继续有效（D-24 保留 `end_image` = 本镜末格 Kn）。

## 七、待拍板

- **R19 K 声明段英文措辞与资产引用链接格式定稿**：3.8 的草案需按供应商对 "first frame / keyframe / last frame" 的实际响应实测后定稿；这段措辞属下发契约，不随版本漂移。
- **R20 存量 `reference_video` 项目的处置（已定）**：保留数据读取、归档、已有剪辑和已提交付费任务恢复；关闭全部新生产入口。不改写旧模式字段，不自动迁移为工厂项目，不从旧 JSON 生成七类工件。重新制作须创建工厂项目并提供完整工件。

已定记录：

  | --- | --- | --- |

## 八、Considered Options

- **保留 `end_image`（尾帧）槽**：**采纳，内容锚本镜末格 Kn**（`cell_paths[-1]`）；上一镜尾帧另进 `start_image` 作接续点（R21 定：首帧 = 接续点）。first_last 型后端（可灵 / Vidu 首尾帧模式）的首尾表达因此变为「上一镜尾帧 → 本镜 K0 起、Kn 收」——时间线连续、无倒挂；两槽都不与参考数组重复（P8 不复发）。
- **K0 同时进首帧槽与参考数组**：同一张图下发两次，声明段还要为此多一句辩解；无宫格时今天正是这么重复的（P9）——放弃，参考数组只放 K0 之后的连续关键帧（D-23）。
- **关键帧超限时静默裁掉**：裁哪几帧直接决定声明段与正文 K 引用是否还对得上，静默裁剪等于把「文本承诺」与「请求载荷」重新拆开——不静默；**超限直接报错**（R18 定论），声明与准入都不做收窄分支。
- **三段论提示词降级为纯文本保留**：其主体绑定（`@图片N`）依赖的主体参考图已退场（D-25），音色声明（`@音频N`）因参考音频保留（D-25）另行安置——路线既废，渲染无从谈起；资产身份改由文本资产引用链接承载（D-27）。

## 九、Consequences

**正向**

- 视频输入面收窄：主体参考图退场（D-25）、三段论渲染随之退场；**参考音频保留**（D-25）；资产身份锚点迁到提示词的资产引用链接（D-27）。
- 修掉两处重复下发：已确认宫格下 K0 与 Kn 各占两个槽（P8）、无宫格时同一张分镜图兼作首帧与唯一参考图（P9）；后者还连带修掉一个隐性硬拒——首帧型后端（`max_reference_images=0`）今天会把没有宫格的分镜整个挡在生成外。
- 声明段从「4 张参考图」改写为「首帧 + K1–Kn 关键帧」：文本承诺与请求载荷的对齐，从「靠约定」变成「靠结构」（D-26）。
- 跨镜连续性：非首镜的视频都从上一镜尾帧接续（`start_image`，D-24 / R21），本镜以末格 Kn 收尾（`end_image`）；尾帧快照的消费方从本镜改为下一镜。

**负向 / 代价**

- 接续点依赖上一镜的尾帧来源（成片实际尾帧 > `end_frame_image` 快照 > 上一镜宫格末格）；都无时回落本镜 K0，连续性降级但不阻断。首镜仅一格时尾帧需省略（与首帧同图），实现时注意去重。
- 超限直接报错（R18 定论）会把「3×3 + gemini（3 张关键帧）」这类组合挡在入队期，用户必须改规格或换模型——这是放弃静默收窄的代价。
- 参考生视频的既有实现（任务、渲染、catalog）进入废止流程，存量项目在 R20 有结论前处于「能看不能产」的中间态。
- K 声明段英文措辞与资产引用链接格式在 R19 定稿前属「按草案下发」，供应商侧行为需实测兜底。
