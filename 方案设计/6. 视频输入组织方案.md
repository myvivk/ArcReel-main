# 6. 视频输入组织方案

> 分镜视频固定使用 reference/r2v：唯一动态提示词 + 引用资产图 + confirmed K 帧。

## 一、请求契约

视频请求只有一种图片组织方式：

```text
prompt = 当前 image_prompt 的确定性渲染结果 + utterances / 声音约束
reference_images = 角色资产图 → 场景资产图 → 道具资产图 → K0 → … → Kn
```

不下发 `start_image` 或 `end_image`，不接受 `first_last`，前端、HTTP 和 Agent 均不暴露 `frame_mode`。

## 二、准入前提

每个分镜必须同时满足：

1. `image_prompt` 非空。
2. 动态提示词通过镜头格式、资产 token、连续时间轴、四层制作信息和 K 前向引用校验。
3. 分镜绑定完整 confirmed ShotGrid。
4. `cell_paths` 非空且所有图片可读。
5. 引用资产满足项目引用准入。
6. 项目当前视频供应商支持 r2v。
7. 实际参考图数量、视频时长、音频数量和音频总时长满足模型能力。
8. 源稿、视觉状态和 Artifact Manifest 输入认领仍为当前版本。

批量请求是全有或全无：任一目标不满足时整批零入队、零计费，并返回逐 ID 问题。

## 三、参考图顺序与上限

资产图从分镜结构化清单读取，而不是扫描提示词文本：

1. `characters_in_scene` 对应的角色资产图。
2. `scenes` 对应的场景资产图。
3. `props` 对应的道具资产图。
4. confirmed ShotGrid 的 K0…Kn。

同类资产保持清单顺序，缺图资产按引用准入规则处理。K 帧优先占用 `max_reference_images`：

- K 帧数量超过上限：拒绝请求，提示改小宫格或更换模型。
- K 帧未超过上限：剩余名额按角色 → 场景 → 道具顺序保留资产图。
- 被上限裁掉的资产图记录 warning；K 帧不裁剪。

准入、预览和 worker 共用同一投影函数，编号、计数和实际发出的文件必须一致。

## 四、提示词渲染

`render_storyboard_video_prompt` 是最终请求文本的唯一出口。输入正文来自 `image_prompt`，不读取历史 `video_prompt`。

渲染层只做确定性包装：

- 按实际 `reference_images` 生成引用编号和模型要求的语法。
- 注入 `utterances` 的逐字台词。
- 按角色配置注入声音风格或参考音频声明。
- 注入资产链接和必要的负向约束。
- 按当前供应商的 `VideoPromptSpec` 调整包装格式，不改写剧情事实和动态正文。

提示词预览、批量准入、执行任务和产物摘要使用同一渲染出口。

## 五、声音输入

- 台词与画外音来自 `utterances`，不从动态提示词反解析。
- 参考音频按台词 speaker 首次出现顺序去重。
- 需要 per-image 绑定时，只绑定到有明确角色证据的 K 帧。
- 音频开关、数量、时长和供应商能力在准入与执行前再次校验。
- TTS 不阻塞视频生成；后期配音项目可以只生成无声视频。

## 六、执行与并发复核

任务入队只保存请求快照；worker 开工后从当前正式分镜重新物化：

- 当前 `image_prompt`。
- confirmed ShotGrid 与 K 帧。
- 当前引用资产图。
- 当前 `utterances`、角色声音配置和参考音频。
- 当前供应商、模型、时长与分辨率能力。

付费提交前复核源稿身份、Artifact Manifest 输入认领、全部图片 SHA、声音文件 SHA 和最终渲染文本。任一输入变化都拒绝本次提交，不能按旧快照继续计费。

## 七、产物时效

视频视觉 basis 至少包含：

- 唯一动态提示词的最终渲染文本。
- 实际发送的全部 `reference_images` 及内容摘要。
- ShotGrid ID、规格、联系表摘要和 K 帧编号证据。
- 供应商、模型、分辨率、时长、seed 与音频开关。
- `utterances`、声音风格、参考音频与绑定关系。

以下变化使视频 stale：

- `image_prompt` 变化。
- confirmed ShotGrid 或任一 K 帧变化。
- 实际发送的资产图变化。
- 影响请求的声音、模型或执行配置变化。

历史 `video_prompt_basis` 不参与新时效判断。

## 八、界面与 API

- 视频生成弹窗展示最终请求预览，但不允许编辑提示词。
- 弹窗只保留声音、模型、时长、seed 等合法生成配置。
- 单条和批量 HTTP 请求不接受 `frame_mode`。
- Agent `generate_videos` 不接受 `frame_mode`。
- 缺动态提示词或 confirmed 宫格时，按钮与服务端准入都拒绝。

## 九、验收标准

1. 所有分镜视频请求都走 r2v 能力桶。
2. `reference_images` 顺序稳定为资产图在前、K 帧在后。
3. K 帧优先占用上限，资产裁减有 warning，K 帧超限直接拒绝。
4. 预览、准入、执行和产物证据中的图片列表与提示词编号逐项一致。
5. 历史 `video_prompt` 内容不会改变或阻断新请求。
