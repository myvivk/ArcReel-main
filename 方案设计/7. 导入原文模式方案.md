# 7. 导入原文模式方案

> 状态：待 review（本文件只描述设计，不含实现）
> 范围：新建项目双模式（AI 原创 / 导入原文）、导入原文的剧本生成链路、剧本页原文/剧本双视图、页面入口收敛。
> 不在本方案内：整本小说自动拆集、系列级人物圣经/大纲/台账、工厂质量闭环（作为交付门槛）。

## 零、结论先行

新增**项目级不可变字段 `creation_mode`**（`ai_original` / `source_import`），它只决定两件事：

1. 入口：`source_import` 项目隐藏「故事规划」页与「AI 原创剧本 / 故事规划」按钮，剧本页给「导入原文」。
2. 剧本来源：`source_import` 项目的剧本由用户粘贴/编辑的原文，经**服务端强文本模型**改写生成，落盘到现行唯一真相源 `source/short_drama/episodes/episode_NN.md`。

**改写结果的格式不是新格式，而是逐字适配现有剧本结构（硬要求）**：必须能被 `parse_short_drama_episode` 完整解析，进而被 AI 分镜转成 `scenes[]`、资产抽取、工作流状态消费。任何偏离都视为实现缺陷，不是"可接受差异"。

跨集一致性沿用 huobao 的**项目级资产池**思路（不是把人物圣经塞进改写）：每集在资产步骤把剧本声明里的角色/场景/道具登记进 `project.json`（只补缺失、不覆盖），下一集改写时注入「资产池 + 前序集声明」，画面一致仍由资产参考图跨集复用来兜。

一句话数据流：

```text
粘贴/编辑原文（剧本页内联输入框，非弹窗）
  → 服务端 TextGenerator（SCRIPT → COMPLEX 档）按工厂单集格式改写
  → 结构校验（阻塞）+ 机检（仅告警）+ 返修 1 轮
  → source/short_drama/episodes/episode_NN.md + source/episode_NN.txt（OWN 源登记）
  → 剧本声明 → 资产步骤补登记资产池（只补缺失）→ 下一集改写注入「资产池 + 前序集声明」
  → 资产页出资产图 → AI 分镜 → K 帧 → 视频 → 剪辑（全部沿用现链路）
```

### review 结论（已确认）

| ID | 结论 |
|---|---|
| R-1 | **按集导入**：每集剧本页粘贴该集原文；整本自动拆集不做 |
| R-2 | **机检不阻塞**：只告警 + 返修；结构校验才阻塞 |
| R-3 | **要「原文 / 剧本」切换**；原文可编辑；保留「重新导入」，重导前提示风险 |
| R-4 | **模式不可变** |
| R-5 | **单集原文 5 万字上限** |

## 一、背景与目标

### 1.1 用户诉求

- 新建项目提供两种模式：**AI 原创**（现状）与**导入原文**（新增），两种模式相互独立。
- 导入原文项目：页面不要故事规划；去掉「AI 原创剧本」「故事规划」按钮。
- 数据流程不变（剧本 → 资产 → 分镜 → 剪辑）；只是剧本不再由剧本工厂生成：剧本页提供「导入原文」按钮，点开出现**内联输入框（不要弹窗）**，粘贴原文后点确定生成剧本。
- 原文 → 剧本的写法借鉴 [huobao-drama](https://github.com/myvivk/huobao-drama)。

### 1.2 目标

1. 项目创建即可区分两种模式，AI 原创项目行为、数据、入口零变化。
2. 导入原文项目一次粘贴完成单集剧本生成，产出与工厂源稿同格式、可被现有解析器消费。
3. 模式差异只体现在入口与剧本来源，不出现第二套资产/分镜/剪辑实现。

### 1.3 非目标

- 整本小说自动分集、跨集人物圣经/大纲/台账、工厂质量闭环（机检 + 合规 + 医生精修）。
- 导入原文项目的富文本剧本编辑器（剧本只读；原文可编辑，重新导入重生成）。
- AI 原创项目改用新写法（继续走 Agent + short-drama-factory）。

### 2.1 huobao-drama 的真实做法

只读分析结论（HEAD `7bb6191`）：

- 它**没有**故事分析/自动分集/结构化 JSON 阶段；4 个 Mastra Agent（剧本改写、资产提取、分镜拆解、提示词）靠 tool-calling 直接读写 SQLite。
- 原文 → 剧本是**按集**的：用户在某一集粘贴原文写入 `episodes.content`，`script_rewriter` 读取后整段改写，`save_script` 写回 `episodes.script_content`；集由用户手动创建，不存在「整本拆集」。
- 剧本格式是文本 DSL：`## S01 | 内景 · 地点 | 时间`、动作自然段、`角色名：（表情）台词`；明确禁止写镜头语言。
- 跨集一致性怎么来的：**不是靠剧本改写 Agent 的上下文**（`read_episode_script` 只返回本集原文，见 `script-tools.ts:12-26`），而是靠**项目级资产池**——每集由用户点「提取资产」（`doExtract` → `POST /episodes/:id/extract`）时运行 `extractor`：先 `read_existing_characters/scenes/props`，按归一化名字去重、同名合并（已有 `appearance`/`styling` 不被覆盖，见 `extract-tools.ts:202-215`），并建立「集 ↔ 资产」关联；分镜时 `read_storyboard_context` 把资产外观回传给分镜 Agent；真正的画面一致靠资产参考图跨集复用。
- 它的坑：无分集/无大纲（**剧情层面**无跨集记忆）、时长硬编码 30–60 秒、prompt 是唯一约束（没有结构校验与返修）、重跑会删掉已生成视频。

关键位置：`backend/workspace/prompts/script_rewriter.md:6-19`、`backend/workspace/skills/script-rewriter/SKILL.md:10-56`、`backend/src/routes/episodes.ts:13-52`、`backend/src/agents/tools/script-tools.ts`。

## 三、核心设计决定

### D-1 新增项目级不可变字段 `creation_mode`

- 取值：`ai_original`（默认，存量与新项目） / `source_import`。
- 只表达「剧本从哪里来」，不参与 `content_mode`（内容类型）与 `generation_mode`（视频来源）的任何判定。
- 创建后不可变：`CreateProjectRequest` 接收，`UpdateProjectRequest` 不接收。
- 校验落点：`DataValidator` 新增字段校验；`create_project_metadata` 只接受合法值并写盘。

为什么不复用 `content_mode`：它是跨骨架、跨校验、跨提示词的枚举（`drama/narration/ad`），新增取值会牵动骨架解析、提示词分支、供应商能力、归档校验；本需求不改内容类型，只改剧本来源。

### D-2 输出严格适配现有剧本结构（硬要求）

- 输出必须是工厂单集 Markdown（§6.2 契约），由 `parse_short_drama_episode` 解析为 beats，再由 AI 分镜转成 `scripts/episode_N.json` 的 `scenes[]`。
- **不新增剧本格式、不直接写 `scripts/episode_N.json`**。直接写 JSON 会绕过 AI 分镜的 beat 分组、资产解析、时长与画面规划，等于另开一条视觉链路，违背「后续流程不变」。
- 路径沿用 `source/short_drama/episodes/episode_NN.md`（唯一真相源）。

### D-3 按集导入（R-1）

- 每集剧本页（`?view=source`）在无源稿时展示内联「导入原文」面板。
- 粘贴的是**这一集的原文**（小说章节或一段梗概），一次改写生成一集。
- 多集：用户新建集后逐集导入；改写提示词带上前序集的 `[人物]` 声明，保证同名同外观。
- 整本导入 + 自动拆集放 v2（需要新增「分析 → 分集大纲 → 逐集」三阶段与人物圣经）。

### D-4 生成走服务端确定性链路，不走内嵌 Agent

- 直接 `TextGenerator.create(TextTaskType.SCRIPT, project_name, purpose=SCRIPT_GENERATION)`，一次请求完成一次改写。
- 不依赖 Agent 配置/会话/工具调用；可精确控制上下文、校验、返修轮数与错误码；成本自动进 Ledger 与用量页。
- 代价：需要新写 prompt 模板与服务层（见 §6/§7）。

### D-5 结构校验阻塞、机检只告警（R-2）

- **阻塞**（不落盘，返回可读错误）：解析不出 beat、没有 `[场景]`、`[人物]` 缺外观、场景数超档位、台词数不足、头部缺失、输出被截断。
- **不阻塞**：`check_episode()` 的 E1–E14 FAIL。命中时先带失败项返修 1 次；仍失败则照常落盘，响应回带 `quality_warnings`，剧本页顶部展示「未通过工厂机检」提示与问题清单，并提供「重新生成」。
- 理由：导入原文不是工厂交付，机检规则（拍数、台词密度、断章钩子）作为交付门槛会让大量正常小说改编失败，且用户没有剧本编辑出口。若后续要收紧，只需把同一份 warnings 改成拒绝分支，代码结构不变。

### D-6 原文/剧本双视图、原文可编辑、重导风险提示（R-3）

- 剧本页顶部提供视图切换：**剧本（只读 Markdown）| 原文（可编辑 Textarea）**。
- 原文编辑后点「保存原文」只落盘原文，**不自动重生成剧本**；界面提示「原文已修改，剧本尚未重新生成」。
- 「重新导入」= 用当前已保存原文重新生成剧本：
  - 先内联展示风险提示（不是新的导入弹窗）：「将用当前原文重新生成剧本，现有剧本会被替换；本集已生成的分镜、K 帧与视频会标记过期，需要重新生成」；
  - 有分镜图/视频时必须二次确认（复用 `script_has_media_artifacts` 判定与 `short_drama_reimport_confirmation_required` 语义）；
  - 确认后走与首次导入相同的生成链路，覆盖 `episode_NN.md`。
- 原文落盘 `source/import/episode_NN.txt`；另存 `source/import/episode_NN.meta.json` 记录生成时所用原文 revision、模型与时间，用于判断「原文已改、剧本未重生成」。

### D-7 入口独立：导入模式隐藏故事规划与 AI 原创

- 侧栏不渲染 `/story`；路由 `/story` 在导入模式下重定向到项目概览（防地址栏直达）。
- 概览、分集页、分集空态、集页剧本视图、分镜空态中的「AI 原创剧本」「故事规划」按钮全部按模式收敛；剧本页改为「导入原文」。
- `ShortDramaGenerateHost` 仍挂载但导入模式永不打开（入口不存在），不删组件、避免影响 AI 原创。

### D-8 导入模式创建项目时自动建第 1 集

- 原因：需求把导入入口放在「剧本页面」，而项目刚创建时没有集就没有剧本页。
- 做法：创建接口在写入元数据后调用现有 `create_episode()` 建第 1 集，响应回带 `first_episode`；前端创建成功后直接跳到 `/app/projects/{name}/episodes/{first}?view=source`。
- AI 原创模式不建集，行为不变。

### D-9 模式互斥守卫

- `POST …/source-import` 只接受 `creation_mode == source_import`，否则 422。
- `ingest_short_drama_artifacts`（Agent 工厂入库）对 `source_import` 项目拒绝，防止两条剧本来源混写。
- `GET …/story-planning/context` 等故事规划读接口对导入模式返回 422（路由层与 UI 双重收敛）。

### D-10 复用 `CallPurpose.SCRIPT_GENERATION`

- 不新增 usage 来源枚举（新增要同步 GLOSSARY、i18n、统计维度）；导入改写本质是剧本生成，记账口径一致。

### D-11 跨集一致性走「资产池 + 前集声明」，不引入人物圣经

借用 huobao 的资产池机制，落到本仓已有实现上：

1. **资产池就是 `project.json` 的 `characters/scenes/props`**，去重判等键、合并语义与 huobao 的 `save_dedup_*` 等价（`resolve_asset_key` / `register_missing_assets`，已存在则一律不动）。
2. **每集资产步骤就是 huobao 的 extractor 对应物**：现有「一键生成资产」= `register_episode_assets`（只补缺失、不覆盖已有条目）→ `fill_episode_asset_descriptions`（只填空描述）→ 出资产图。用户点一次，池子按名字归一、跨集累积；与 huobao 的「提取资产」按钮同节奏，不改变现有资产流程。
3. **改写提示词注入池 + 前集声明**：已登记资产（name + description）优先，其次是前序集的声明（按名字去重，取最早外观；预算不足时只取最近 5 集）。huobao 的改写 Agent 拿不到这些，我们多做这一步，直接解决文字层的人物名/外观漂移。
4. **画面一致沿用资产图**：角色三视图/场景空镜/道具白底图跨集复用，与 AI 原创完全同一条链路，不需要新做。
5. **可选增强（v1.1，默认不做）**：导入生成后自动补登记（`referenced_asset_descriptions` 直接作 description，零模型调用），让用户在点资产步骤之前池子也完整。它不改变一致性结论，只是把资产页的初始状态提前；若 review 认为资产步骤必须完全手动，这一条不实现。

不做人物圣经/大纲的理由：圣经解决的是人物动机、弧光、语言指纹与跨集剧情记忆；导入模式 v1 的诉求是"人物长得一致、名字一致、画面能复用"，资产池 + 声明 + 参考图已经覆盖。等 v2 做整本拆集时再引入圣经，成本才划算。

## 四、端到端流程

### 4.1 创建

```text
新建项目向导
 第 1 步 基础信息：项目标题 / 画面比例 / 创作模式（AI 原创 | 导入原文）
 第 2 步 生成设置：不变（目标时长、语速、模型、旁白交付）
 第 3 步 风格：不变
 提交：
   AI 原创   → POST /projects（creation_mode=ai_original）→ 项目概览（现状）
   导入原文  → POST /projects（creation_mode=source_import）
             → 自动建第 1 集 → 跳 /episodes/1?view=source
```

### 4.2 首次导入（单集）

```text
剧本页（view=source）无源稿
  → 内联面板：大 Textarea + 字数计数 + 「生成剧本」
  → POST /projects/{name}/episodes/{n}/source-import
      body: { text, expected_revision: null, confirm_artifacts: false }
      服务端：
        1) 校验模式、集存在、文本长度（≤50k）、空文本
        2) 组装上下文（项目/风格/目标时长/前集人物声明/已登记资产）
        3) TextGenerator 改写（最多 1 次返修）
        4) 结构校验（阻塞）+ check_episode（告警）
        5) 锁内写原文、meta、source/short_drama/episodes/episode_NN.md
        6) register_factory_episode_sources：写 source/episode_NN.txt，
           账本 source_origin=own、source_kind=screenplay
        7) emit 项目变更事件
  → 返回 { episode, path, revision, markdown, quality_warnings }
  → 前端刷新项目 + 源稿；剧本页切到只读剧本
```

### 4.3 原文编辑与重新导入

```text
剧本页切到「原文」
  → 编辑 Textarea → 保存原文（PUT …/source-import/original）
      → 只写 source/import/episode_NN.txt；界面提示「剧本尚未重新生成」
  → 点「重新导入」
      → 内联风险提示（覆盖剧本、下游产物过期；有媒体时要求二次确认）
      → 确认 → POST …/source-import（带当前原文）
      → 与首次导入同链路，覆盖源稿；下游按 revision 规则判过期
```

### 4.4 下游（完全不变）

```text
资产页：从剧本 [人物]/[场景]/[道具] 抽出待登记资产 → AI 补齐描述 → 生成资产图
分镜页：AI 分镜（source_revision 校验通过）→ 宫格 K 帧 → 视频提示词 → 视频
剪辑页：时间线与出片
```

### 6.1 改写规则逐条标注：沿用 / 借鉴 / 自创

> 判据：**本仓已有契约优先沿用**（避免双份真相源）；**huobao 已验证且不冲突的写作手法才借鉴**；**现有资产没有的能力才自创**，并说明为什么不能直接复用。

#### A. 沿用本仓工厂既有规则（不是自创）

| # | 规则 | 出处 | 为什么沿用 |

| F1 | 单集 Markdown 格式：集号标题 + 7 个头部字段 + `[场景]/[人物]/[道具]` + `△` 动作行 + 台词行 | `short-drama-factory/templates/episode-format.md`；解析器 `lib/script/short_drama_import.py:210-295` | 现有解析器/分镜/资产只认这一种；改格式就要改下游全部读取方 |

#### B. 借鉴 huobao-drama（仅写作手法层）

| # | 规则 | 出处 | 为什么借鉴 | 与本仓的差异 |
|---|---|---|---|---|
| H1 | 单集整段改写：读本集原文 → 一次改写 → 存回本集 | `prompts/script_rewriter.md:6-19`；`tools/script-tools.ts:12-76` | 与本方案「按集导入」粒度天然一致，链路最短 | 它由 Agent 调工具写 SQLite；我们由服务端调 TextGenerator 写 Markdown 文件 |
| H2 | 对白驱动、减少旁白与叙述 | `skills/script-rewriter/SKILL.md:13` | 短视频节奏与我们的台词行下限一致 | 我们还要满足工厂台词条数下限与机检 |
| H3 | 不写镜头语言（景别/角度/运镜） | `SKILL.md:14` | 镜头语言属于 AI 分镜；写进剧本会污染分镜提示词 | 我们由工厂格式与机检再兜一道 |
| H4 | 心理描写转表情/动作/画外音 | `SKILL.md:51` | 把不可拍内容变成可拍内容，避免分镜阶段卡住 | 我们用 `△` 动作行 + 神态括号承载 |
| H5 | 长段叙述拆成多个短场景、每场有情绪转折 | `SKILL.md:52-53` | 控制单场信息密度，利于 beat 切分 | 场景数受工厂档位上限约束，不能照搬"想拆几场拆几场" |
| H6 | 保留核心情节与角色关系 | `SKILL.md:10` | 改编底线，符合用户"导入原文"的预期 | 与我们 F6 改编红线一致，二者叠加 |

**不照搬的 huobao 元素**：

- `## S01 | 内景 · 地点 | 时间` 场景头 DSL：现有解析器不认，会整段丢失（见 §6.2）。
- 每场 30–60 秒硬编码：与项目档位、机检冲突。
- Agent 自己写正文 + tool 保存：不可控、不可校验；我们改为服务端确定性调用。
- 无大纲、无跨集记忆的整本处理：v1 按集，v2 再补。
- 重跑先删后写：我们沿用工厂的 revision 覆盖语义，由下游判过期，不销毁已有媒体记录。

#### C. 本方案自创（现有资产没有，且说明为什么）

| # | 规则 | 为什么必须自创 |
|---|---|---|
| S1 | 原文作为唯一素材；复用现有资产步骤维护池（只补缺失），并把「已登记资产 + 前序集声明」注入下一集 prompt | 工厂原创靠「人物圣经先立项」；导入没有系列工件。huobao 的一致性同样来自项目级资产池 + 参考图（其改写上下文并不含池），这里把它接到现有资产步骤与提示词上；不新增自动写盘 |
| S2 | 服务端确定性改写（TextGenerator，单次 + 1 轮返修） | 需求是「点确定就生成」；要可校验、可重试、可给错误码；Agent 自由编排做不到稳定验收 |
| S3 | 结构校验作为阻塞门 + 机检只告警（R-2） | 工厂机检是交付门，导入不是工厂交付；但结构必须可被下游解析（硬要求），所以结构单独设为阻塞 |
| S4 | 5 万字上限、单集一次调用 | 按集粒度决定；避免 huobao 的整章截断坑；超限明确报错而不是静默截断 |
| S5 | 原文/剧本双视图、原文可编辑、重导风险提示 | 工厂源稿只读、无"原文"概念；这是导入模式的新交互（R-3） |
| S6 | `creation_mode` 字段 + 入口收敛 + 模式互斥守卫 | 现有项目没有创作模式维度，无法用任何既有字段等价表达 |

#### 6.2.1 消费链

#### 6.2.2 解析器契约表

| 输出元素 | 解析规则（代码） | 写错的实际后果 |
|---|---|---|
| 集标题 | `^(?:#\s*)?第\s*[【\[]?\s*(\d+)\s*[】\]]?\s*集(?:\s*[：:]?\s*(.*))?$` | 集号不匹配 → 分镜/提示词挂错集 |
| 头部字段 | `【所属阶段】【黄金前3秒钩子】【情绪流变】【本集时长】【本集结构】【本集中段小钩】【本集断章卡点】` | 【本集时长】缺失 → `total_duration=0`，切幕窗口失真 |
| `[场景]` | `^\[场景\][：:]\s*(.+)$`，连续多行合并为同一块场景清单；`｜` 后为外观 | 写在 beat 之后 → 被当成新场景块，场景清单错位 |
| `[人物]` | `^\[人物\][：:]`，顿号分隔；括号内/外 `｜` 后为外观 | 缺外观 → 资产缺描述，AI 分镜在资产闸门被拒 |
| `[道具]` | `^\[道具\][：:]`，一行一个，`｜` 后为外观 | 缺外观同上；正文没写名字 → 分镜清单漏道具 |
| 动作行 | 行首 `△` | 不带 `△` → 仍能兜底成动作 beat，但不推荐（易与台词混淆） |
| 台词行 | `角色（神态）：台词`；两行式「说话人行 + 下一行引号」会先合并 | 说话人格式错 → 整行被当动作，台词丢失 |
| 其它非结构行 | 不以 `[`/`【` 开头 → 兜底为动作 beat | 夹带说明文字会被当动作写进剧本 |
| 未识别的 `【…】` 行 | 直接忽略 | 自定义头部等于没写，还会让模型误以为格式合法 |

#### 6.2.3 硬性禁止

1. 禁止 `## S01 | 内景 · 地点 | 时间`（huobao DSL）、禁止 JSON、禁止代码块围栏、禁止解释性段落。
2. 禁止在 `[场景]` 行之后再补场景声明；场景声明必须集中在 beat 前。
3. 禁止把多个动作/多句台词合并进一行（beat 粒度直接决定分幕与时长）。
4. 禁止输出下一集内容或"未完待续"以外的结构（只写目标集）。
5. 禁止自造 `【…】` 头部；只用 F1 规定的字段。
6. 禁止直接写 `scripts/episode_N.json`；视觉状态只能由 AI 分镜生成。

#### 6.2.4 生成前注入的格式约束

Prompt 末尾附上解析器的字段清单与一个最小示例（取自工厂模板），并要求"只输出该结构"；同时把档位对应数值（场景上限、台词下限、拍数下限、目标秒数）显式写进 prompt，避免模型自由发挥。

| 已登记资产 | `project.json` | 角色/场景/道具名称与描述（各最多 20 条） |

### 6.4 档位与时长

与现有创建弹窗同一口径：

- `episode_target_duration` 未设 → 标准档，提示词目标取 105 秒；
- `>= 150` → 长档（165–195 秒）；
- `<= 90` → 漫剧档（60–90 秒）。

### 6.8 跨集一致性：借用 huobao 的资产池（D-11）

#### 6.8.1 huobao 的做法（已核实）

| 环节 | huobao | 作用 |
|---|---|---|
| 资产提取 | 用户在每集点「提取资产」：`extractor` 先 `read_existing_characters/scenes/props` → `save_dedup_*` 按名字去重合并（同名保留已有 appearance/styling）→ 建立集↔资产关联 | 池子跨集累积，名字归一 |
| 分镜上下文 | `read_storyboard_context` 返回本集关联资产的外观/场景光影/道具描述 | 分镜按同一份设定写画面 |
| 画面一致 | 角色三视图 / 场景空镜 / 道具白底图跨集复用为参考图 | 真正兜住视觉一致 |
| 剧本改写 | `read_episode_script` **只返回本集原文**，不注入资产池 | 文字层一致性其实没管，靠下游资产兜底 |

#### 6.8.2 本仓的等价物与差异

本仓已有 1:1 的池与登记实现，不需要新造：

- 池：`project.json` 的 `characters/scenes/props`；判等用 `resolve_asset_key`；
- 登记：`register_missing_assets(project, names, descriptions_by_type=…)`，**只补缺失、不覆盖已有描述**（与 huobao 的合并策略一致）；
- 每集抽取：`episode_asset_names()` 已能从剧本源稿 `[人物]/[场景]/[道具]` 抽名字；
- 描述来源：`referenced_asset_descriptions(parsed)` 已能从声明里直接拿外观（无需 LLM）。

差异与增强：huobao 用 LLM extractor 产出外观；我们的改写结果里已经带外观声明，资产步骤的 AI 补齐只在描述为空时才调用。另外我们把池注入下一集 prompt，补上 huobao 不管的文字层。

#### 6.8.3 v1 落法

1. **池由现有资产步骤维护（不新增自动写）**：用户在资产页点「一键生成资产」，走 `register_episode_assets`（`register_missing_assets`，只补缺失）→ `fill_episode_asset_descriptions`（只填空描述）→ 资产图批量。这就是 huobao「提取资产」的对应动作，节奏也一致：改完剧本 → 提取 → 出图。
2. **下一集改写注入**：
   - 已登记资产：`name + description`（用户可能改过，优先级最高）；
   - 前序集声明：解析 `[人物]/[场景]/[道具]`，按名字去重取最早外观，预算不足时只取最近 5 集；
   - prompt 明确要求「同名沿用外观，不得改名」。
3. **资产图与分镜复用**：角色三视图/场景空镜/道具白底图跨集复用；AI 分镜按既有资产解析绑定参考图。跨集视觉一致与 AI 原创完全同一条链路。

#### 6.8.4 边界

- 不做人物圣经/大纲/台账：它们解决动机、弧光、语言指纹与剧情记忆，不是 v1 的一致性瓶颈。
- 资产步骤保持现有语义：只补缺失、不覆盖已有描述、不改资产图流程；导入模式不偷偷写项目资产。
- **可选增强（v1.1，默认不做）**：生成后自动补登记（声明外观直接作 description、零模型调用），让池提前完整；代价是资产页初始状态与 AI 原创不同，需另行 review。

### 6.9 并发、取消、幂等

- 同一项目/集的并发导入：revision 比对 + 项目锁，后者 409。
- 前端用 `AbortController` 取消请求；服务端随断开取消文本任务。
- 幂等：同一文本重复提交重写同一路径，不产生孤儿文件。

### 6.10 失败与错误码

| 场景 | HTTP | code | 前端提示 |
|---|---|---|---|
| 非导入模式 | 422 | `source_import_mode_required` | 当前项目不是导入原文模式 |
| 空文本 | 422 | `source_import_text_required` | 请粘贴原文 |
| 超长 | 422 | `source_import_text_too_long` | 原文超过 5 万字，请分段导入 |
| 原文不存在 | 404 | `source_import_original_not_found` | 该集还没有导入原文 |

## 十一、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型不遵守格式（缺头部/拍数不足） | 生成失败率 | 模板强约束 + 结构校验 + 1 次返修；失败项可读 |
| 机检 E12/台词密度规则与小说改编冲突 | 告警噪声 | 机检不阻塞（R-2）；界面折叠展示 |
| 长原文超上下文 | 截断/丢细节 | 50k 上限 + `require_complete` + 明确错误；v2 分块/大纲 |
| 跨集人物外观漂移 | 资产不一致 | 资产池 + 前序集声明注入 prompt（§6.8）；资产图跨集复用 |
| v1.1 若开启自动补登记，可能写入用户不想要的资产 | 资产页多出条目 | 默认不做；开启时只补剧本声明里真实出现的名字、只补缺失、不覆盖，回执可追溯且资产可删 |
| 声明外观与用户后来改的描述冲突 | 提示词用到旧外观 | 已登记 `description` 优先级最高，声明只作兜底 |
| 原文编辑后忘记重生成 | 剧本与原文不一致 | meta 记录 `generated_from_revision`，界面提示 stale |
| 重导覆盖导致下游产物过期 | 用户误操作 | 内联风险提示 + 有媒体时二次确认；下游按既有 revision 规则判过期 |
| 入口遗漏某处仍显示 AI 原创 | 模式不独立 | 统一 `isSourceImport()` 判定 + 10.2 清单逐项走查 |
| 模式字段漏改归档/演示/迁移 | 旧项目报错 | 读侧默认 + 迁移 + 归档导入走迁移 |
| 长时间请求被代理超时 | 前端报错但已落盘 | 与 AI 分镜同样式同步请求；成功后刷新可恢复；后续可改 SSE/任务 |
