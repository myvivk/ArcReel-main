# 7. 镜头宫格生成质量分析与优化方案

## 核心流程

目标形态的主线（本方案要改成的样子）：

```
分镜提示词 scene（【镜头N】段首带景别，一格一镜）
  → 逐格镜头文本（单分镜弹窗手填优先，空则 scene 现解析；格数必须等于规格）
  → 逐格出图（每格一次单帧生成，参考图 = 商品/角色/场景/道具资产图 + 上一分镜图）
  → 程序拼宫格图（等大画格、无边框无间隙，几何由程序保证）
  → 逐格人工审核（K 编号 + 景别 + 文本同屏，坏格可单格重画）
  → 确认（登记格文件为 K 帧、拼图登记为分镜图，不再等分切图）
  → 视频提示词（按 K 帧节拍写，本步收尾）
```

现状形态的主线（本次核查的对象）：

```
scene 现解析（或弹窗手填逐格文本）
  → 一次 T2I 出整张宫格（排版全靠提示词文字，无任何校验）
  → 确认时按 rows/cols 等分切图（假设模型画出了几何完美的网格）
  → 格文件绑视频首尾帧、整图绑分镜图
```

**页面入口**：分镜详情「参考素材」区（`ReferenceMaterialsSection.tsx`）——「配置参考素材」开弹窗、结果区看宫格、确认后写视频提示词；制作进度「参考素材」行（step `shot_grid`）走整集批量。本方案不改入口位置，改入口背后的产物形态与审核方式。

**范围排除**：商品（product）资产图、广告集（ad 批量）不在本方案内；视频生成步骤本身、视频提示词的正文字体（11.6 标准）不在本方案内，只在受影响处点名。

## 二、问题清单

### P1（致命）把「一次随机出图」当成「确定性排版产物」

整张宫格由**一次** T2I 调用生成，排版（几行几列、等大、阅读序）全部靠提示词文字约束。核查过全部图像后端（`lib/backends/image_backends/`）：**没有任何一家有原生网格/分格能力**，提示词是唯一手段。截图即为实证：面板大小不一（左上大幅、右侧两小幅堆叠、下方三等大），「所有画格大小完全相同」没有兑现。方案对此**无校验、无补救、无替代路径**——P1/P2/P3 修的都是提示词那一侧，从来没有回答「模型不服从怎么办」。

### P2（致命）等分裁剪假设几何完美

`POST /{grid_id}/confirm`（`shot_grids.py:430-447`）按 `width/cols`、`height/rows` 等分切图，前置校验只有「图幅不小于行列数」。面板不齐时，切缝会落在画面主体中间：每一格 K 帧都是错 crop，并继续污染分镜图、视频首尾帧。**下游越关键（视频首帧），这个假设越致命。**

### P3（致命）没有质量检测，也没有修复回路

- 全库检索无图像质检/一致性检查代码；confirm 的校验只有尺寸。
- 唯一的闸门是人眼确认，但**确认前 UI 只显示整张拼图**（`ReferenceMaterialsSection.tsx:186` 的 `cells.some(image_path)` 门禁，`image_path` 只在 confirm 后写入）——用户在看图时看不到任何逐格文本，无法判断「这一格对应哪句描述、景别是否递进」。
- 出了坏图只能**整张重出**（新任务、二次计费），没有单格重画；没有重试策略。

### P4（结构）景别无结构化来源

方案判定表要求「明确的景别变化（全景→中景→特写）」，但：

- 写作指引（`shared/image_prompt_writing_guide.md`）只要求 `【镜头N】` 开头，正例段首直接是画面内容，不写景别；
- 0098 的 `｜景别` 槽位因此通常为空，`continuity_notes`（`<keyframes>` 的景别标签、UI 的景别显示）系统性缺失；
- 方案 6 规定的段首「景别，机位，运镜。」格式**没有落进写作指引**——两份文档的口径漂移。

景别退化不只是显示问题：网格提示词里「第N格（景别）」的景别槽空置，模型失去景别递进指令，只能自行发挥角度——这正是「换个角度场景内容不一致」的诱因之一。

### P5（结构）跨格一致性只靠一段提示词文字

「同一套角色外观、服装、道具、场景、光线方向与时段，跨格完全一致」写在【风格与锚点】里，但没有任何机制保证：每格没有独立的身份锚定，格间没有链式参考，模型每画一格都是重新想象。参考图（资产图 + 上一分镜图）确实随请求下发，但在一张图内部分格子的场景里，参考图对各格的约束力很弱。

### P6（结构）「延续格」机械补位

`resolve_grid_cells`（`shot_prompt_builder.py:31-45`）在镜头数少于格数时自动补「延续第N格的动作，直到自然结束」——产出一格没有独立节拍的凑数格，与方案 6「禁止为凑数制造无效切片」同向冲突。

### P7（实现偏差）单分镜走不到 scene 兜底

D-3 设计「弹窗留空 → 生成时回退解析 scene」，但弹窗「确定」在输入框为空时禁用。结果是两条路径口径分裂：批量能用 scene，单分镜必须手写或点 AI 生成。要么放开 UI，要么删掉兜底——不能文档写一套、界面拦一套。

### P8（流程）执行标准与内容标准只覆盖了一半

- **执行标准**有：四段式拼装、布局算式、准入守卫（scene 缺镜头序列即拒）、K 引用边界。
- **内容标准**只有视频提示词的 11.6（S1–S6）；**宫格图本身没有任何验收口径**——没人能回答「一张合格的宫格图应该满足什么」，测试也只覆盖拼装函数的输出，不覆盖产物质量。

## 三、对流程四问的直接回答

| 质问 | 核查结论 |
| --- | --- |
| 输入来源是否明确 | **半明确**。单分镜 `ShotGrid.prompt` 优先、scene 兜底（批量同路），但 scene 的格式契约漂移（P4：景别没落进指引），且弹窗阻断空 prompt（P7）。 |
| 流程步骤是否稳定 | **不稳定**。scene 无镜头标记即硬失败（0098 D-F，设计如此）；镜头数≠格数靠截断 + 延续格机械抹平（P6）；confirm 的等分切图依赖未校验的几何假设（P2）。 |
| 执行是否独立、不受其它模式影响 | **准入层已收敛**（`plan_shot_grid_batch` 统一判 scene 可解析 + 资产图可用，跳过原因明确），但执行质量受上游 scene 质量支配且无归因通道——scene 写得差，这一步只能产出差图，错误却要到人眼确认才暴露。 |
| 质量检测 / 内容优化是否存在 | **均不存在**。无图像质检代码；无单格修复；唯一优化手段是整张重出。 |
| 执行标准 / 内容标准是否有明确规则 | 执行标准部分有；**宫格图像的内容标准完全空缺**（P8），视频提示词文本有 S1–S6 可对标。 |

## 四、结论：方案是否合理

**合理的部分（保留）**：

1. 数据流设计成立：prompt 优先 / scene 兜底的混合真相源、`cells` 留证、`scene_revision` 指纹、批量与单分镜在生成层汇合——这些正是「输入来源」问题的正确答法，问题只在 UI 没跟上（P7）。
2. 编排成立：「参考素材」行 + 「视频提示词」行 + K 边界校验 + 分段编辑器，把「出图」和「出文本」接成了闭环。
3. 纯净性约束（无序号/气泡/箭头）与「排版指令不进可编辑文本」（避 P3 规格打架）是对的。

**不合理的部分（本方案要改的）**：

1. **核心假设不成立**：把一次随机图像生成当作确定性排版产物，下游（等分切图 → K 帧 → 视频首尾帧）全部建立在「模型会画出完美网格」上。方案花了大力气算比例（D-6、R4 的 2×3 档），却没有一格校验。
2. **质量层整体缺失**：有文本标准（11.6）无图像标准；有生成无审核工具（确认前不给逐格文本）；有整张重出无单格修复。
3. **输入契约脆且漂移**：景别没落进写作指引（P4），镜头数与格数的关系靠机械补位抹平（P6）。

一句话：**骨架是对的，质量层是缺的；要把「一次赌一张网格」改成「逐格确定产出 + 程序拼图 + 逐格可修复」。**

## 五、优化方案（目标形态）

### D-1 逐格生成 + 程序拼图（核心改动）

宫格不再由一次出图产生，改为：

1. **每格一次单帧出图**：逐格文本 + 项目画风 + 参考图声明 + 纯净性约束，参考图集与现分镜图同源（商品 → 角色/场景/道具资产图 → 上一分镜图，`storyboard_image_input` 已实现该装配，直接复用）。每格按项目画布比例（竖屏 9:16）出图——**格文件天生就是视频比例，不再需要 grid/panel 两套比例算式**。
2. **程序拼图**：全部格文件产出后，按 rows×cols 等大拼合成 `composite`（PIL，无边框无间隙；仓库已有 `lib/video_review/contact_sheet.py` 的拼图先例，复用其模式、不带标签）。
3. **几何由程序保证**：格数、等大、阅读序、单格比例全部确定；`grid_aspect_ratio_for` / `panel_aspect_ratio_for` / 存量非方形档表（含 R4 的 2×3 争议）随本改动一并退场——拼图只是显示与登记件，格文件不经过裁剪。
4. **任务形态**：仍是一个 `shot_grid` 任务，内部逐格出图、逐格落盘（`storyboards/{grid_id}/{i}.png`）、全部成功后拼图并走既有 formal commit；任务进度按格上报（「3/4 格」）。

这一改同时消灭 P1（排版不服从：不存在了）、P2（等分切图：不存在了）、P4 的景别显示问题（见 D-5）、P5 的一半（见 D-3）。

### D-2 每格提示词形态：回归单帧，四段式宫格模板退场

逐格生成后，`storyboard/shot_grid` 模板的【布局要求】段（行列、比例、无边框）整体失去意义——那是为了骗一张图装下 N 个面板才存在的。每格提示词改为单帧形态，与现分镜图提示词同构：

```
Reference_Images: <类型声明，按随请求参考图序位编号图N>
<该格逐格文本（含段首景别；资产名已链接为 图N）>
<项目画风块>
Avoid: <纯净性约束：文字/序号/气泡/箭头/水印>
```

`build_shot_grid_prompt` 从「渲染一张网格」改为「渲染一格」；拼图尺寸另行按规格算，不进任何提示词。

### D-3 跨格一致性锚定

逐格生成不保证一致（每次调用独立），但把「一张图全废、不可修复」变成「单格可重摇 + 有锚点」：

1. **资产参考图每格必带**（身份锚定，已由 `storyboard_image_input` 装配保证）；
2. **跨格不变约束逐格重复**：scene 导语段（同一场景陈设、同一光线方向、同一时段、不换装）拼进**每一格**的提示词——单格生成时参考图与文本同帧在场，0099 P4「不复述资产外观」的顾虑只针对系统锚点段复述外观，不变约束不是外观复述，照写；
3. **链式参考列为可选增强**（上一格图作为附加参考图），与资产图争用供应商参考图位（gemini 3 / grok 7 上限），默认关，见 R3。

### D-4 质量检测与修复回路

1. **程序质检（出图后、确认前）**：格数 = rows×cols；每格尺寸 = 画布比例；空图 / 近黑图（像素方差阈值）判废并自动重摇一次，仍失败则该格标记 `failed` 进人工处理。
2. **人审界面（见 D-6）**：逐格同屏展示，坏格一键「重画这一格」——只重出该格、重拼宫格，不动其它格。
3. **验收口径**见 D-8；质量状态落格记录（`ok / failed`），批量行的「已生成 N 个」按 `ok` 格数计。

### D-5 输入契约修复（三件事）

1. **景别段首化**：scene 每个 `【镜头N】` 段首固定语序「景别，机位，运镜。」（对齐方案 6 已规定的格式，把它落进 `shared/image_prompt_writing_guide`，正例同步改）；解析器从段首提取景别填 `shot_size`（`｜景别` 槽位保留兼容存量）。景别枚举：远景 / 全景 / 中景 / 近景 / 特写。
2. **一格一镜硬规则**：镜头数必须等于 rows×cols。多则截断并在结果区明示被丢弃的镜头；少则**拒绝入队**，错误信息给两个出口（去分镜详情补写 scene / 用弹窗 AI 生成补齐）。**删除 `resolve_grid_cells` 的延续格分支**（P6）。
3. **放开空 prompt**：弹窗「确定」不再因输入框为空而禁用，空 = 走 scene 兜底，与批量同路径（修 P7）；输入框下方的格数提示照旧。

### D-6 确认前逐格审核界面

「参考素材」区的结果区改版（确认前后同一形态）：

```
参考素材  2×2  已生成 4 格
┌────┬────┐
│ K0 │ K1 │   ← 每格：缩略图 + K 编号 + 景别 + 逐格文本（line-clamp）
├────┼────┤   ← CSS 间距分隔（显示层），格文件本身无分隔
│ K2 │ K3 │
└────┴────┘
[ 重画这一格 ]（选中格后可用）      [ 确认参考素材 ]
```

- 拼图降级为「拼图预览」次级入口（查看/下载用），不再是审核主界面——「图片挨着、没有描述信息」由此解决：**视觉分隔走显示层，描述信息与图同屏**。
- 横竖屏都用同一栅格（现 9:16 分支的横向条带 + 箭头布局退役），格间距、K 编号、景别、文本齐全。
- 「重画这一格」= 以该格为资源的新任务（首尾帧两格优先），完成后重拼。

### D-7 确认与登记改造

confirm 不再切图（格文件已存在）：

- 校验：格数、每格文件在、程序质检全 `ok`（或用户强制确认并留痕）；
- 登记：`generated_assets.shot_grid.cell_paths` 直接指向格文件；`start_cell` / `key_cell` / `end_cell` / `video_reference_mode` 口径不变；
- 拼图登记为分镜图（`storyboard_image`）口径不变；
- 「已确认锁规格」（R7）口径不变。

### D-8 宫格图验收口径（内容标准，硬约束）

对标 11.6，任一条不满足即判不合格——重画对应格，不降级、不兜底：

| # | 标准 | 判定方式 |
| --- | --- | --- |
| S1 | 格数与规格一致，无空格、无合并格 | 程序保证（D-1），拼图前断言 |
| S2 | 每格画面与该格逐格文本对应（主体、动作、环境可辨认） | 人审（D-6 同屏展示） |
| S3 | 跨格一致：同一角色装容、同一场景陈设、同一光线方向与时段 | 人审；锚定机制见 D-3 |
| S4 | 景别按 scene 段首递进，不重复、不跳档 | 结构可检（段首景别序列）+ 人审 |
| S5 | 纯净：无文字、序号、气泡、箭头、水印 | 模板约束 + 人审 |
| S6 | 每格比例 = 项目画布比例 | 程序保证（每格按画布比例出图） |

## 六、对下游的影响

| 下游 | 影响 |
| --- | --- |
| 视频生成 | 首尾帧来自格文件，比例天然正确；`start_end_cells` 口径不变；2×3 的 1:2 怪格问题随之消失 |
| 视频提示词 | `<keyframes>` 取 `cells` 的口径不变；景别标签因 D-5 段首化而补齐 |
| 计费 | 每分镜图像调用从 1 张变为 rows×cols 张；批量预览的预估费用必须按格数计（现按 1 张宫格档计价，要改） |
| 工作流行 | 「参考素材」行状态判定加质量维度（有失败格 ≠ 已生成）；「重新生成全部」= 逐格重跑 + 重拼 |
| 分镜图 | 仍登记拼图；拼图由程序产出，稳定可复现 |

## 七、待拍板（review 焦点）

- **R1 逐格出图的成本口径**：(a) 全规格逐格（2×2=4 张 / 2×3=6 张 / 3×3=9 张，质量最稳）｜(b) 仅 2×2、2×3 逐格，3×3 移出白名单（成本与参考图上限双考虑）｜(c) 首尾两格必出、中间格文本化（只出 2 张，放弃可审核的 K 序列）。建议 (a)，但需先实测一集的总费用与耗时。
- **R2 任务内并发**：N 格串行还是并行发请求（受生成队列与供应商并发约束）；影响墙钟时间，不影响正确性。

- **R4 单格重画的任务形态**：新任务类型 vs 复用 `image_edit`；失败格自动重摇几次后转人工（建议 1 次）。

## Considered Options

- **保持一次出图，加视觉模型质检（VLM 数格子/查一致性）+ 不达标重出**：能发现 P1，不能修复 P2（切坏了就是切坏了），且每张宫格多付一次 VLM 调用；重出仍是全张。否决，仅可作为逐格方案落地前的过渡告警。
- **等网格原生模型**：后端注册表里目前没有；不能把正确性押在供应商路线图上。列为后续选项，不进入本方案。
- **只出首尾两帧、中间帧纯文本**：最便宜，但丢掉「可审核的 K 序列」——用户核不了一条视频提示词对不上哪一帧，11.6 的 S1 失去着落。列为 R1(c)。
- **保留四段式模板、把布局段留给拼图后用**：布局指令对模型完全无益（不出网格了），留着只会干扰单帧生成。否决，模板退场（D-2）。
- **「延续格」改为留空格**：拼一张带空格的宫格，视频首尾帧可能落在空格上。否决，改为拒绝入队（D-5）。
