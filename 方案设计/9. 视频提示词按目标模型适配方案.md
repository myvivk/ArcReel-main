# 9. 视频提示词按目标模型选型与规范适配

> 唯一链路不变（工厂 → 资产 → AI 分镜 → ShotGrid / K 帧 → 独立视频提示词 → 视频 → 剪辑）。本方案只改「独立视频提示词」这一步：加一个模型下拉框，按所选模型的规范写、按所选模型的规范渲染，参考图编号沿用系统现有写法。
>
> 回答三个问题：**规范怎么定义、参考图怎么编号、最终发出去的提示词长什么样。**

## 一、模型选择：复用生成弹窗已有的那个下拉框

生成弹窗（`VideoGenerationDialog`）已经有模型下拉，写的是项目字段 `video_provider_i2v`，选「跟随全局」时清空。提示词步骤直接复用同一个控件、同一个字段：

| 项 | 做法 |
| --- | --- |
| 位置 | 视频提示词步骤顶部（本批）+ 逐行可改（单条） |
| 绑定 | 项目 `video_provider_i2v`（故事板模式），与生成弹窗同一字段 |
| 何时生效 | 立即生效：改了它，本批/下一条视频就用这个模型 |
| 记录 | 写提示词时把 `{provider, model, spec}` 记进条目 `video_prompt_basis.target` |
| 切换后 | 已有提示词标「按 X 写的」软 stale，可一键按新模型重写；不阻断生成 |

## 二、参考图编号：名字后面紧跟图号，不另起清单

沿用系统现有写法，不做第二套：

1. **名字与编号贴在一起**：作者写 `@沈昭`（或 `沈昭@[沈昭]`），渲染成 `沈昭图1`——名字保留，图号紧跟其后。不是把编号搬到句尾，也不是另开一份带名字的清单。
2. **声明段只写类型**：`Reference_Images: 图1、图2 为角色参考图；图3 为场景参考图。`——和图片侧完全一致，**不写资产名**（资产名与图号的绑定在正文内联完成）。
3. **编号在裁剪之后生成**：按本次请求实际发出的 `reference_images` 顺序（下标 + 1），裁剪/去重后编号；没发出的图不编号。
4. **数组顺序固定**：先资产图（角色 → 场景 → 道具，按 mention 首现序），后 K 帧（按 K 号）。声明段给出 K ↔ 图号的映射（`图4–图7 为关键帧 K0–K3`），正文可以继续用 K 号。
5. **首帧/尾帧不占图号**：它们走独立字段，用「首帧」「尾帧」称呼；只有进 `reference_images` 数组的图才编号。

示例（reference 模式，资产图与 K 帧都在数组里）：

```text
Reference_Images: 图1、图2 为角色参考图；图3 为场景参考图；图4 为道具参考图；图5–图8 为关键帧 K0–K3。
Action: 0-3秒：沈昭图1贴墙稳住重心，铁镐图4压入砖缝。3-6秒：手腕拧转，肩背发力，身体向上撑起。6-12秒：泥浆从井口倾泻，他侧身避开，保持上爬节奏。
```

## 三、资产图能不能进同一个请求

能不能带资产图，取决于后端，不能假设：

| 后端 | 首帧 + 参考图同请求 | 结论 |
| --- | --- | --- |
| MiniMax H3 | 不允许（官方：`first_frame`/`last_frame` 与 `reference_image` 互斥） | 首尾帧模式下资产图不出现，正文也不写图号 |
| Agnes | 拒绝（backend 抛 `VideoCapabilityError`） | 同上 |
| v2 中转 / Grok / Sora | 首帧与参考共享单槽 | 可编「首帧即图1」 |
| Seedance / Kling / Veo / Wan | 逐档位不同，接入前逐条核实 | 由 spec 的 `ref.frame_plus_reference` 声明 |

## 四、规范怎么定义：一份 spec，十二个槽

规范只定义**长什么样**，不定义**写什么**（内容仍来自 `action / camera_motion / ambiance_audio / dialogue` 与参考图槽位）。

| 槽 | 取值 | 决定 |
| --- | --- | --- |
| `body.unit` | `seconds` / `shots_cn` / `shots_en` / `prose` | 正文按「0-3秒：」「镜头1：」「[Shot 1]」还是整段散文 |
| `body.open` | `[Shot {n}]` / `镜头{n}：` / 空 | 每段开头写什么 |
| `body.time` | `inline` / `marker`（`At 00:03.000, cut to`）/ `none` | 时间怎么写 |
| `camera.mode` | `key` / `bracket` / `inline` / `natural` | 运镜单列、`[Push in]`、嵌句、自然句 |
| `sound.mode` | `key` / `section` / `inline` | 环境声落点 |
| `music.mode` | `avoid` / `section` / `sentence` / `param` | "不要配乐"的四种写法 |
| `negative.mode` | `avoid_line` / `param` / `sentence` / `none` | 排除项走正文、参数、约束句，还是不管 |
| `dialogue.mode` | `block` / `inline` / `quote` | 台词落点 |
| `ref.frame_plus_reference` | `allow` / `reject` / `shared_slot` / `unknown` | 见第三节 |
| `ref.numbering` | `inline`（名字图N）/ `roles` | 见第二节 |
| `ref.declare` | `line` / `prose` / `roles` | 声明段位置 |
| `limits` | `max_chars` / `duration` | 从 `VideoCapabilities` 读，spec 不重复写数字 |

```json
{
  "key": "minimax-h3",
  "body": {"unit": "shots_en", "open": "[Shot {n}]", "time": "marker", "first_no_time": true},
  "camera": {"mode": "inline"},
  "sound": {"mode": "section", "label": "overall_soundscape"},
  "music": {"mode": "section", "label": "non_diegetic_music", "empty": "N/A"},
  "negative": {"mode": "none"},
  "dialogue": {"mode": "inline"},
  "ref": {"frame_plus_reference": "reject", "numbering": "roles", "declare": "roles"},
  "limits": {"max_chars": 7000, "duration": [4, 15]}
}
```

```json
{
  "key": "generic",
  "body": {"unit": "seconds", "open": "", "time": "inline"},
  "camera": {"mode": "key", "label": "Camera_Motion"},
  "sound": {"mode": "key", "label": "Ambiance_Audio"},
  "music": {"mode": "avoid", "text": "BGM、文字字幕、水印、Logo"},
  "negative": {"mode": "avoid_line"},
  "dialogue": {"mode": "block", "label": "Dialogue"},
  "ref": {"frame_plus_reference": "unknown", "numbering": "inline", "declare": "line"}
}
```

匹配顺序：model 精确 → model 前缀 → endpoint key → provider 家族 → `generic`。`generic` 的渲染结果与今天逐字一致（回归护栏）。

## 五、最终提示词：同一个分镜，几套输出

共用输入：12 秒，reference 模式，`reference_images` = 沈昭角色图、井壁场景图、铁镐道具图、K0–K3；一句台词「别松手。」；运镜 `Push In`。

### 5.1 `generic`

```text
Reference_Images: 图1 为角色参考图；图2 为场景参考图；图3 为道具参考图；图4–图7 为关键帧 K0–K3。
Action: 0-3秒：沈昭图1贴墙稳住重心，铁镐图3压入砖缝。3-6秒：手腕拧转，肩背发力，身体向上撑起。6-12秒：泥浆从井口倾泻，他侧身避开，保持上爬节奏。
Camera_Motion: Push In
Ambiance_Audio: 铁器摩擦砖石的短促声，泥浆落水的闷响
Dialogue:
  - Speaker: 沈昭
    Line: 别松手。
Avoid: BGM、文字字幕、水印、Logo
```

### 5.2 `minimax-h3`（首尾帧模式，资产图不可带）

```text
integrated_multimodal_description: [Shot 1] A medium-wide shot inside a narrow well shaft, rain seeping through the brick seams. 沈昭 presses his back to the wall and drives the pickaxe into the joint. The camera makes a slow push in. [Shot 2] At 00:03.000, cut to a close-up: his wrist twists, his shoulder blades tighten, and his body rises along the wall. [Shot 3] At 00:06.000, cut to a low angle: grey mud pours from the well mouth; he turns his shoulder away without breaking the climbing rhythm. He says in a low voice, "别松手。"
overall_soundscape: 铁器摩擦砖石的短促声，泥浆落水的闷响，井壁渗水的持续滴答。
non_diegetic_music: N/A
```

首帧 K0 / 尾帧 K3 由 `first_frame` / `last_frame` 两个 role 承载，正文不编号；资产图属 `reference_image`，与首尾帧互斥，本模式不带。要带就整条改 reference 模式，按 5.1 内联编号。


## 六、渲染管线

1. **语义层**：`action`（分段时间段）/ `camera_motion` / `ambiance_audio` / `dialogue`。
2. **图片列表**：资产图（按 mention 首现序）+ K 帧 → 按 spec 的 `frame_plus_reference` 决定能否同请求 → 裁剪 → 编号（编号与列表同一函数产出）。
3. **正文替换**：`@名称` / `名称@[名称]` → `名称图N`（名字只出现一次，编号紧跟）；声明段按类型分组，不带资产名。
4. **spec 投影**：按槽投成正文单位、运镜写法、声音段、台词写法、排除项。
5. **约束**：`max_prompt_chars` 超限作可回喂原因局部修复；时长不在档位内报能力不匹配。
6. **单一出口**：仍是 `render_storyboard_video_prompt`，默认 `generic` 逐字等于现状；重复渲染幂等（编号不得叠加）。

## 附：实现状态（2026-11-01）

已落地：

- `lib/prompts/model_specs/`：12 槽 spec + 匹配注册表（generic / minimax-h3 / minimax-hailuo / ark-seedance / kling / gemini-veo / openai-sora / vidu）。
- `render_storyboard_video_prompt(..., spec, references, language)`：generic 逐字不变；其余按 spec 投影。
- 编号：`@名称` → `名称图N`、`Reference_Images` 类型声明行（K 合并区间），编号按实际发出序列（裁剪后）生成。
- 资产图进 `reference_images`：`resolve_storyboard_video_asset_images`（角色→场景→道具，缺图跳过），仅在参考图模式（`frame_mode=reference`）前置到 K 帧之前，按 `max_reference_images` 剩余名额截断。
- 写作侧：目标模型事实块 + 方言要点注入；`video_prompt_basis.target`；写作期 `max_prompt_chars` 预算 lint（按条目估后缀：编号行 + K 帧 + 资产链接 + 说话人）。
- 工作流集合出 `model_stale_ids`，步骤行提示「按另一个模型的口径写的」；分镜详情里按条目 `video_prompt_basis.target` 与当前项目模型比对，不一致时行内提示建议重写。
- 前端：提示词弹窗「目标视频模型」下拉，写 `video_provider_i2v` 后刷新。
- 批量视频：`POST /videos/batch[/preview]` 接受 `frame_mode`；Agent 工具 `generate_videos` 也暴露同名字段（episode / all / selected 三种 scope 都生效）。参考图模式下资产图与 K 帧一起计数、一起编号；准入与执行共用 `_video_reference_plan`，编号、计数与实发列表同源。
- 能力补齐：`minimax-hailuo-v1(-fast).json` 声明 `max_prompt_chars: 2000`（官方 i2v 文档）；Hailuo 方括号运镜改用官方中文指令（[推进]/[拉远]/[固定]/[左摇] 等 15 条）。

按能力事实保留的边界：

- 首帧 / 尾帧模式不带资产图（H3 官方互斥；多数 i2v 后端只收首帧），因此这些模式下不编号资产。
- 批量的 `frame_mode` 目前只有 API 与 Agent 工具入口（前端批量视频界面无帧模式选择器），默认仍是首尾帧。
