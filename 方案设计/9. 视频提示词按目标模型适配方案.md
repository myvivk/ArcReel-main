# 9. 视频请求按目标模型适配方案

## 一、结论

目标模型适配保留，但从「AI 按模型重写视频提示词」改为「请求出口确定性渲染」。

唯一动态 `image_prompt` 不绑定某个视频模型，不因切换模型而重写。当前供应商和模型只决定：

- reference/r2v 能力是否可用。
- 参考图、参考音频、时长和分辨率上限。
- 最终包装字段、参考图编号语法、声音段和负向约束格式。

## 二、单一真相源

| 事实 | 真相源 |
| --- | --- |
| 动态剧情与镜头正文 | `image_prompt` |
| 实际参考图 | 视频准入与 worker 共用的参考图投影 |
| 模型能力 | backend `VideoCapabilities` / `VideoRequestFacts` |
| 模型提示词包装 | `VideoPromptSpec` |
| 最终请求文本 | `render_storyboard_video_prompt` |

提示词模板和 Agent 文档不硬编码模型时长、参考图数量或分辨率。

## 三、适配边界

允许的确定性适配：

- 把实际参考图按模型语法编号。
- 把 `utterances` 转成模型接受的台词段。
- 把角色声音配置转成声音风格或参考音频声明。
- 追加模型要求的负向约束。
- 在不改变正文事实的前提下调整包装键名和段落顺序。

补充（2026-11-04）：提示词编写弹窗可以选择目标视频模型；写作侧据此注入模型事实（模型身份、可用时长档位、`VideoPromptSpec.writing_guide`），让新写的 `image_prompt` 直接符合该模型方言，而请求渲染仍按实际执行模型做确定性适配。

禁止的适配：

- 再次调用 AI 改写动作、剧情、表演或镜头调度。
- 生成或写回 `video_prompt`。
- 因切换模型修改 `image_prompt`。
- 用 `video_prompt_basis.target` 判断提示词过期。

> 2026-11-04 修订：提示词编写弹窗重新提供「视频模型」选择（参考 fea_1026 的视频提示词实现）。选择只决定**本次新写提示词**的目标方言与时长档位，并写入项目 `video_provider_r2v`；既有 `image_prompt` 不因切换模型自动改写。

## 四、切换模型

切换模型后：

1. `image_prompt` 保持不变。
2. 参考素材保持不变，除非新模型参考图上限无法容纳 confirmed K 帧。
3. 下一次预览和生成按新模型重新渲染最终请求。
4. 模型能力不足时准入拒绝，并给出改小宫格或更换模型的修复动作。
5. 已生成视频是否 stale 由 Artifact Manifest 中的执行配置和真实输入判断。

## 五、历史兼容

历史 `video_prompt_basis.target` 可以随旧 JSON 读取，但新流程不写入、不比较、不展示。历史字段不是迁移前提，也不参与请求渲染。

## 六、验收标准

1. 同一 `image_prompt` 切换模型时不会触发 AI 文本任务。
2. 预览、准入和 worker 使用同一个 `VideoPromptSpec` 与请求事实。
3. 参考图编号与实际发送数组一致。
4. 模型能力变化通过准入暴露，不通过隐式裁剪 K 帧或回退首尾帧掩盖。
